本章讲的是搜索引擎的文本转换（Text Transformation）阶段：文档的文本在文档库与索引之间会经历什么。它以搜索引擎与 Web的架构和文档转换、存储与去重中存储的文档为前提；它的输出（索引词项、短语、额外的文本字段）正是倒排索引与索引构建所存储的内容，也是检索模型：布尔、tf-idf 与向量空间排序时所用的内容。

1. 从文档到索引词项

语料（corpus）是可供搜索的全部文档的集合。在网页搜索中，它就是搜索引擎会考虑的全部页面，也就是文本获取（text acquisition）放入本地文档库的内容。

文本处理（text processing）是为搜索引擎使用语料中的文档做准备的阶段。它发生在建立索引之前，目的是提高效率和性能，通常包含两个主要步骤：

  1. 分词（tokenization，即词法分析 lexical analysis）：把文本切分为词元（token）。
  2. 语言学预处理（linguistic pre-processing）：对词元应用规则，以提高索引的效率：停用词去除与词干提取（§4–§5），再加上短语识别（§6）。

为什么不直接索引原始字符串？

  • 对网页搜索而言，逐字匹配用户输入的字符串限制太多，效果不好（例如，区分大小写的搜索未必是你想要的）。
  • 并非所有词的价值都相同。
  • 有时词的起止位置并不清楚：在中文、韩文这类语言中，甚至连"词"是什么都说不清。

处理文本，是把文档转换为索引词项（index term）的关键步骤。本章沿着这条流程展开：分词（§2）、为后续选择提供依据的统计（§3）、停用词去除（§4）、词干提取（§5）、短语（§6），以及帮助引擎判断页面哪些部分更重要的结构与链接（§7–§8）。

2. 分词

2.1 分词器的作用

分词（tokenizing），又叫词法分析（lexical analysis），是从字符（通常是字符序列）中组成有意义的单元：它把输入切分为具有简单含义的单元。词元可以是一个词，也可以不是，这取决于你选择如何创建词元。在英语中，分词已经出乎意料地复杂；在其他语言中可能更难。

分词器（tokenizer，也称词法分析器（lexer）或扫描器（scanner））把字符流转换为词元流。同一种机制会出现在两个地方：

位置 分词器的输出交给谁
编译器前端 语法分析器（parser）
信息检索的预处理器 检索系统

把大写转换为小写，有几种说法：大小写折叠（case folding）、规范化（normalization）或转小写（downcasing）。

2.2 什么是词元？取决于约定

"按空白切分，再丢掉标点"是显而易见的规则，但有些情况迫使我们做出选择：

问题 例子
撇号 O'Neill、Aren't
连字符 clear-headed 与 clearheaded；mother-in-law
多个词，算作一个词元？ San Francisco；white space；New York University 与 York University
不是词的词元 info@uci.edu、http://www.ics.uci.edu/、192.168.0.1

没有普遍正确的答案：每种选择都决定了哪些查询能够匹配。例如，把 New York University 切成三个词元，就意味着 "York University" 也能匹配它。

2.3 早期的分词方法

早期的 IR 系统使用一条非常简单的规则：

  • 词元是连续 3 个或以上的字母数字字符。
  • 空格或特殊字符结束一个词元。
  • 所有字符转换为小写。

对一个示例句子，结果如下：

"Bigcorp's 2007 bi-annual report showed profits rose 10%."
        ↓
"bigcorp 2007 annual report showed profits rose"

s、bi 和 10 都短于 3 个字符，被丢弃。结论是：这种方法过于笼统、过于简单，丢失了大量信息——对搜索来说它太简陋，即便用于大规模实验也是如此。分词中的小决定，可能对某些查询的效果产生重大影响。

2.5 分词过程

分词是一个多步骤的过程。第一步使用分词器 + 解析器找出文档中哪些部分需要为搜索而分词（§7 中的标记正是解析器发挥作用的地方）。

最一般的策略是把复杂的决定交给其他组件：

  • 词是由字母数字字符组成的任意序列，以空格或特殊字符结束，并全部转换为小写。
  • 所有内容都被索引，系统同时记录额外的信息。例如：92.3 → 92 3，但搜索仍能找到 92 与 3 相邻出现的文档。
  • 加入一些特殊规则，以减少对查询变换组件的依赖。

这与过去使用的简单分词方法差别不大。早期 TREC 语料所使用的规则：

规则 例子
忽略词中的撇号 o'connor → oconnor，bob's → bobs
忽略缩写中的句点 I.B.M. → ibm，Ph.D. → phd

困难的情况仍交给后处理：信息抽取与查询变换。

💡 关键洞见：分词器有意保持简单，同时保留足够的信息（例如词的位置），让后续阶段能够找回它丢弃的内容。

3. 文本统计与 Zipf 定律

3.1 为什么要看统计量

文本使用的词种类繁多，但词出现的许多统计特征是可以预测的，例如词频的分布。检索模型与排序算法高度依赖这些特征（检索模型：布尔、tf-idf 与向量空间）：对检索重要的词，通常是在某个文档中频繁出现，但在整个语料中并不常见的词。

3.2 Zipf 定律

词频分布高度偏斜：少数词出现得非常频繁，许多词几乎从不出现。最常见的两个词（"the"、"of"）约占所有词出现次数的 10%。Zipf 的"定律"指出：第 rrr 个最常见词的频率与 rrr 成反比，即秩与频率的乘积大致为常数：

r⋅f≈korr⋅Pr≈c,c≈0.1 for Englishr \cdot f \approx k \qquad\text{or}\qquad r \cdot P_r \approx c, \quad c \approx 0.1 \text{ for English}r⋅f≈korr⋅Pr​≈c,c≈0.1 for English

这里 rrr 是秩（按频率降序排列的词序号），fff 是该词的频率，PrP_rPr​ 是它的出现概率（频率 / 词出现总数），kkk、ccc 为常数。对英语绘制 PrP_rPr​（0 到 0.1）与秩（0 到 100）的曲线，会得到一条从 0.1 附近开始、在前约 10 个秩内急剧下降、随后趋于接近 0 的平缓曲线：其形状就是 0.1/r0.1/r0.1/r。

3.4 练习

在 AP89 上检验 Zipf 定律

使用以下 AP89 数据：词出现总次数 39,749,179，不同的词 198,763 个，只出现一次的词 70,064 个，出现超过 1,000 次的词 4,169 个；"the" 出现 2,420,778 次（秩 1），"of" 出现 1,045,733 次（秩 2），"people" 出现 68,988 次（秩 50）。"the" 和 "of" 占文本的多少？"people" 的 r⋅Prr \cdot P_rr⋅Pr​ 是否接近 0.1？hapax legomena 占词表的比例是多少？出现超过 1,000 次的词又占多少？

解答
  • "the" + "of"：(2,420,778 + 1,045,733) / 39,749,179 = 3,466,511 / 39,749,179 = 8.7%，即 Zipf 定律中的"约 10%"（6.09% + 2.63%）。
  • "people"：r⋅Pr=50×68,988/39,749,179=0.087r \cdot P_r = 50 \times 68{,}988 / 39{,}749{,}179 = 0.087r⋅Pr​=50×68,988/39,749,179=0.087，接近 0.1。一般而言，"the" 的 r⋅Prr \cdot P_rr⋅Pr​ 为 0.061，"of" 为 0.053，秩 11 到 50 则保持在 0.076 到 0.090 之间（见 §3.3 的表）。
  • hapax legomena：70,064 / 198,763 = 35% 的词表只出现一次；只有 4,169 个词（2.1%）出现超过 1,000 次。

Zipf 定律在中间段大致成立，在两端失效，也就是高频和低频处的问题。

4. 停用词去除与停用词

功能词（如限定词、介词）本身几乎没有意义，而且出现频率极高，位于 §3 中 Zipf 曲线的顶端。它们可以被当作停用词（stopword）去掉，这样可以：

  • 减少索引空间，
  • 缩短响应时间，
  • 提高效果。

不过，它们在组合中可能很重要："to be or not to be" 全部由停用词组成。

构建词表：停用词表可以取自最高频的词，也可以采用标准词表。词表会针对应用、领域，甚至文档的不同部分定制：对锚文本（§8）而言，"click" 和 "here" 就是很好的停用词。

💡 关键洞见：通常最好的策略是索引文档中的所有词，并在查询时决定使用哪些词。在建索引时删除的词，无法再恢复。

5. 词干提取：suffix-s、Porter、Krovetz

5.1 词形与为何要做词干提取

词干提取（stemming）也叫合并（conflation）。词由语素（morpheme）构成：

  • 词干（stem）是核心单元。
  • 词缀（affix）是附着在词干上的单元。在 "stems" 中，STEM 是词干，S 是词缀。

许多词都有形态变化：屈折变化（inflectional，如复数、时态）和派生变化（derivational，如通过加后缀 -ation 把动词变为名词）。在大多数情况下，这些变体的含义相同或非常相近。

词干提取器（stemmer）试图把这些变化归并到一个共同的词干，通常是通过去掉后缀实现的。与停用词一样，它可以在建索引时进行，也可以在查询处理时进行，或两者兼用。例如，用户搜索 "mark spitz swimming"，而描述往届赛事的网页写的是 "swam"。词干提取器必须把 "swimming" 和 "swam" 都转换为同一个词干（例如 "swim"），二者才能匹配。

这种收益通常不大，但很重要：英语的效果提升约为 5% 到 10%，阿拉伯语或俄语则可达 50%，在这些语言里它可能至关重要。阿拉伯语的许多词都围绕一个词根构建，比如词根 ktb：

词 含义
kitab 一本书
kitabi 我的书
alkitab 这本书
kitabuki 你的书（阴性）
kitabuka 你的书（阳性）
kitabuhu 他的书
kataba 写
maktaba 图书馆、书店
maktab 办公室

两种基本类型，都依赖具体语言：

  • 基于词典：使用相关词的列表。
  • 基于算法：使用程序来判断相关词。

5.2 suffix-s 词干提取器

最简单的英语算法型词干提取器是 suffix-s：去掉结尾的 "s"，假定它是复数。

def suffix_s(word):
    return word[:-1] if word.endswith("s") else word

for w in ["cats", "lakes", "wiis", "centuries", "is"]:
    print(w, "->", suffix_s(w))
cats -> cat
lakes -> lake
wiis -> wii
centuries -> centurie
is -> i

它会产生很多假阴性（应当合并的相关词没有合并：centuries ↛ century），也会产生一些假阳性（把不相关的词合并了：is → i）。

⚠️ 易错点：注意方向。假阳性（false positive）是把不该匹配的词合并在一起（is/I）；假阴性（false negative）是漏掉了应该匹配的词（centuries/century）。

5.3 Porter 词干提取器

Porter 词干提取器是一种算法型词干提取器，自 1980 年前后起就用于 IR 实验：

  • 它由五个步骤组成的一系列规则构成；在每个步骤中，执行最长适用后缀对应的规则。
  • 它在 TREC 上效果良好。
  • 它产生的是词干，而不一定是词。
  • 缺点：它会犯不少错误，而且难以修改。

第 1 步（五步之一）的完整内容：

Step 1a:
- Replace sses by ss (e.g., stresses → stress).
- Delete s if the preceding word part contains a vowel not immediately
  before the s (e.g., gaps → gap but gas → gas).
- Replace ied or ies by i if preceded by more than one letter, otherwise
  by ie (e.g., ties → tie, cries → cri).
- If suffix is us or ss do nothing (e.g., stress → stress).
Step 1b:
- Replace eed, eedly by ee if it is in the part of the word after the
  first non-vowel following a vowel (e.g., agreed → agree, feed → feed).
- Delete ed, edly, ing, ingly if the preceding word part contains a
  vowel, and then if the word ends in at, bl, or iz add e (e.g., fished →
  fish, pirating → pirate), or if the word ends with a double letter that
  is not ll, ss or zz, remove the last letter (e.g., falling → fall,
  dripping → drip), or if the word is short, add e (e.g., hoping → hope).
- Whew!

5.4 词典词干提取器与 Krovetz 词干提取器

词典词干提取器使用人工构建的 (词, 词干) 对列表：

  • 假阳性率非常低。
  • 相关的词不需要长得相像，例如 "is"、"be"、"was"。
  • 一个重要缺点是它无法自动应对新词。
  • 词表可以通过统计分析半自动地构建，再由人工校对。这对搜索应用中的查询扩展很有用。

Krovetz 词干提取器是算法与词典的混合体。它基于这样一种观察：不规则的词通常是语言中最古老的，而新词往往遵循规则的语法惯例。

  1. 先在词典中查找该词。若在词典中，则保持不变，或替换为它的"例外"形式。
  2. 若不在词典中，则检查它是否带有可以去掉的后缀。
  3. 去掉后缀之后，再次查询词典。

它的优势在于：通常产生的是词，而不是词干。其假阳性率较低，假阴性率则略高（取决于词典的大小和整理质量）。用于搜索时，两者效果相当。

6. 短语：词性标注与词 n-gram

6.1 为什么要识别短语

短语在搜索中很重要：许多网页搜索查询都是 2 到 3 个词的短语。短语：

  • 比单个词更精确：包含 "black sea" 的文档，与只是同时含有 "black" 和 "sea" 两个词的文档并不相同。词序很重要：你想要的是 "the sea turned black" 这样的页面吗？
  • 歧义更少："big apple" 与 "apple" 的对比。

短语也会给排序带来困难，具体细节取决于所用的模型。对于查询 "fishing supplies"，应该如何给下列文档打分：完整短语出现多次、完整短语出现一次、两个词出现在同一句中、同一段中、整篇文档中，或词的各种变体？

两个问题：什么是短语？以及如何识别短语？有三种方法：

  1. 用词性（POS）标注器识别句法短语（§6.2）。
  2. 使用词 n-gram（§6.3）。
  3. 在索引中存储词的位置，并在查询中使用邻近运算符（倒排索引与索引构建）。

6.3 词 n-gram

词性标注对大型语料来说太慢。更简单的定义是：短语就是任意 n 个词组成的序列，即一个 n-gram（也叫 shingle）。bigram 是 2 个词，trigram 是 3 个词，unigram 是单个词。n-gram 也用于字符级别，例如 OCR 之类的应用。

n-gram 通常由重叠的词序列构成：把一个包含 n 个词的"窗口"每次向后移动一个词，穿过整篇文档。

def ngrams(words, n):
    return [" ".join(words[i:i + n])
            for i in range(len(words) - n + 1)]

words = "the sea turned black".split()
for n in (1, 2, 3):
    print(n, ngrams(words, n))
1 ['the', 'sea', 'turned', 'black']
2 ['the sea', 'sea turned', 'turned black']
3 ['the sea turned', 'sea turned black']

6.4 练习

一篇 1,000 词的文档有多少个 n-gram？

一篇文档有 1,000 个词。对于 2 ≤ n ≤ 5，使用重叠窗口，它包含多少个词 n-gram 实例？

解答

长为 n 的窗口可以放在 1000−n+11000 - n + 11000−n+1 个位置：999 个 bigram、998 个 trigram、997 个 fourgram、996 个 fivegram。合计 999+998+997+996=3,990999 + 998 + 997 + 996 = 3{,}990999+998+997+996=3,990，是文档长度的四倍。这就是为 n-gram 建索引的存储代价。

8. 链接与锚文本

链接是网络的关键组成部分：它对导航很重要，对搜索也很重要。在

<a href="http://example.com">Example website</a>

中，"Example website" 是锚文本（anchor text），http://example.com 是目标链接（destination link）。搜索引擎会同时使用这两者。

锚文本被用作目标页面内容的描述。所有指向某个页面的链接的锚文本，会被收集成该页面的一个额外文本字段。例如，页面 www.example.com 有四个字段：

字段 内容
text（页面自身的正文） document text
来自 other.com 的锚文本 example
来自 null.com 的锚文本 click here
title（标题） example site

锚文本往往简短、描述性强，并且与查询文本相似。检索实验表明，它对某些类型的查询的效果有显著影响，甚至超过了 PageRank！（PageRank 只使用链接结构，不使用链接上的文字，见 链接分析：HITS 与 PageRank。）

⚠️ 易错点：锚文本描述的是链接指向的页面，而不是链接所在的页面。另外，"click here" 正是锚文本专用停用词表会去掉的那类文字（§4）。

文本处理步骤 作用 注意事项
分词 字符 → 词元；转为小写（大小写折叠） 连字符、撇号、句点、数字；查询必须与文档以相同方式分词
停用词去除 去掉功能词 "to be or not to be"；最佳做法：全部索引，查询时再决定
词干提取 把形态变体归并为一个词干 假阳性（is → i）与假阴性（centuries ↛ century）
短语 多词单元 词性标注（慢）、n-gram（占存储）、位置 + 邻近运算符
结构 / 标记 重视标题、锚文本、加粗、元数据 锚文本描述的是目标页面
事实 数值
Zipf 定律 r⋅Pr≈cr \cdot P_r \approx cr⋅Pr​≈c，英语中 c≈0.1c \approx 0.1c≈0.1
AP89 39.7M 次词出现，198,763 个不同的词，70,064 个 hapax legomena（35%）
长为 NNN 的文档中的 n-gram 每个 nnn 有 N−n+1N - n + 1N−n+1 个；N=1000N = 1000N=1000 时，2≤n≤52 \le n \le 52≤n≤5 共 3,990 个

必记的 5 件事

  1. 分词的决定虽小，却可能大幅改变查询的效果，而且查询必须经过与文档完全相同的步骤。
  2. 词频服从 Zipf 分布：中间段 r⋅Pr≈0.1r \cdot P_r \approx 0.1r⋅Pr​≈0.1；少数词（"the"、"of" 约占 9–10%）占主导；AP89 词表中约 35% 的词只出现一次；该定律在两端都会偏离。
  3. 停用词的通常策略：全部索引，查询时再决定；停用词在组合中可能很重要。
  4. 词干提取器在假阳性与假阴性之间权衡：Porter 产生词干（cri），Krovetz 产生词。
  5. 短语可以用词性标注（准确、慢）、n-gram（快，但占存储：n = 2–5 时每 1,000 词有 3,990 个）或位置 + 邻近运算符来识别；锚文本是目标页面的强信号。
