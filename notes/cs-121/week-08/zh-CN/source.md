## 2. 文档作为向量

第 7 周以 tf-idf 收尾（[第 7 周第 18.3 节](week-07.zh-CN.md#183-tf-idf)）：$w_{t,d} = (1 + \log_{10} \mathrm{tf}_{t,d}) \times \log_{10}(N/\mathrm{df}_t)$，这是最著名的加权方案，它随词项在文档中的出现次数增加而增大，也随它在集合中的稀有程度增加而增大（L22 p4 回顾）。

**二值 → 计数 → 权重矩阵**（L21 p4–5）。词项-文档矩阵经历了三个版本：**关联矩阵**（0/1，[第 5 周](week-05.zh-CN.md#13-词项-文档关联矩阵)）→ **计数**（[第 7 周第 16 节](week-07.zh-CN.md#16-计数向量与词袋模型)）→ **tf-idf 权重**：

| | Antony and Cleopatra | Julius Caesar | The Tempest | Hamlet | Othello | Macbeth |
|---|---|---|---|---|---|---|
| Antony | 5.25 | 3.18 | 0 | 0 | 0 | 0.35 |
| Brutus | 1.21 | 6.1 | 0 | 1 | 0 | 0 |
| Caesar | 8.59 | 2.54 | 0 | 1.51 | 0.25 | 0 |
| Calpurnia | 0 | 1.54 | 0 | 0 | 0 | 0 |
| Cleopatra | 2.85 | 0 | 0 | 0 | 0 | 0 |
| mercy | 1.51 | 0 | 1.9 | 0.12 | 5.25 | 0.88 |
| worser | 1.37 | 0 | 0.11 | 4.15 | 0.25 | 1.95 |

**每个文档现在都由一个实值的 tf-idf 权重向量表示** $\in \mathbb{R}^{|V|}$——就是这张表中的一列。（幻灯片没有给出它的 N 或 df，所以这里无法重新算出这些权重。）

**文档作为向量**（L21 p6–10）：

- 我们有一个 **$|V|$ 维向量空间**（$|V|$ 为词表大小）。
- **词项是空间的坐标轴**。
- **文档是这个空间中的点或向量**。
- **维度极高**：对网络搜索引擎而言可达数千万维。
- **极其稀疏**：大多数分量为零（一个网页只用到词表的极小一部分）。

> 💡 **关键见解**：文档向量从来不会被存成 $|V|$ 个数字——它的非零分量恰好就是它的 postings。

## 3. 查询作为向量，以及为什么不用欧氏距离

**查询作为向量**（L21 p11–14 · L22 p5）：

- **关键思想 1**：对查询做同样的事——把它们表示为**同一空间中的向量**。
- **关键思想 2**：在这个空间中，**按文档与查询的接近程度给文档排序**。接近程度 = 向量的相似度；接近程度 ≈ 距离的倒数。
- 原因：我们希望摆脱**非此即彼的布尔模型**，转而把**更相关的文档排在更不相关的文档之前**（[第 7 周第 14 节](week-07.zh-CN.md#14-从布尔检索到排序检索)）。

**把接近程度形式化**（L21 p15–18）。最先想到的是两点之间的距离（即两个向量终点之间的距离）：**欧氏距离？** 这是**一个坏主意**，因为欧氏距离对**长度不同的向量**会**很大**——而**查询和文档的长度通常相差很大**。

**示意图**（L21 p19）：两个坐标轴，JEALOUS（x）与 GOSSIP（y），取值都在 0 到 1 之间。$d_1$ 几乎笔直向上（主要是 *gossip*），$d_3$ 几乎水平（主要是 *jealous*），而 $q$ 与 $d_2$ 指向几乎相同的方向（两个词项，比例相近）——但 $d_2$ 是一根长得多的箭头，伸出了单位正方形之外。$q$ 与 $d_2$ 之间的欧氏距离**很大**，尽管 $q$ 与 $d_2$ 中词项的分布非常相似。

L22 p7 用排序重复了同一个要点：在 term1/term2 坐标轴上，$q$ 位于 (1, 1) 附近。$d_1$ 位于过原点、与 $q$ **同一条直线**上、更远的位置；而 $d_2$ 作为一个点离 $q$ 更近，但方向更陡。**按欧氏 tf-idf：$d_2, d_1$。按余弦：$d_1, d_2$。**

> ⚠️ **易错点**：“离得最近”和“方向最相似”是两个不同的问题。一篇与查询主题完全相符的长文档，按欧氏距离衡量，离一个 3 词的查询*很远*。向量空间模型按**方向**排序。

## 4. 用夹角：余弦相似度

**思想实验**（L21 p20–24）：取一个文档 $d$，把它**接到自身后面**；记作 $d'$。

- “从语义上”看，$d$ 与 $d'$ 有**相同的内容**。
- 它们之间的**欧氏距离**可能**相当大**——很糟！
- 它们之间的**夹角**为 **0**，对应**最大相似度**——很好！

**关键思想：按文档与查询之间的夹角给文档排序。**

**从夹角到余弦**（L21 p25–26）。在 $[0°, 180°]$ 上，余弦是**单调递减**的函数（幻灯片画的是从 0° 到 360° 的 $\cos$：0° 时为 1，90° 时为 0，180° 时为 −1，360° 时回到 1）。因此按夹角排序与按余弦排序是等价的。幻灯片把“夹角**递减**的顺序”与“余弦**递增**的顺序”配对——这个等价是正确的，但我们*想要*的排序是另一对：**夹角递增 = 余弦递减**，最好的文档排在最前。

**cosine(query, document)**（L21 p27 · L22 p6）：

$$\cos(\vec q, \vec d) = \frac{\vec q \cdot \vec d}{\lvert\vec q\rvert\,\lvert\vec d\rvert} = \frac{\vec q}{\lvert\vec q\rvert} \cdot \frac{\vec d}{\lvert\vec d\rvert} = \frac{\sum_{i=1}^{|V|} q_i d_i}{\sqrt{\sum_{i=1}^{|V|} q_i^2}\,\sqrt{\sum_{i=1}^{|V|} d_i^2}}$$

$q_i$ 是词项 $i$ 在查询中的 tf-idf 权重，$d_i$ 是词项 $i$ 在文档中的 tf-idf 权重。分子是**点积**；除以两个向量的长度后，两个向量都变成了**单位向量**。$\cos(\vec q, \vec d)$ 就是 $q$ 与 $d$ 的余弦相似度——等价地说，就是它们夹角的余弦。

> 🔗 **延伸阅读**：[Croft §7.1.2 向量空间模型（书中第 237 页）](https://ciir.cs.umass.edu/downloads/SEIRiP.pdf) · [IIR 第 6 章（余弦相似度）](https://nlp.stanford.edu/IR-book/pdf/irbookonlinereading.pdf)

## 5. 长度归一化

向量的**长度归一化**是用它的 **$L_2$ 范数**去除每个分量（L21 p28–30）：

$$\lVert\vec x\rVert_2 = \sqrt{\sum_i x_i^2}$$

- 除以 $L_2$ 范数后，它成为一个**单位向量**——即**单位超球面表面上的一个点**。
- 对 $d$ 与 $d'$（$d$ 接到自身后面）的影响：长度归一化之后，它们是**完全相同的向量**。
- **长文档与短文档的权重现在可以相互比较了。**

**对于长度归一化的向量，余弦**（L21 p31）就是简单的**点积**（数量积）：

$$\cos(\vec q, \vec d) = \vec q \cdot \vec d = \sum_{i=1}^{|V|} q_i d_i \qquad \text{for } q, d \text{ length-normalized.}$$

**图示**（L21 p32）：坐标轴为 RICH 与 POOR，单位正方形，以及一条半径为 1 的虚线四分之一圆弧。归一化后的向量 $\vec v(d_1)$、$\vec v(q)$、$\vec v(d_2)$、$\vec v(d_3)$ 都终止于**这段圆弧上**；它们的区别只在方向，角度 $\theta$ 画在 $\vec v(d_1)$ 与 $\vec v(d_2)$ 之间。$\vec v(q)$ 与 $\vec v(d_2)$ 在圆弧上是紧邻的两个点。

**例子：三本小说有多相似？**（L21 p34–41）——*Sense and Sensibility*（SaS，《理智与情感》）、*Pride and Prejudice*（PaP，《傲慢与偏见》）、*Wuthering Heights*（WH，《呼啸山庄》），四个词项。为简单起见**不用 idf**，所以方案是 “lnc”：对数 tf、无 idf、余弦归一化。计数 → 对数权重 → 归一化 → 点积：

| 词项 | SaS | PaP | WH |
|---|---|---|---|
| affection | 115 | 58 | 20 |
| jealous | 10 | 7 | 11 |
| gossip | 2 | 0 | 6 |
| wuthering | 0 | 0 | 38 |

结果：$\cos(\text{SaS}, \text{PaP}) \approx 0.94$，$\cos(\text{SaS}, \text{WH}) \approx 0.79$，$\cos(\text{PaP}, \text{WH}) \approx 0.69$。两部奥斯汀的小说最为接近。逐步查看：

```viz tfidf-cosine
{"title": "三本小说两两之间的 lnc 余弦（L21 p34–41）", "docs": "SaS: affection:115 jealous:10 gossip:2 wuthering:0; PaP: affection:58 jealous:7 gossip:0 wuthering:0; WH: affection:20 jealous:11 gossip:6 wuthering:38", "scheme": "lnc"}
```

> 💡 **关键见解**：L21 p38 的注释指出：文档一旦归一化，它们就已经“位于超球面表面上”，所以余弦在查询时无需再做除法——只需点积。这正是搜索引擎在**建索引时**就对文档向量做归一化的原因。

## 6. 计算余弦分数

算法（L21 p33 · L22 p9，后者高亮了最后一行 “Top K components of Scores[]”）：

```text
CosineScore(q)
 1  float Scores[N] = 0
 2  float Length[N]
 3  for each query term t
 4  do calculate w_t,q and fetch postings list for t
 5       for each pair(d, tf_t,d) in postings list
 6       do Scores[d] += w_t,d × w_t,q
 7  Read the array Length
 8  for each d
 9  do Scores[d] = Scores[d] / Length[d]
10  return Top K components of Scores[]
```

- 它是**按词项处理**的（[第 7 周第 11 节](week-07.zh-CN.md#11-按文档处理与按词项处理)）：`Scores` 就是**累加器**，每次填充一个 postings 列表。
- 只有包含**至少一个查询词项**的文档才会得到非零分数——读取的只有 postings 列表。
- `Length[d]` 在**建索引时**计算，这里只是读取（第 7 行）；最后的除法（第 9 行）是余弦中关于文档的那一半。查询的长度对每个文档都相同，所以不会改变排序。
- 第 10 行就是第 10 节要解决的问题：不必对所有结果排序，直接得到前 K 个。

下面用 Python 实现同样的步骤，取 L21 的 lnc.ltc 例子（§7）：文档 *car insurance auto insurance*，查询 *best car insurance*：

```python
import heapq
import math

# The lnc.ltc example (L21 p47-53): one document.
docs = {"d": "car insurance auto insurance".split()}
df = {"auto": 5000, "best": 50000,
      "car": 10000, "insurance": 1000}
N = 1_000_000

def log_tf(tf):
    return 1 + math.log10(tf) if tf > 0 else 0

# Index time: postings (d, tf) and Length[d] (lnc)
postings, length = {}, {}
for d, words in docs.items():
    counts = {t: words.count(t) for t in set(words)}
    for t, tf in counts.items():
        postings.setdefault(t, []).append((d, tf))
    length[d] = math.sqrt(sum(log_tf(tf) ** 2
                              for tf in counts.values()))

def cosine_score(query, K=10):
    q = {t: query.count(t) for t in set(query)}
    w_q = {t: log_tf(tf) * math.log10(N / df[t])
           for t, tf in q.items()}          # ltc ...
    q_len = math.sqrt(sum(w * w for w in w_q.values()))
    scores = {}                             # line 1
    for t, wtq in w_q.items():              # lines 3-4
        for d, tf in postings.get(t, []):   # line 5
            scores[d] = scores.get(d, 0) + \
                log_tf(tf) * wtq / q_len    # line 6
    for d in scores:                        # lines 7-9
        scores[d] /= length[d]
    return heapq.nlargest(K, scores.items(),
                          key=lambda x: x[1])  # line 10

print(round(length["d"], 2))
print([(d, round(s, 2)) for d, s in
       cosine_score("best car insurance".split())])
```

```text
1.92
[('d', 0.8)]
```

文档长度 1.92 与分数 0.8 来自幻灯片（L21 p52–53）。（幻灯片上没有印出 $N$ = 1,000,000；它是能复现其 idf 列的数值，例如 $\log_{10}(10^6/5000) = 2.3$。）

## 7. tf-idf 变体与 SMART 记号

**tf-idf 加权有很多变体**（L21 p42 · p50）。括号中是每种选择的**单字母代号**。

| 词项频率 | | 文档频率 | | 归一化 | |
|---|---|---|---|---|---|
| n（自然） | $\mathrm{tf}_{t,d}$ | n（无） | 1 | n（无） | 1 |
| **l（对数）** | $1 + \log(\mathrm{tf}_{t,d})$ | **t（idf）** | $\log \frac{N}{\mathrm{df}_t}$ | **c（余弦）** | $\frac{1}{\sqrt{w_1^2 + w_2^2 + \dots + w_M^2}}$ |
| a（增广） | $0.5 + \frac{0.5 \times \mathrm{tf}_{t,d}}{\max_t(\mathrm{tf}_{t,d})}$ | p（概率 idf） | $\max\{0, \log \frac{N - \mathrm{df}_t}{\mathrm{df}_t}\}$ | u（枢轴唯一） | $1/u$ |
| b（布尔） | 若 $\mathrm{tf}_{t,d} > 0$ 则为 1，否则为 0 | | | b（字节大小） | $1/\mathit{CharLength}^{\alpha}$，$\alpha < 1$ |
| L（对数平均） | $\frac{1 + \log(\mathrm{tf}_{t,d})}{1 + \log(\mathrm{ave}_{t \in d}(\mathrm{tf}_{t,d}))}$ | | | | |

第一行（n、n、n——原始计数，无 idf，无归一化）在幻灯片上被框了出来；加粗的那一行（l、t、c，幻灯片上为红色）是 **ltc：“通常采用的通用标准”**（p42；p50 上只写了 “ltc: standard”）。

**查询与文档的加权可以不同**（L21 p43–46）：

- 许多搜索引擎允许对**查询和文档使用不同的加权**。
- **SMART 记号**用 **ddd.qqq** 表示引擎所用的组合——文档三个字母，查询三个字母，字母取自上表。
- **一个非常标准的加权方案是 lnc.ltc**：
  - **文档**：**l**，对数 tf；**n**，无 idf；**c**，余弦归一化。
  - **查询**：**l**，对数 tf；idf（**t**）；**c**，余弦归一化。

**tf-idf 例子：lnc.ltc**（L21 p47–53）。文档 *car insurance auto insurance*；查询 *best car insurance*。幻灯片按列填写下表（原始 tf → tf 权重 → df/idf → 权重 → 归一化 → 乘积）：

## 8. 向量空间排序的总结与扩展

**总结——向量空间排序**（L21 p54–56）：

1. 把**查询**表示为加权的 tf-idf 向量。
2. 把**每个文档**表示为加权的 tf-idf 向量。
3. 计算查询向量与每个文档向量的**余弦相似度**分数。
4. 按分数对文档相对于查询进行**排序**。
5. 把**前 K 个**（例如 K = 10）返回给用户。

**打分的一种可能的聚合方式**（L21 p57）——真正的引擎会把向量空间分数与其他证据混合起来：

$$S(q, D) = \alpha\left[\beta \sum_{t \in (q \cap D)} \mathrm{tfidf}_{t,D}\,\bigl(1 + P(t, D)\bigr) + (1 - \beta)\cos(q, D)\right] \times \bigl(1 + \Phi(q, D)\bigr) + (1 - \alpha)\,g(D)$$

| 符号 | 含义 |
|---|---|
| $\mathrm{tfidf}(t, D)$ | 词项 $t$ 在文档 $D$ 中的 tf.idf |
| $\cos(q, D)$ | 查询 $q$ 与文档 $D$ 向量之间的余弦相似度 |
| $P(t, D)$ | 词元 $t$ 在 $D$ 中的**“字段权重”**——提升那些词元出现在**标题、粗体、斜体**等位置的文档 |
| $\Phi(q, D)$ | $q$ 在 $D$ 中的**“短语权重”**——提升那些词元以**与查询相同的顺序和相同的距离**出现的文档 |
| $g(D)$ | 文档**自身特征与链接分析**（例如 PageRank、HITS）的函数 |
| $\alpha$ | 可调参数：平衡**查询 + 文档**部分与**仅文档**部分 |
| $\beta$ | 可调参数：平衡 **tf.idf** 部分与**余弦**部分 |

> 💡 **关键见解**：从内到外读这个式子：tf-idf 经字段加权，与余弦按 $\beta$ 混合，再由短语匹配 $\Phi$ 提升，最后与查询无关的质量分数（$\alpha$、$g$）混合。$P$ 需要建索引时的字段信息，$\Phi$ 需要**位置**（[第 7 周第 5 节](week-07.zh-CN.md#5-位置索引)），而 $g$ 就是第 9 周的 PageRank/HITS——议程中的“字段与区域”“查询词项邻近度”和“静态质量分数”都在这一个式子里。

> 🔗 **延伸阅读**：[Croft §7.4 复杂查询与证据组合（书中第 267 页）](https://ciir.cs.umass.edu/downloads/SEIRiP.pdf) · [Croft §7.5 网络搜索（书中第 279 页）](https://ciir.cs.umass.edu/downloads/SEIRiP.pdf) · [IIR 第 7 章（完整的搜索系统）](https://nlp.stanford.edu/IR-book/pdf/irbookonlinereading.pdf)

## 9. 高效的余弦排序

L22（“Scoring and result assembly”，打分与结果组装）提出了如何让第 6 节的算法变快的问题（L22 p10–17）：

- 在集合中找出与查询“最近”的**K 个文档** ⇒ 即查询与文档余弦中**最大的 K 个**。
- 高效排序意味着两件事：高效地**计算单个余弦**，以及高效地**选出最大的 K 个**余弦值。
- **能否不计算全部 N 个余弦就完成这件事？**
- 我们实际上是在为查询向量求解 **K 近邻问题**。一般来说，我们**不知道如何在高维空间中高效地做到这一点**——
- **但**对网络搜索而言我们不必如此：**查询向量高度稀疏！** 对于短查询，这个问题**是可以解决的**，并且**标准索引对此支持得很好**（只需读取查询词项的少数几个 postings 列表）。

**特殊情形——无权重查询**（L22 p18）：对查询词项不加权——假设每个查询词项只出现一次。这样**为了排序，你不需要对查询向量做归一化**：每个文档的分数都除以同一个查询长度，这不会改变顺序。（因此 $w_{t,q} = 1$，`CosineScore` 第 6 行只需累加 $w_{t,d}$。）

> 🔗 **延伸阅读**：[IIR 第 7 章（高效打分与排序）](https://nlp.stanford.edu/IR-book/pdf/irbookonlinereading.pdf) · [Croft §5.7.3 优化技术（书中第 170 页）](https://ciir.cs.umass.edu/downloads/SEIRiP.pdf)

## 10. 用堆选出前 K 个

**选择与排序**（L22 p19–21）：我们通常只想要余弦排序中的**前 K 个**文档，**而不是**集合中**所有文档的全序**。能否直接挑出余弦最高的 K 个文档？设 **J 为余弦非零的文档数**；我们要的是这 J 个中**最好的 K 个**。

**使用堆**（L22 p22）：

- 一棵**二叉树，其中每个节点的值大于其子节点的值**（即最大堆；参见 [ICS 46 第 10 讲第 9 节](../ICS-46/lec-10.zh-CN.md#9-堆有序的二叉树)）。
- **构建需要 2J 次操作**，然后每个**K 个“胜出者”**可以在 **2 log J 步**内取出。
- **当 J = 100 万、K = 100 时，这大约只是排序成本的 10%！**

取以 2 为底的对数，排序需要 $J \log_2 J$ 次比较：堆 $= 2J + 2K\log_2 J \approx$ 200 万，排序约 1990 万，比值为 **0.10**——即幻灯片上的 10%。（在 Python 中，§6 里的 `heapq.nlargest(K, …)` 正是做这件事。）

> ⚠️ **易错点**：节省来自 K ≪ J：建堆是线性的，而 $\log J$ 只需付出 K 次。排序则要为**每一个**的 J 个文档付出 $\log J$。

## 11. 余弦只是代理：近似的前 K 个

**瓶颈**（L22 p23–27）：打分中的**主要计算瓶颈**是**余弦计算**。能否避开所有这些计算？**可以，但有时可能会算错**：一个**不在**前 K 个中的文档**可能会混进**输出的 K 个文档列表。**这是件很坏的事吗？**

**余弦相似度只是一个代理！**（L22 p28–31）

- **用户有一个任务**，以及一个**查询表述**。
- **余弦衡量的是文档与查询的匹配**——而不是与任务的匹配。
- 因此，余弦无论如何都只是**用户满意度的一个代理**。
- 如果我们得到的 K 个文档列表，按余弦来看与前 K 个“接近”，它**应该是可以接受的**。

**通用方法**（L22 p32–35）：

- 找一个**候选集合 A**，满足 $K < |A| \ll N$。
  - $A$ **不一定包含前 K 个**，
  - 但它包含**前 K 个中的许多文档**。
  - 返回 $A$ 中的前 K 个文档。
- 可以把 $A$ 看作**剪掉非候选者**的结果。
- 同样的方法也用于**其他（非余弦）的打分函数**。
- 我们将看几种遵循这一思路的方案：本周看**索引剪枝**（§12）；champion 列表、分层索引及其余内容见[第 9 周](week-09.zh-CN.md)。

> 💡 **关键见解**：对比第 7 周的**安全**与**不安全**优化（[第 7 周第 13 节](week-07.zh-CN.md#13-阈值方法maxscore-与提前终止)）：从这里开始，一切都刻意是**不安全**的——用精确的前 K 个换取速度，这样做是合理的，因为精确的前 K 个从来都不是真正的目标。

## 12. 索引剪枝

基本的余弦算法**本来就只考虑包含至少一个查询词项的文档**（L22 p36–37）。把这一启发式进一步推广：

1. **只考虑高 idf 的查询词项。**
2. **只考虑包含许多查询词项的文档。**

**只用高 idf 的查询词项**（L22 p38–40）：对于 *catcher in the rye* 这样的查询，**只累加 *catcher* 和 *rye* 的分数**。直觉是：*in* 和 *the* 对分数贡献很小，因此**基本不会改变排序**。好处是：**低 idf 词项的 postings 包含很多文档** → 这些（很多！！！）文档会被**从候选集合 A 中剔除**。

**包含许多查询词项的文档**（L22 p41–45，p47）：

- 任何包含至少一个查询词项的文档，都是前 K 个输出列表的候选。
- 对于**多词项查询**，只为包含**若干个查询词项**（甚至可能是全部词项！）的文档计算分数——比如**四个中至少三个**。
- 这相当于对查询施加了一个**“软合取”**，这在网络搜索引擎（**早期的 Google**）上可以见到。
- 如果限制太严，它**可能最终得到的候选少于 K 个**。可以在此之上再加一个启发式：**可以迭代！**（放宽到更少的词项）。
- **很容易在 postings 遍历中实现。**

**例子：四个查询词项中的三个**（L22 p46）：

| 词项 | Postings |
|---|---|
| Antony | 3 4 **8** **16** **32** 64 128 |
| Brutus | 2 4 **8** **16** **32** 64 128 |
| Caesar | 1 2 3 5 **8** 13 21 34 |
| Calpurnia | 13 **16** **32** |

**只为文档 8、16 和 32 计算分数**（即方框中的 postings）。如果只想向用户展示 **2 个文档**，这就够了；如果需要更多，就**迭代**，并同时为包含 **2 个**查询词项的文档计算分数。

> ⚠️ **易错点**：“至少 3 个（共 4 个）”不是 AND——文档 8 缺少 Calpurnia，文档 16 缺少 Caesar，两者都会被打分。它是对文档出现在几个列表中的阈值判断，而按文档处理的遍历可以免费地数出这个次数。

> 📝 **练习**：[例题 14.5](#145-四个查询词项中至少命中三个哪些文档会被打分l22-p46)

> 🔗 **延伸阅读**：[IIR 第 7 章（索引剪枝、近似 top K）](https://nlp.stanford.edu/IR-book/pdf/irbookonlinereading.pdf) · [Croft §5.7.3 优化技术（书中第 170 页）](https://ciir.cs.umass.edu/downloads/SEIRiP.pdf)

### 14.1 按距离与夹角排序 d1 和 d2（L22 p7）

在 term1/term2 坐标轴上，查询 $q$ 位于 (1, 1) 附近。$d_1$ 位于过原点、与 $q$ **同一条直线**上、更远的位置；$d_2$ 是一个**离 $q$ 更近**的点，但方向更陡（term2 比 term1 多）。请分别按欧氏距离与余弦对 $d_1$、$d_2$ 排序。

余弦才是对的：$d_1$ 中查询词项的比例与查询相同，只是更长——就像 §4 中的 $d'$。（幻灯片没有给出坐标；这里是从图中读出的。）

### 14.2 三本小说有多相似？（L21 p34–41）

计数（无 idf）：affection 在 SaS / PaP / WH 中分别为 115 / 58 / 20；jealous 为 10 / 7 / 11；gossip 为 2 / 0 / 6；wuthering 为 0 / 0 / 38。计算对数频率权重，做长度归一化，并求三对两两余弦。为什么 $\cos(\text{SaS}, \text{PaP}) > \cos(\text{SaS}, \text{WH})$？

<details>
<summary>解答</summary>

**1. 对数频率权重** $1 + \log_{10}\mathrm{tf}$（若 tf = 0 则为 0）：

| 词项 | SaS | PaP | WH |
|---|---|---|---|
| affection | 3.06 | 2.76 | 2.30 |
| jealous | 2.00 | 1.85 | 2.04 |
| gossip | 1.30 | 0 | 1.78 |
| wuthering | 0 | 0 | 2.58 |

**2. 长度**：SaS $\sqrt{3.06^2 + 2.00^2 + 1.30^2} = 3.881$，PaP 3.323，WH 4.391。把每一列除以它的长度：

| 词项 | SaS | PaP | WH |
|---|---|---|---|
| affection | 0.789 | 0.832 | 0.524 |
| jealous | 0.515 | 0.555 | 0.465 |
| gossip | 0.335 | 0 | 0.405 |
| wuthering | 0 | 0 | 0.588 |

（幻灯片第 37 页把 PaP 的 jealous 印成 0.557；$1.845 / 3.323 = 0.555$。）

**3. 点积**（向量是单位长度，所以点积 = 余弦）：

- $\cos(\text{SaS}, \text{PaP}) = 0.789 \times 0.832 + 0.515 \times 0.557 + 0.335 \times 0 + 0 \times 0 \approx$ **0.94**
- $\cos(\text{SaS}, \text{WH}) \approx$ **0.79**
- $\cos(\text{PaP}, \text{WH}) \approx$ **0.69**

（精确值：0.942、0.789、0.694——无论取 0.555 还是 0.557，到两位小数都相同。）

**为什么 SaS–PaP > SaS–WH？** SaS 与 PaP 具有**相同的形状**：以 *affection* 为主，有一些 *jealous*，几乎没有 *gossip*，并且**完全没有 *wuthering***。WH 把权重分散到全部四个词项上，并且有一个很大的 *wuthering* 分量，而另外两本小说完全没有这一分量——这一维度增加了 WH 的长度，但在与 SaS 或 PaP 的每一次乘积中都贡献 **0**。比例相同 → 夹角小 → 余弦高，与书的长短无关。

</details>

### 14.3 用 lnc.ltc 为 best car insurance 打分（L21 p47–53）

文档 *car insurance auto insurance*；查询 *best car insurance*；df：auto 5000，best 50000，car 10000，insurance 1000。填写 lnc.ltc 表并计算分数。

<details>
<summary>解答</summary>

**查询（ltc）**：原始 tf——best 1，car 1，insurance 1，auto 0 → tf 权重 1、1、1、0。idf = $\log_{10}(N/\mathrm{df})$：auto 2.3，best 1.3，car 2.0，insurance 3.0（与幻灯片的值一致，取 $N = 10^6$ 可复现）。权重 = tf 权重 × idf：auto 0，best 1.3，car 2.0，insurance 3.0。长度 $= \sqrt{1.3^2 + 2.0^2 + 3.0^2} = 3.83$ → 归一化后：best **0.34**，car **0.52**，insurance **0.78**。

**文档（lnc）**：原始 tf——auto 1，best 0，car 1，insurance 2 → tf 权重 1、0、1、$1 + \log_{10} 2 = 1.3$。没有 idf，所以权重 = tf 权重。长度 $= \sqrt{1^2 + 0^2 + 1^2 + 1.3^2} \approx 1.92$ → 归一化后：auto **0.52**，car **0.52**，insurance **0.68**。

**乘积**：auto $0 \times 0.52 = 0$；best $0.34 \times 0 = 0$；car $0.52 \times 0.52 = 0.27$；insurance $0.78 \times 0.68 = 0.53$。

**分数 = 0 + 0 + 0.27 + 0.53 = 0.8**（未取整：0.801）。*auto* 在文档中但不在查询中，*best* 在查询中但不在文档中：两者的贡献都是 0，但它们仍然计入各自向量的长度。

</details>

### 14.4 一百万文档：堆与排序（L22 p22）

建堆需要 2J 次操作，每个胜出者需要 2 log J 步。从 J = 1,000,000 个中选出前 K = 100 个，与对全部 J 个排序相比如何？

<details>
<summary>解答</summary>

- 堆：$2J + K \cdot 2\log_2 J = 2{,}000{,}000 + 100 \times 2 \times 19.93 \approx 2{,}003{,}986$ 次操作。

- 比值 ≈ **0.10** → 即幻灯片所说的“约为排序成本的 10%”。

线性的建堆部分占主导；那 100 次取出几乎不计。（以 2 为底的对数，以及排序取 $J\log_2 J$，是我的假设；幻灯片只给出了 10%。）

## 15. 速查与必记的 5 件事

**向量空间模型**

| 概念 | 一句话概括 | 幻灯片 |
|---|---|---|
| 文档向量 | $\mathbb{R}^{\lvert V\rvert}$ 中 tf-idf 权重的一列；词项即坐标轴；极其稀疏 | L21 p4–10 |
| 查询向量 | 同一空间中的查询；按接近程度给文档排序 | L21 p11–14 |
| 欧氏距离 | 不好：对长度不同的向量很大 | L21 p15–19，L22 p7 |
| 夹角 / 余弦 | $d$ 与 $d$+$d$ 的夹角为 0；按余弦递减排序 | L21 p20–26 |
| 长度归一化 | 除以 $L_2$ 范数 → 单位向量；长短文档可比 | L21 p28–30 |
| 单位向量的余弦 | 点积 $\sum_i q_i d_i$ | L21 p31 |

**公式**

| 名称 | 公式 |
|---|---|
| tf-idf | $w_{t,d} = (1 + \log_{10}\mathrm{tf}_{t,d}) \times \log_{10}(N/\mathrm{df}_t)$ |
| $L_2$ 范数 | $\lVert\vec x\rVert_2 = \sqrt{\sum_i x_i^2}$ |
| 余弦 | $\cos(\vec q, \vec d) = \dfrac{\vec q \cdot \vec d}{\lvert\vec q\rvert\,\lvert\vec d\rvert}$ |
| 聚合分数 | $\alpha[\beta\sum \mathrm{tfidf}(1+P) + (1-\beta)\cos] \times (1 + \Phi) + (1-\alpha)g(D)$ |

**SMART 字母**（ddd.qqq——文档在前）

| 位置 | 字母 |
|---|---|
| tf | n 自然 · **l** 对数 · a 增广 · b 布尔 · L 对数平均 |
| df | n 无 · **t** idf · p 概率 idf |
| 归一化 | n 无 · **c** 余弦 · u 枢轴唯一 · b 字节大小 |
| 标准 | **lnc.ltc**：文档对数 tf，无 idf，余弦；查询对数 tf，idf，余弦 |

**更快的排序**

| 技术 | 思路 | 精确吗？ |
|---|---|---|
| 稀疏查询 + 索引 | 只读取查询词项的 postings | 是 |
| 无权重查询 | 跳过查询归一化 | 是（排序不变） |
| 用堆取前 K 个 | 建堆 2J + 每个胜出者 2 log J（J = 100 万、K = 100 时约为排序的 10%） | 是 |
| 候选集合 A | $K < \lvert A\rvert \ll N$，返回 A 中的前 K 个 | 否 |
| 索引剪枝：高 idf 词项 | 跳过低 idf 词项（*in*、*the*） | 否 |
| 索引剪枝：多词项 | 只保留至少含 m 个查询词项的文档（“软合取”）；若不足 K 个则迭代 | 否 |

**必记的 5 件事**

1. 按**夹角而非距离**排序：余弦就是**长度归一化**的 tf-idf 向量的点积，因此一个文档和它的双倍副本是完全相同的。
2. 文档在**建索引时**就做归一化（`Length[d]`）；查询的长度从不改变排序，因此无权重查询完全不需要归一化。
3. **SMART 的 ddd.qqq 把文档放在前面**：lnc.ltc = 文档对数 tf + 余弦，无 idf；查询对数 tf + idf + 余弦。幻灯片例子的分数：**0.8**。
4. `CosineScore` 是带累加器的**按词项处理**，它的最后一行是**前 K 选择**——堆胜过对全部 J 个已打分文档排序（J = 100 万、K = 100 时约为成本的 10%）。
5. 余弦**只是**用户满意度的代理，因此**近似的前 K 个**是可以接受的：构造一个候选集合 A——例如用**索引剪枝**（只用高 idf 词项；保留四个中至少 3 个词项的文档，若太少则迭代）。
