1. 链接为何是证据

从页面 xxx 到页面 yyy 的一条链接，是一个微小的、由人作出的判断：xxx 的作者认为 yyy 值得指向。仅靠文本匹配，无法区分一个受人尊重的页面与一个复制品，或与之用了相同词语的垃圾页面；链接结构却可以做到。

网络搜索当时多么迫切地需要这一信号：在 1997 年 11 月，"only one of the top four commercial search engines finds itself"（即四大商业搜索引擎中只有一个，在搜索自身名称时，能在前十条结果中返回它自己的搜索页面）。Brin 和 Page 在提出 PageRank 的论文中明确表述的目标是 "to improve the quality of web search engines"（提高网络搜索引擎的质量）。

📘 延伸阅读： Brin & Page, "The Anatomy of a Large-Scale Hypertextual Web Search Engine" (1998) · Page, Brin, Motwani & Winograd, "The PageRank Citation Ranking: Bringing Order to the Web"

两个经典算法把链接转化为分数：

  • HITS（§2）以每个查询为单位：它收集查询结果周围的页面，找出两类好页面，即枢纽页和权威页。
  • PageRank（§3–§5）对整个网络只计算一次：为每个页面给出一个与查询无关的分数，即随机游走者的长期访问率。

2. HITS：枢纽页与权威页

2.1 枢纽页与权威页

超链接诱导的主题搜索（HITS）。对于一个查询，它不返回一个由各自满足查询的页面组成的有序列表，而是找出两组相互关联的页面：

  • 枢纽页是关于某一主题的优质链接列表，例如 Bob 的癌症相关链接列表。
  • 权威页会反复出现在该主题的优质枢纽页上。

HITS 最适合"宽泛主题"查询，而不是找单个页面的查询；它能反映更广泛的大众共识。

这一定义是循环的：

  • 某一主题的好枢纽页会指向该主题的许多权威页。
  • 某一主题的好权威页会被该主题的许多好枢纽页指向。

这种循环被转化为一个迭代计算。其设想是：如果枢纽 Alice 和 Bob 都链接到 AT&T、Sprint 和 Tmob，那么这三者会作为移动电信公司的权威页脱颖而出（计算过程见 §2.5）。

2.2 基础集与连通性服务器

总体方案：从网络中抽取一个基础集，其中的页面可能是好的枢纽页或权威页；再用迭代算法从中找出少量排名靠前的枢纽页与权威页。

构建基础集：

  1. 给定一个文本查询（比如 browser），用文本索引取得所有包含 browser 的页面，称之为根集。
  2. 加入任何指向根集中某个页面，或被根集中某个页面指向的页面。
  3. 称之为基础集。

可以把根集想象成一块内部区域，把基础集想象成包围它的一个方框，方框中还包括与之相连的邻居页面；根集的入链（以及出链）则来自连通性服务器。

连通性服务器：支持对网络图进行快速查询，即哪些 URL 指向某个给定的 URL？某个给定的 URL 指向哪些 URL？

  • 在内存中保存从 URL 到出链、从 URL 到入链的映射。
  • 利用图的稀疏性质（不要构造整个矩阵！）。
  • 应用包括：爬取控制；网络图分析（连通性、爬取优化）；链接分析（HITS、PageRank 等）。

2.3 迭代过程

提炼枢纽页与权威页。对基础集中的每个页面 xxx，计算一个枢纽分数 h(x)h(x)h(x) 和一个权威分数 a(x)a(x)a(x)。

  • 初始化：对所有 xxx，h(x)←1h(x) \leftarrow 1h(x)←1，a(x)←1a(x) \leftarrow 1a(x)←1。
  • 迭代更新所有 h(x)h(x)h(x)、a(x)a(x)a(x)：
h(x)←∑x↦ya(y)a(x)←∑y↦xh(y)h(x) \leftarrow \sum_{x \mapsto y} a(y) \qquad\qquad a(x) \leftarrow \sum_{y \mapsto x} h(y)h(x)←x↦y∑​a(y)a(x)←y↦x∑​h(y)

x↦yx \mapsto yx↦y 表示"xxx 链接到 yyy"：一个页面的枢纽分数，是它所指向的页面的权威分数之和；它的权威分数，是指向它的页面的枢纽分数之和。

  • 经过若干次迭代（或收敛之后），输出h()h()h() 最高的页面作为顶级枢纽页，输出a()a()a() 最高的页面作为顶级权威页。

缩放：为防止 h()h()h() 和 a()a()a() 变得过大，要在每次迭代后缩小。缩放因子其实无关紧要（只要保持一致）：我们只关心分数的相对值。

需要多少次迭代？ 结论是：分数的相对值会在几次迭代之后收敛，经过适当缩放，h()h()h() 和 a()a()a() 会趋于一个稳态。实践中，约 5 次迭代就足以接近稳定。

⚠️ 易错点：箭头就是全部诀窍。枢纽的分数来自它所指向的权威之和；权威的分数来自指向它的枢纽之和。把两者弄反是经典错误。

📘 延伸阅读：若以基础集的邻接矩阵 MMM 表示（Mxy=1M_{xy} = 1Mxy​=1 当且仅当 x↦yx \mapsto yx↦y），每一轮可写为 a←MTh\mathbf{a} \leftarrow M^T\mathbf{h}a←MTh，h←Ma\mathbf{h} \leftarrow M\mathbf{a}h←Ma，于是缩放后的分数会收敛到 MTMM^TMMTM（权威）和 MMTMM^TMMT（枢纽）的主特征向量。这正是相对值能达到稳态的原因。（IIR 第 21 章 Link analysis，§21.3）

2.4 例子与问题

日本小学：一个分两栏展示的 HITS 结果。枢纽页包括 "100 Schools Home Pages (English)"、"K-12 from Japan"、"Koulutus ja oppilaitokset"（芬兰语）和 "Education"；权威页包括 "The American School in Japan"、"KEIMEI GAKUEN Home Page (Japanese)"、"Torisu primary school" 和 "Yakumo Elementary, Hokkaido, Japan"，另有许多日文标题的页面。

需要注意的是：

  • 它不论页面内容是什么语言，都能把好的页面聚集起来。
  • 基础集组装完成之后，它只使用链接分析；迭代打分与查询无关。
  • 文本索引检索之后的迭代计算是不小的开销（但不发生在查询时！）。

HITS 的问题：

  • 主题漂移：离题的页面可能导致离题的"权威"被返回，例如邻域图可能围绕某个"超级主题"展开。
  • 相互强化的附属站点：附属页面或站点可以相互抬高分数。附属页面之间的链接并不是有用的信号，因此分析中应避免考虑它们。

📘 延伸阅读：IIR 第 21 章 Link analysis · Croft §4.5 Link Analysis（书中第 104 页）、§4.5.3 Link Quality（书中第 111 页）

移动电信图上的 HITS

解答

第 1 轮。 由 h=1h = 1h=1 得到权威分数：AT&T 被 Alice、Bob 和 Carol 指向 → 3；Sprint 与 Tmob 各被 Alice 和 Bob 指向 → 各为 2。除以 3 缩放后：AT&T = 1，Sprint = Tmob = 0.667。由这些权威分数得到枢纽分数：Alice = Bob = 1 + 0.667 + 0.667 = 2.333，Carol = 1。除以 2.333 缩放后：Alice = Bob = 1，Carol = 0.429。

用 Python 运行各轮：

links = {
    "Alice": ["AT&T", "Sprint", "Tmob"],
    "Bob":   ["AT&T", "Sprint", "Tmob"],
    "Carol": ["AT&T"],
}
pages = sorted(set(links) | {y for ys in links.values() for y in ys})
h = {x: 1.0 for x in pages}
a = {x: 1.0 for x in pages}
for it in range(1, 6):
    a = {x: sum(h[y] for y in pages if x in links.get(y, [])) for x in pages}
    h = {x: sum(a[y] for y in links.get(x, [])) for x in pages}
    sa, sh = max(a.values()), max(h.values())   # scale: largest score = 1
    a = {x: v / sa for x, v in a.items()}
    h = {x: v / sh for x, v in h.items()}
    print(it, "a:", {x: round(v, 3) for x, v in a.items() if v},
          "h:", {x: round(v, 3) for x, v in h.items() if v})

3. PageRank：随机游走者

3.1 随机游走

PageRank 打分。设想一个浏览器在网页上做随机游走：

  • 从一个随机页面开始。
  • 每一步，都沿当前页面上的某条链接离开，且每条链接被选中的概率相等（一个有三条出链的页面，每条出链被选中的概率都是 1/3）。
  • 在稳态下，每个页面都有一个长期访问率，并把它作为该页面的分数。

3.2 死胡同与远程跳转

还不够：网络上充满了死胡同（有入链但没有出链的页面）。随机游走可能会卡在死胡同里，而一旦如此，讨论长期访问率就没有意义了。

远程跳转：

  • 在死胡同处，跳转到一个随机网页。
  • 在非死胡同处，以 10% 的概率跳转到一个随机网页；以其余的概率（90%）沿一条随机链接离开。
  • 这里的 10% 是一个参数。

远程跳转的结果：现在游走者不会在局部卡住，并且任何页面都有一个长期被访问的速率（这一点并不显然）。PageRank 的思想是：这个随机游走者访问得越多的页面，就越重要。如何计算这一访问率，见 §4。

💡 关键洞见：与 HITS 不同，PageRank 是为整个网络计算一次，而不是按查询计算，它是 查询处理与高效 Top-K 中的静态质量分数 g(d)g(d)g(d)。而与锚文本（文本处理）不同，它只使用链接结构，而不使用链接上的文字。

📘 延伸阅读：Croft §4.5.2 PageRank（书中第 105 页） · IIR 第 21 章 Link analysis

4. 计算 PageRank

计算 PageRank 有两种方法：1. 代数计算（原始 Google 论文中所用的方法）和 2. 马尔可夫链模型。本节展开的是代数方法。

4.1 公式

pi=(1−d)+d∑j=1N(Lijcj)pjcj=∑i=1NLijp_i = (1 - d) + d \sum_{j=1}^{N} \left(\frac{L_{ij}}{c_j}\right) p_j \qquad\qquad c_j = \sum_{i=1}^{N} L_{ij}pi​=(1−d)+dj=1∑N​(cj​Lij​​)pj​cj​=i=1∑N​Lij​

pip_ipi​ 是页面 iii 的 PageRank，pjp_jpj​ 是页面 jjj 的 PageRank；若页面 jjj 指向 iii，则 Lij=1L_{ij} = 1Lij​=1，否则为 0；cjc_jcj​ 是离开页面 jjj 的链接数（即它的出链数）；ddd 是阻尼因子。

同一公式，按 Google 论文的写法为：

PR(A)=(1−d)+d(PR(T1)C(T1)+⋯+PR(Tn)C(Tn))PR(A) = (1 - d) + d \left( \frac{PR(T_1)}{C(T_1)} + \dots + \frac{PR(T_n)}{C(T_n)} \right)PR(A)=(1−d)+d(C(T1​)PR(T1​)​+⋯+C(Tn​)PR(Tn​)​)

AAA 是一个页面；T1…TnT_1 \dots T_nT1​…Tn​ 是链接到 AAA 的页面；PR(Ti)PR(T_i)PR(Ti​) 是 TiT_iTi​ 的 PageRank；C(Ti)C(T_i)C(Ti​) 是 TiT_iTi​ 的出向链接数；ddd 是阻尼（远程跳转）因子，通常取 0.85。

⚠️ 易错点：C(Ti)C(T_i)C(Ti​) 统计的是投出票的页面的出链数，而不是 AAA 的入链数。出链很多的页面会把它的 PageRank 分成许多小份的投票。

两种参数化方式是一致的：ddd 是沿链接前进的概率，所以随机游走中的"10% 远程跳转"对应 d=0.9d = 0.9d=0.9，而公式中的 d=0.85d = 0.85d=0.85 对应 15% 的远程跳转。公式经过缩放，使平均 PageRank 为 1（而不是总和为 1）：在下面的例子中，三个值的和始终为 N=3N = 3N=3。

4.3 矩阵记法

e = np.ones(N)
Dc_inv = np.diag(1 / L.sum(axis=0))   # c_j = out-links of j
A = (1 - d) * np.outer(e, e) / N + d * L @ Dc_inv

p = np.ones(N)                 # guess 1
for k in range(50):
    p = A @ p                  # p_k <- A p_{k-1}
    p = N * p / (e @ p)        # keep e^T p = N
print(p.round(4))

5. 真实搜索引擎中的 PageRank

PageRank 小结：

  • 预处理：给定链接图，构建一个（稀疏）链接矩阵，并由它计算 PageRank。
  • 在查询处理（查询时）中加入 PR 的一种方式：检索出满足查询的页面，并按它们的 PageRank 排序。但这一排序与查询无关……

现实情况：

  • PageRank 被 Google 等搜索引擎使用，但它远非排序的全部故事。它只是相关性打分中众多标准之一；还使用了许多其他复杂特征，其中一些针对特定的查询类别，而机器学习排序的使用也越来越多。
  • 对于一个查询，真实的搜索引擎会为每个网页计算一个综合分数，它结合了数百个特征（余弦相似度、词项邻近度、PageRank、HITS 等），即 检索模型 中的聚合分数。
  • 单独使用 PageRank，对于爬取策略（网络爬虫）等工作仍然非常有用。
