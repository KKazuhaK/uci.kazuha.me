## 1. 排序基础

### 1.1 为什么要学习排序

1. **实用价值。** 排序无处不在：按价格、姓氏、尺寸、日期或邮编排序。用户界面、数据库查询和数据展示都以它为基础。
2. **基准。** 它是在完全相同的问题上比较不同算法性能的好办法，而且有些排序策略与特定的数据结构紧密相关。
3. **解题工具。** 先对数据排序往往是个好的起点，因为它改变了接下来能做的事：例如，有序数组可以使用二分查找。

排序算法有很多：自适应堆排序、双调排序（高度并行，在 GPU 上很流行）、块排序、冒泡排序、桶排序、级联归并排序、鸡尾酒排序、梳排序、flashsort、侏儒排序、**堆排序**、**插入排序**、库排序、**归并排序**、奇偶排序、煎饼排序、**快速排序**、基数排序、**选择排序**、希尔排序、意大利面排序、树排序，等等。加粗的算法会在本章中展开。

### 1.2 键、比较与交换

- **排序**把一个集合中的 n 个元素按非递减顺序排列，可以是数值顺序，也可以是字母顺序。
- 当一个元素有多个分量时，**键**就是我们用来排序的那个分量，它决定元素之间的相对次序。例如，一本书可以按书名、按作者（都是字母序）或按 ISBN（数值）排序。

本章的每个算法都只通过两种抽象操作来访问数据：

- **比较**：`v` 是否小于 `w`？在 C++ 中，这是 `operator<`（可为你的类型重载），或者一个自定义的比较函数。
- **交换**：交换 `a[i]` 与 `a[j]`。

```cpp
T temp = a[i];      // manual swap
a[i] = a[j];
a[j] = temp;

std::swap(a[i], a[j]);   // standard library (#include <utility>)
```

本章所有排序函数共享同一种签名风格：一个以元素类型 `T` 为参数的函数模板，接收指向首元素的指针和元素个数，即 `void xSort(T* a, int n)`，并且只用 `operator<` 把 `a[0..n-1]` 排成升序。递归辅助函数接收闭区间的索引范围 `lo..hi`。

### 1.3 代价模型与内存

**代价模型。** 我们计数**比较与交换**的次数。对于不做交换的算法，计数数组访问次数。并非所有排序都基于比较：例如，基数排序从不比较两个键。

**内存。** 额外的内存与运行时间同样重要。

| 类别 | 额外内存 |
|---|---|
| **原地** | 相对于被排序的元素，只需常数或对数级的额外内存 |
| **非原地** | 线性的额外内存，与输入规模成正比 |

### 1.4 稳定性

如果键相等的元素在输出中保持输入时的相对次序，这种排序就是**稳定**的。例子：按点数对扑克牌排序，输入为 7♠ 5♥ 2♥ 5♠。稳定排序给出 2♥ **5♥ 5♠** 7♠（5♥ 原本在前，所以仍然在前）。不稳定排序则可能给出 2♥ **5♠ 5♥** 7♠。

> 📘 **延伸阅读**：Thornton，*Comparison-Based Sorting*：稳定性让你能够依次按多个键排序。先按名字排序人员，再**稳定地**按姓氏排序。结果按姓氏有序，同姓的人仍然按名字有序。如果第二次排序不稳定，同姓者之间的名字次序就可能被打乱。

## 2. 选择排序

### 2.1 思路与代码

把数组分成**左侧的有序子数组**和**右侧的无序子数组**。重复以下步骤：

- 在无序部分中找到**最小**的元素，
- 把它与**最左侧的无序**元素交换，
- 把边界向右移动一个元素。

```cpp
template <typename T>
void selectionSort(T* a, int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;                          // index of the smallest remaining item
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[min]) {
                min = j;
            }
        }
        std::swap(a[i], a[min]);
    }
}
```

**不变式。** 第 i 轮结束时：

- `a[0…i]` 按升序排列，并且
- `a[i+1…n−1]` 中没有任何元素小于 `a[0…i]` 中的任何元素。

因此第 i 轮结束后，`a[0…i]` 保存了这些位置的最终值，之后再也不会被改动。最后一个元素会自动就位，这就是外层循环在 `n − 1` 处停止的原因。

在数组 `3 44 38 5 47 1 36 26`（→ `1 3 5 26 36 38 44 47`）上一步步演示：

```viz selection-sort

```

### 2.2 分析

- **比较次数：** 第 i 轮扫描 n − 1 − i 个元素，总数为 (n−1) + (n−2) + … + 1 = n(n−1)/2 ≈ n²/2，即 **O(n²)**。对每种输入都一样，因为扫描无法提前停止。
- **交换次数：** 每轮一次，共 n − 1 次，即 **O(n)**（代码在 `min == i` 时也会"交换"）。
- **是否已排序？** 仍然需要 n(n−1)/2 次比较，所以仍是 O(n²)。选择排序察觉不到数据已经有序。
- **原地：** 是，额外只用到 `i`、`j` 和 `min`。
- **稳定：** 否。远距离的交换可能让一个元素越过与它相等的元素。例子：`5♥ 5♠ 2♥`。第 0 轮把 2♥ 与 5♥ 交换，得到 `2♥ 5♠ 5♥`，两张 5 的次序就颠倒了。

在 n = 1000 上的计数器验证了这些公式（1000·999/2 = 499,500）；实测计数见[第 4 节](#4-选择排序与插入排序对比)。

> 📘 **延伸阅读**：由于选择排序至多只做 n − 1 次交换，当**移动**元素的代价远高于比较时，它是首选。algs4 的例子是一位仓库管理员，通过读取标签来重新码放沉重的箱子。（algs4 §2.1）

## 3. 插入排序

### 3.1 思路与代码

保持一个*部分有序*的子数组在左侧，未排序的子数组在右侧。重复：

- 取未排序部分的下一个元素，
- 找到它在有序部分中应处的位置并插入，
- 把边界向右移动一个元素。

大多数人整理手中的扑克牌就是这样做的。与选择排序不同，左侧部分只是*相对于自身*有序：后面的元素仍然可以插入其中。

```cpp
template <typename T>
void insertionSort(T* a, int n) {
    for (int i = 1; i < n; i++) {
        for (int j = i; j > 0; j--) {         // move a[i] left past larger items
            if (a[j] < a[j - 1]) {
                std::swap(a[j], a[j - 1]);
            }
            else break;                       // everything further left is smaller
        }
    }
}
```

内层循环把 `a[j]` **持续向左交换，越过每一个比它大的元素**。遇到第一个不比它大的邻元素时，它就 **break**：更靠左的所有元素都更小，因此该元素已经处于正确位置。这个提前退出正是它与选择排序的全部区别。（外层循环从 1 开始，因为只含一个元素的前缀本身就是有序的。）

在同一数组上一步步演示：

```viz insertion-sort
{"title": "对 3 44 38 5 47 1 36 26 进行插入排序", "array": [3, 44, 38, 5, 47, 1, 36, 26], "interactive": true}
```

### 3.2 分析

| 输入 | 比较次数 | 交换次数 | 大 O |
|---|---|---|---|
| **最好**：已排序 | n − 1（每轮：一次比较，然后 break） | 0 | **O(n)** |
| **最坏**：逆序 | n(n−1)/2（每个元素都要一路移到最前面） | n(n−1)/2 | **O(n²)** |
| 平均（随机） | ≈ n²/4 | ≈ n²/4 | O(n²) |

在 n = 1000 时，计数器给出：已排序输入为 999 次比较、0 次交换；逆序输入则各为 499,500 次比较和交换（见[第 4 节](#4-选择排序与插入排序对比)）。

- **原地：** 是。
- **稳定：** 是。它只在 `a[j] < a[j-1]`（严格小于）时才交换，因此元素永远不会越过与它相等的元素。把扑克牌 7♠ 5♥ 2♥ 5♠ 按点数排序，得到 `2H 5H 5S 7S`：5♥ 仍在 5♠ 之前。

> 📘 **延伸阅读**：插入排序所做的交换次数恰好等于**逆序对**的数量，即顺序错误的元素对。因此在*部分有序*的数组上（逆序对很少，例如在一个有序列表后面附加了几个新元素），插入排序几乎是线性时间。这就是它常用于小规模或近乎有序输入的原因。（algs4 §2.1）

## 4. 选择排序与插入排序对比

| | 选择排序 | 插入排序 |
|---|---|---|
| 比较次数，最坏 | n(n−1)/2 → O(n²) | n(n−1)/2 → O(n²)（逆序） |
| 比较次数，最好 | n(n−1)/2 → O(n²)（始终如此） | n − 1 → O(n)（已排序） |
| 交换次数 | n − 1 → O(n)，始终如此 | 0（最好）到 n(n−1)/2（最坏） |
| 原地 | 是 | 是 |
| 稳定 | **否**（远距离交换） | **是**（只交换相邻且严格更小的元素） |
| 优势 | 交换次数最少 | 对已排序或近乎有序的数据很快 |

> 💡 **关键洞见**：两者在最坏情况下都是 O(n²)。选择排序**每次**都要付出 n²/2 次比较。插入排序只为实际存在的无序付出代价。

下面是用[第 9 节](#9-完整实现)的程序在 n = 1000 个元素上测得的比较与交换次数：

```text
sorted   selection cmps=499500 swaps=999
sorted   insertion cmps=999 swaps=0
reversed selection cmps=499500 swaps=999
reversed insertion cmps=499500 swaps=499500
```

这些结果与公式完全吻合。实际墙钟时间见[第 8.2 节](#82-实测运行时间)：在 64,000 个随机整数上，这个基于交换的插入排序比选择排序慢约 9 倍（每一步都是一次有依赖的交换，而不是廉价的比较，因此看起来同为 O(n²) 的代价，其常数差别很大）；而在已排序的输入上，它快约 20,000 倍。

## 5. 归并排序

### 5.1 基本思想

归并排序由 John von Neumann 于 1945 年发明，它是"分治法的典型范例"。算法如下：

1. **划分**：把数组分成两半。
2. **递归排序**每一半。
3. **归并**两个有序的半部分。

在 `M E R G E S O R T E X A M P L E` 上的概览：

| 步骤 | 数组 |
| --- | --- |
| 输入 | M E R G E S O R T E X A M P L E |
| 排序左半部分 | E E G M O R R S \| T E X A M P L E |
| 排序右半部分 | E E G M O R R S \| A E E L M P T X |
| 合并结果 | A E E E E G L M M O P R R S T X |

> 💡 **关键洞见**：划分是平凡的（在中间下标处切开）。所有真正的工作，即每一次比较，都发生在 `merge()` 中。

### 5.2 归并两个有序的半部分

`merge` 接收 `a[lo..mid]` 和 `a[mid+1..hi]`，它们**各自已经有序**，并使 `a[lo..hi]` 变为有序。它先把该范围复制到辅助数组 `aux` 中，然后按位置 `k` 逐个写回 `a`：

```cpp
template <typename T>
void merge(T* a, T* aux, int lo, int mid, int hi) {
    for (int k = lo; k <= hi; k++)            // copy a to aux
        aux[k] = a[k];

    int i = lo, j = mid + 1;
    for (int k = lo; k <= hi; k++) {          // merge back into a
        if (i > mid)                          // left half exhausted
            a[k] = aux[j++];
        else if (j > hi)                      // right half exhausted
            a[k] = aux[i++];
        else if (aux[j] < aux[i])             // right item is strictly smaller
            a[k] = aux[j++];
        else                                  // left item (ties go left)
            a[k] = aux[i++];
    }
}
```

各索引的含义如下：

- `i` = `aux` 中左半部分的下一个未用元素（当 `i <= mid` 时有效）
- `j` = `aux` 中右半部分的下一个未用元素（当 `j <= hi` 时有效）
- `k` = `a` 中下一个待填入的位置

`i > mid` 表示左半部分已经用完，`j > hi` 表示右半部分已经用完；此时剩下的元素直接复制，无需比较。只有当两半都还有元素时，第三个分支才比较 `aux[j] < aux[i]`，较小者胜出。可以想象两叠已排序的扑克牌面朝上摆放：总是取较小的那张顶牌。

归并 `aux = A G L O R | H I M S T`（lo = 0，mid = 4，hi = 9）：

| k | 情况 | 赋值 | 赋值后的 a |
| --- | --- | --- | --- |
| 0 | aux[i] < aux[j]（A 对 H） | a[0] = aux[0] | **A** |
| 1 | G 对 H | a[1] = aux[1] | A **G** |
| 2 | aux[i] > aux[j]（L 对 H） | a[2] = aux[5] | A G **H** |
| 3 | L 对 I | a[3] = aux[6] | A G H **I** |
| 4 | L 对 M | a[4] = aux[2] | … **L** |
| 5 | O 对 M | a[5] = aux[7] | … **M** |
| 6 | O 对 S | a[6] = aux[3] | … **O** |
| 7 | R 对 S | a[7] = aux[4] | … **R** |
| 8 | i > mid | a[8] = aux[8] | … **S** |
| 9 | i > mid | a[9] = aux[9] | A G H I L M O R S T |

在下面一步步演示（聚焦演示区后，← / → 键可用）：

```viz merge-sort
{"title": "合并 A G L O R | H I M S T", "items": "A, G, L, O, R, H, I, M, S, T", "mode": "merge", "mid": 4}
```

> ⚠️ **易错点**：`merge` 只有在两半都已有序时才正确。它从不回头检查，因此一个未排序的半部分会按原来的顺序，混在另一半中间输出。

### 5.3 递归排序与包装函数

```cpp
template <typename T>
void mergeSort(T* a, T* aux, int lo, int hi) {
    if (hi <= lo) return;                     // 0 or 1 items: already sorted
    int mid = lo + (hi - lo) / 2;
    mergeSort(a, aux, lo, mid);
    mergeSort(a, aux, mid + 1, hi);
    merge(a, aux, lo, mid, hi);
}

template <typename T>
void mergeSort(T* a, int n) {
    T* aux = new T[n];                        // allocated once
    mergeSort(a, aux, 0, n - 1);
    delete[] aux;
}
```

- `lo` 和 `hi` 都是**闭区间**，所以包装函数传入 `n - 1`。
- 基本情形 `hi <= lo`：含 0 或 1 个元素的范围本身就是有序的。
- `mid = lo + (hi - lo) / 2` 与 `(lo + hi) / 2` 相等，但不会使 `int` 溢出。长度为奇数时，左半部分 `lo..mid` 多出一个元素。
- 两个 `mergeSort` 函数是**重载**。用户调用 `mergeSort(a, n)`；包装函数只分配一次 `aux` 并把它向下传递，而不是在每次 `merge` 中分配。
- `new T[n]` 要与 `delete[]` 配对。

`std::sort` 和 `std::merge` 已经在 `<algorithm>` 中；我们自己实现它们是为了理解其原理。

### 5.4 跟踪归并排序

在 `[M,E,R,G,E,S,R,T]` 上跟踪 `mergeSort`。调用顺序是**深度优先**的：一直向左走，直到遇到基本情形（想象一堵砖墙），然后处理右边，最后在回溯时归并。

| 调用 | 发生的事情 | 之后的 a |
| --- | --- | --- |
| mergeSort(0,7) | mid = 3，先走左边 | M E R G E S R T |
| mergeSort(0,3) | mid = 1，先走左边 | |
| mergeSort(0,1) | mid = 0；mergeSort(0,0) 与 mergeSort(1,1) 命中基本情形；merge(0,0,1) | **E M** R G E S R T |
| mergeSort(2,3) | mergeSort(2,2)、mergeSort(3,3) 返回；merge(2,2,3) | E M **G R** E S R T |
| 回到 mergeSort(0,3) | merge(0,1,3) | **E G M R** E S R T |
| mergeSort(4,7) | 对 E S R T 重复同样的模式 | E G M R **E R S T** |
| 回到 mergeSort(0,7) | merge(0,3,7) | **E E G M R R S T** |

整棵递归树为：`MERG | ESRT` → `ME RG ES RT` → 单个字母 → `EM GR ES RT` → `EGMR ERST` → `EEGMRRST`。`aux` 数组会保留归并之间的旧副本（例如 `[M, E, R, G, , , , ]`）；这无害，因为每次 `merge` 都会先复制它自己的范围。

### 5.5 归并排序的分析

**为什么重要：** 下表比较了插入排序（约 n² 次比较）与归并排序（约 n lg n 次比较），假设一台每秒约做 10⁸ 次比较的笔记本电脑，以及一台每秒约做 10¹² 次比较的超级计算机（algs4 §2.2，粗略估计）：

| 计算机 | 插入排序：千 | 百万 | 十亿 | 归并排序：千 | 百万 | 十亿 |
| --- | --- | --- | --- | --- | --- | --- |
| 笔记本电脑 | 瞬间 | 2 小时 | 300 年 | 瞬间 | 1 秒 | 15 分钟 |
| 超级计算机 | 瞬间 | 1 秒 | 1 周 | 瞬间 | 瞬间 | 瞬间 |

笔记本电脑运行归并排序，胜过超级计算机运行插入排序：好的算法胜过超级计算机。

**计数比较次数。** 一次 n 个元素的 `merge` 至多做 **n − 1** 次比较：每次比较放入一个元素，而最后一个元素总是无需比较就能放入（另一半已经空了）。因此最坏情况的计数满足

$$C(n) = 2\,C(n/2) + (n - 1), \qquad C(1) = 0$$

（两次递归排序，加上最后的一次归并；计算 `mid` 不需要比较）。若只看增长阶，则写作 $T(n) = 2T(n/2) + n$。

- **递归树**：第 k 层有 2ᵏ 个子问题，每个规模为 n/2ᵏ，因此每一层共归并 n 个元素。把 n 不断减半直到 1 需要 log₂ n 层。总计约为 n · log₂ n。准确地说，当 n 为 2 的幂时 $C(n) = n\log_2 n - n + 1$（n = 8 → 17）。
- **主定理**（$T(n) = aT(n/b) + n^d$）：a = 2，b = 2，d = 1，且 a = bᵈ，因此 $T(n) = \Theta(n^d \log n) = \Theta(n \log n)$。（参见[算法分析](topic-analysis.zh-CN.md)。）

把所有工作（复制到 `aux`、更新索引）都计入，而不只计数比较，只会改变常数：每次 `merge` 仍是 Θ(n)，因此在最好、平均和最坏情况下，答案都是 **Θ(n log n)**。

把两个各为 n/2 的有序半部分归并，比较次数在约 n/2（一半先用完，例如 `1 2 3 | 4 5 6` → 3 次）与 n − 1（两半交错，例如 `1 3 5 | 2 4 6` → 5 次）之间。[第 9 节](#9-完整实现)的程序恰好计数了这些：第 5.2 节 10 元素的归并做了 8 次比较，`M E R G E S R T` 的整个排序做了 15 次，8 元素的最坏情况输入做了 17 次。

> 📘 **延伸阅读**：algs4 §2.2 给出了完整的范围：对于任意规模 n 的输入，归并排序的比较次数在 ½ n lg n 与 n lg n 之间。最好情况恰好是最坏情况的一半，因为一次归并至少需要 n/2 次比较（一半先用完）。

### 5.6 性质

- **额外内存与 n 成正比**：最后一次归并需要 `aux` 容纳 n 个元素。
- **非原地**（以其最简单的形式）。有些改进可以把辅助数组减半，但真正的原地归并非常困难。
- **稳定**：相等的键保持原有次序。在 `merge` 中，只有 `aux[j] < aux[i]` 时才取右边的元素；相等时走 `else` 分支，取**左边**的元素，它原本就在前面。

> ⚠️ **易错点**：如果把打破平局的条件改成 `aux[j] <= aux[i]`，归并排序就不再稳定了（右边相等的元素会跳到前面）。

### 5.7 改进

1. 对小的子数组使用**插入排序**。
2. **提前停止**：如果两半已经有序，就跳过 `merge`。
3. **消除**复制到辅助数组的操作，以节省时间。

> 📘 **延伸阅读**：这三项改进具体意味着什么（algs4 §2.2）：(1) 在约 10–15 个元素以下切换到插入排序，可以使典型的归并排序提速 10–15%；(2) 当 `a[mid] <= a[mid+1]` 时跳过 `merge`，这使已排序的输入变为线性；(3) 在每一层递归中交替 `a` 与 `aux` 的角色，节省复制的时间（但不节省空间）。

改进 1 和 2 直接放进递归辅助函数中。它与[第 5.3 节](#53-递归排序与包装函数)是同一算法，只多了一个 `cutoff` 参数（值 ≤ 0 时关闭插入排序截断）。小范围情形对指针 `a + lo` 调用 `insertionSort`，因此它恰好排序 `a[lo..hi]`：

```cpp
template <typename T>
void mergeSortOptimized(T* a, T* aux, int lo, int hi, int cutoff) {
    if (hi <= lo) return;
    if (cutoff > 0 && hi - lo + 1 <= cutoff) {
        insertionSort(a + lo, hi - lo + 1);   // sorts exactly a[lo..hi]
        return;
    }
    int mid = lo + (hi - lo) / 2;
    mergeSortOptimized(a, aux, lo, mid, cutoff);
    mergeSortOptimized(a, aux, mid + 1, hi, cutoff);
    if (!(a[mid + 1] < a[mid])) return;       // halves already in order
    merge(a, aux, lo, mid, hi);
}

template <typename T>
void mergeSortOptimized(T* a, int n, int cutoff = -1) {   // cutoff <= 0: off
    T* aux = new T[n];
    mergeSortOptimized(a, aux, 0, n - 1, cutoff);
    delete[] aux;
}
```

- 跳过判断写作 `!(a[mid + 1] < a[mid])`（等价于 `a[mid] <= a[mid + 1]`），这样只需要 `operator<`。
- **跳过检查**：对已排序的输入，每次 `merge` 都被跳过，因此整个排序的代价为 T(n) = 2T(n/2) + 1 = **Θ(n)**（n − 1 次比较；第 9 节的程序对 n = 1000 计数为 999 次，而没有该检查时为 5,044 次）。这两项改动都不会让相等的键越过彼此，所以排序仍然**稳定**。
- **实测**（单台机器，g++ -O2，64,000 个整数；绝对时间随机器和实现而变）：随机输入，无截断时 6.5 ms，截断值 32 时 8.6 ms，截断值 64 时 12.0 ms；已排序输入则为 0.34 ms 对 0.08 ms。在 2²⁰ 个随机整数上的另一项基准测试（取 5 次中的最佳值）：无截断 128 ms，截断值 8 → 130，16 → 140，32 → 169，64 → 221。因此，对这种基于交换的插入排序，截断只在（近乎）有序的数据上才有收益，而 32 和 64 远高于 algs4 建议的 10–15 左右。完整表格见[第 8.2 节](#82-实测运行时间)。

> ⚠️ **易错点**：当小范围插入排序直接写在 `a[lo..hi]` 上时，它的内层循环必须在 `j > lo` 处停止，而不是 `j > 0`。若用 `j > 0`，它会继续与相邻的、递归尚未完成的子数组交换。像上面那样调用 `insertionSort(a + lo, …)` 可以避免这个问题。

### 5.8 去掉耗尽检查的归并

更快的 `merge` 去掉了前两个判断，即 `i > mid` 与 `j > hi`（algs4 习题 2.2.10，"更快的归并"）。技巧在于：把右半部分**逆序**复制到 `aux` 中。这样 `aux[lo..hi]` 先沿左半部分上升，再沿右半部分下降，并且两半各自的最大元素都紧挨着中间。当某一半用完时，它的指针会落在另一半的**最大**元素上，而这个元素不小于任何仍在等待的元素，因此它充当哨兵，不需要边界检查。从两端归并：`i` 从 `lo` 向右移动，`j` 从 `hi` 向左移动。

```cpp
template <typename T>
void mergeNoChecks(T* a, T* aux, int lo, int mid, int hi) {
    for (int k = lo; k <= mid; k++)
        aux[k] = a[k];
    for (int k = mid + 1; k <= hi; k++)
        aux[k] = a[hi + mid + 1 - k];

    int i = lo, j = hi;
    for (int k = lo; k <= hi; k++) {
        if (aux[j] < aux[i])
            a[k] = aux[j--];
        else
            a[k] = aux[i++];
    }
}
```

以[第 5.2 节](#52-归并两个有序的半部分)的两半为例：`A G L O R | H I M S T` 被复制为 `aux = A G L O R T S M I H`。归并依次取出 A、G（左）、H、I（右，从末尾开始）……在 R 之后，左指针移到 T 上，因此 S 和 T 无需任何 `i > mid` 检查就能按序输出。

- 下标检查：`k = mid + 1` 复制 `a[hi]`，`k = hi` 复制 `a[mid + 1]`，因此第二个循环恰好把右半部分逆序。
- 代价：每一步只需一次比较（而不是至多三次），每次归并仍是 Θ(n)，整体为 **Θ(n log n)**。在 2²⁰ 个随机整数上实测（取 5 次中的最佳值）：118 ms 对 128 ms（约快 8%）。
- **不稳定。** 左半部分用完后，`i` 会走进逆序的右半部分；相等时 `else` 分支取 `aux[i]`，即**较晚**出现的元素。例子：`(1a) | (2b 2c)` → `aux = 1a 2c 2b` → 结果 `1a 2c 2b`（第 9 节的程序会打印这一结果）。因此，必须保持稳定的归并应使用[第 5.2 节](#52-归并两个有序的半部分)的四分支版本。

> ⚠️ **易错点**：这个版本有两个容易犯的错误。第一，复制循环必须从 `lo` 开始，而不是 `0`（从 0 开始复制会使每次归并的代价变为 O(hi)，整个排序变为 O(n²)）。第二，左指针向前移动（`aux[i++]`）；只有 `j` 向下计数。

## 6. 快速排序

### 6.1 基本思想

快速排序同样是分治算法，由 Sir Tony Hoare 于 1959 年发明。他想在字典中查单词之前先把单词排好序，想出了快速排序却不知道如何实现它；后来他学习了 Algol 60 和递归，才把它实现出来。他因此获得了 1980 年的图灵奖（他还发明了 null，而他为此深感后悔）。

与归并排序不同，工作发生在递归**之前**，而不是之后：

1. **打乱**数组（随机地）。
2. **划分**，使得对于某个主元下标 `j`：
   - 元素 `a[j]` 位于其最终位置，
   - `j` 左侧没有更大的元素，
   - `j` 右侧没有更小的元素。
3. **递归排序**每个子数组。没有合并步骤：两侧都有序之后，整个数组就有序了。

| | 划分前 | 划分后 |
|---|---|---|
| 布局 | `v`（主元在 `lo`），然后是直到 `hi` 的未知元素 | `≤ v` … `v`（在 `j` 处）… `≥ v` |

递归驱动函数，以及公共入口（`partition` 将在下一节展开）：

```cpp
template <typename T>
void quickSort(T* a, int lo, int hi) {
    if (hi <= lo) return;
    int j = partition(a, lo, hi);
    quickSort(a, lo, j - 1);
    quickSort(a, j + 1, hi);
}

template <typename T>
void quickSort(T* a, int n) {
    std::random_device device;                // shuffle first: probabilistic guarantee
    std::default_random_engine engine{device()};
    std::shuffle(a, a + n, engine);
    quickSort(a, 0, n - 1);
}
```

示例（algs4 §2.3）：输入 `Q U I C K S O R T E X A M P L E` → 打乱 → `K R A T E L E P U I M Q C X O S` → 以 `K` 划分 → `E C A I E K L P U T M Q R X O S` → 排序左侧 → 排序右侧 → `A C E E I K L M O P Q R S T U X`。

> ⚠️ **易错点**：`std::shuffle` 接收迭代器范围，位于 `<algorithm>` 中。对于裸指针，传入 `a, a + n`；在 `T*` 上使用 `std::begin(a)` / `std::end(a)` 无法编译（它们需要数组或容器），而忘记 `#include <algorithm>` 则是另一个常见的编译错误。

> 💡 **关键洞见**：归并排序 = 平凡的划分 + 困难的合并。快速排序 = 困难的划分 + 平凡的合并。每次划分都把**一个**元素（主元）放到其最终位置，这就是递归总会终止的原因：每个子数组都严格更小。

### 6.2 划分

目标：重排 `a[lo..hi]`，使得 `a[lo..j-1] <= a[j] <= a[j+1..hi]`。

- 主元 `v` 取 `a[lo]`（最简单的选择）。指针 `i` 从 `lo` 开始，`j` 从 `hi + 1` 开始。
- 重复，直到 `i` 与 `j` 交错：
  - 从左到右扫描 `i`，**只要 `a[i] < v`** 就继续（在遇到一个 **≥** 主元的键时停止）；
  - 从右到左扫描 `j`，**只要 `v < a[j]`** 就继续（在遇到一个 **≤** 主元的键时停止）；
  - 若 `i >= j`，跳出循环；
  - 交换 `a[i]` 与 `a[j]`。
- 最后交换 `a[lo]` 与 `a[j]`，并返回 `j`。

为什么要与 `a[j]` 交换，而不是 `a[i]`？当两个扫描交错时，`j` 位于 `≤ v` 区域的最后一个元素上，因此把主元换到那里，能保证它左边的元素都 `≤ v`。

```cpp
template <typename T>
int partition(T* a, int lo, int hi) {
    int i = lo;
    int j = hi + 1;
    T v = a[lo];
    while (true) {
        while (i < hi && a[++i] < v) {        // stop at a key >= v
            if (i == hi) break;
        }
        while (v < a[--j]) {                  // stop at a key <= v
            if (j == lo) break;
        }
        if (i >= j) break;                    // pointers crossed
        std::swap(a[i], a[j]);
    }
    std::swap(a[lo], a[j]);                   // pivot to its final place
    return j;
}
```

`i == hi` 与 `j == lo` 这两个守卫，使得当主元是最大或最小的键时，扫描仍留在子数组之内。（`j == lo` 的守卫其实是多余的，因为 `a[lo]` 就是 `v` 本身，而 `v < v` 为假，但它无害。）

> ⚠️ **易错点**：前置自增很关键。`a[++i]` 先移动再比较，因此 `i` 看的第一个元素是 `a[lo+1]`（主元被跳过）。同样，`a[--j]` 从 `a[hi]` 开始，因为 `j` 的初始值是 `hi + 1`。

> 📘 **延伸阅读**：两个扫描都在遇到**等于主元的键**时停止（用的是 `<`，而不是 `<=`）。这看起来会引起无用的交换，但它正是快速排序在含大量重复元素的数组上保持高效的原因：当所有键都相等时，停止让 `i` 和 `j` 在中间相遇，得到均匀的划分，代价为 n log n；而不停止则会让一个指针一直走到末端，得到 0 / n−1 的划分，代价为平方级（algs4 §2.3）。

### 6.3 跟踪一次划分

对打乱后的数组 `K R A T E L E P U I M Q C X O S` 以 `v = K` 进行第一次划分：

### 6.5 分析：最坏、最好、平均

对 `n` 个元素做一次 `partition` 的代价是 **O(n)**：`i` 与 `j` 一起把子数组扫一遍（约 n + 1 次比较）。因此一切都取决于**主元落在哪里**。

| 情况 | 场景 | 递推式 | 解 |
| --- | --- | --- | --- |
| 最坏 | 主元总是最小或最大的键 → 划分为 0 和 n−1（例如未经打乱的已排序或逆序输入） | T(n) = T(n−1) + n | n + (n−1) + … + 2 ≈ n²/2 → **O(n²)** |
| 最好 | 主元总是中位数 → 两半 | T(n) = 2T(n/2) + n | lg n 层 × 每层 n 的工作 → **O(n log n)** |
| 平均 | 随机打乱 → 主元的秩均匀随机 | — | **O(n log n)** |

用上面的代码实测（不打乱，规模为 n 的已排序输入）：n = 100 → 5,148 次比较，n = 200 → 20,298，n = 400 → 80,598：约为 n²/2，n 每翻一倍，比较次数约增至四倍。同样大小为 1,000 的已排序输入，经过打乱后，在[第 9 节](#9-完整实现)的运行中做了 11,992 次比较（约 12,000）。

什么能降低最坏情况出现的可能？是开头的**随机打乱**：不再有任何固定的输入（已排序、逆序等）会变坏，只有不走运的随机选择才会；而对于较大的 n，这种情况极不可能发生。这就是所谓的"概率保证"。

> 📘 **延伸阅读**：平均情况大约是 **2n ln n ≈ 1.39 n lg n** 次比较（algs4 §2.3），而归并排序至多约 n lg n 次。这个比值，就是"比归并排序多 39% 的比较"一说的由来。

### 6.6 性质

- **比归并排序多 39% 的比较，但实际上更快。** 原因：
  - 数据移动更少（归并排序在每一层都要把每个元素复制到 `aux` 再复制回来）；
  - 缓存性能好：划分顺序扫描内存，与预取配合得很好；
  - 无需额外的内存分配。
- **随机打乱**提供了针对最坏情况的概率保证。
- 平均 O(n log n)，最坏 O(n²)。
- **原地**：只在数组内部交换（外加递归栈）。
- **不稳定**：远距离交换可能使相等的键重新排序。下面练习中的例子：以 `5 8 7 9 5 4` 中的第一个 `5` 为主元进行划分，最后一步的 `swap(a[lo], a[j])` 交换的正是两个 `5`。

快速排序的性能表明，大 O 是描述现实世界性能的一个**不完整的模型**：在 n log n 类排序中，它的最坏情况大 O 最差，但它依然是最快的。

### 6.7 改进：主元选择与截止值

1. **对小的子数组使用插入排序**：在极小的子数组上，递归开销占主导，而插入排序在这里很快（与归并排序相同的技巧，见[第 5.7 节](#57-改进)）。
2. **改进主元选择**（并去掉开头的随机打乱）：
   - 使用**随机元素**作为主元（把它换到 `a[lo]`，然后照常划分）；
   - 使用**小样本的中位数**作为主元，平均而言划分更均衡。

> 📘 **延伸阅读**：algs4 建议切换到插入排序的截止值大约在 5 到 15 个元素之间，并指出取 **3** 个样本（三数取中）就能获得样本中位数的大部分好处。

在代码中，主元规则是一个参数（`First` 即朴素的 `a[lo]`），`choosePivot` 在每次 `partition` 之前运行。它选中的元素会被**交换到 `a[lo]`**，因此 `partition` 仍然是[第 6.2 节](#62-划分)的代码（主元 `v = a[lo]`）。无需在开头打乱：

```cpp
enum class Pivot { First, Median, Random };

// Move the chosen pivot into a[lo], where partition expects it.
template <typename T>
void choosePivot(T* a, int lo, int hi, Pivot rule, std::mt19937& rng) {
    if (rule == Pivot::Median) {              // median of a[lo], a[mid], a[hi]
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < a[lo]) std::swap(a[lo], a[mid]);
        if (a[hi] < a[lo])  std::swap(a[lo], a[hi]);
        if (a[hi] < a[mid]) std::swap(a[mid], a[hi]);
        std::swap(a[lo], a[mid]);
    }
    else if (rule == Pivot::Random) {         // any index in [lo, hi]
        std::uniform_int_distribution<int> dist{lo, hi};
        std::swap(a[lo], a[dist(rng)]);
    }
}

template <typename T>
void quickSort(T* a, int lo, int hi, Pivot rule, std::mt19937& rng, int cutoff = 0) {
    if (hi <= lo) return;
    if (cutoff > 0 && hi - lo + 1 <= cutoff) {
        insertionSort(a + lo, hi - lo + 1);
        return;
    }
    choosePivot(a, lo, hi, rule, rng);
    int j = partition(a, lo, hi);
    quickSort(a, lo, j - 1, rule, rng, cutoff);
    quickSort(a, j + 1, hi, rule, rng, cutoff);
}
```

- 经过三次比较-交换之后，`a[lo] <= a[mid] <= a[hi]`，因此 `a[mid]` 就是三者的中位数；最后一次交换把它移到 `lo`。
- `rng` 由调用者创建一次（`std::mt19937 rng{std::random_device{}()};`）。在每次调用时都创建 `random_device` 很慢。
- **为什么这很重要：已排序的输入。** 使用 `First` 时，主元每次都是最小的键，因此每次划分都是 0 / n−1：约 n²/2 次比较，递归深度为 n（足够深的输入会耗尽栈空间）。三数取中在已排序的区间上选出真正的中间值，因此最高层的划分是完美的，其下各层也接近完美；随机主元则提供了原本由打乱带来的、概率意义上的 n log n 保证。对于一个 3,000 个元素的已排序输入，第 9 节的程序计数：`First` 为 4,504,498 次比较，`Median` 为 38,797 次，`Random` 为 43,880 次。

> ⚠️ **易错点**：`choosePivot` 必须把主元**留在 `a[lo]`**，因为 `partition` 依赖于此。如果返回了主元的值，却让它留在 `mid`（或随机下标）处，划分就会围绕错误的元素进行。

> 📘 **延伸阅读**：[归并排序](https://www.youtube.com/watch?v=XaqR3G_NVoo)与[快速排序](https://www.youtube.com/watch?v=3San3uKKHgg)都有动画"舞蹈"视频；快速排序的舞蹈（与 VisuAlgo 的实现一样）使用的是与本章**不同的划分变体**，因此不要用它们来核对由本章 `partition` 生成的追踪。

## 7. 堆排序

### 7.1 计划

用堆（[堆与优先队列](topic-heaps.zh-CN.md)）分两步排序：

1. **堆构建**：用全部 n 个待排序的键构建一个二叉最大堆；
2. **排空（sortdown）**：反复删除并返回最大的键。

例子：由 9 个键 1, 2, 3, 7, 17, 19, 25, 36, 100 构建的最大堆，经过九次删除最大值的操作，依次返回 `100 36 25 19 17 7 3 2 1`，即按降序排列。由于每个被删除的最大值都被交换到缩小后的堆之后的位置上，数组本身最终按升序排列：`1 2 3 7 17 19 25 36 100`。这种原地技巧就是排空（[第 7.6 节](#76-排空sortdown)）。

堆的位置从 1 到 n 编号（根在位置 1，`k` 的子节点为 `2k` 和 `2k + 1`，父节点为 ⌊k/2⌋），并且**位置 k 存放在 `a[k - 1]` 中**，因此排序符合本章的 `T* a, int n` 签名，对 `a[0..n-1]` 排序。辅助函数 `swim(a, k)`（上浮）与 `sink(a, k, n)`（下沉）作用于位置上；它们就是[堆与优先队列](topic-heaps.zh-CN.md)中的堆操作，以数组和堆的大小作为参数，因此堆排序可以作用于任何数组：

```cpp
template <typename T>
void swim(T* a, int k) {
    while (k > 1 && a[k / 2 - 1] < a[k - 1]) {
        std::swap(a[k / 2 - 1], a[k - 1]);
        k /= 2;
    }
}

template <typename T>
void sink(T* a, int k, int n) {
    while (2 * k <= n) {
        int j = 2 * k;
        if (j < n && a[j - 1] < a[j]) j++;    // the larger child
        if (!(a[k - 1] < a[j - 1])) break;    // heap order restored
        std::swap(a[k - 1], a[j - 1]);
        k = j;
    }
}
```

第二阶段总是相同的。第一阶段可以用**两种方式**完成，它们很容易混淆，因为两者最终都得到一个堆。它们的区别在于方向、所用的操作（swim 还是 sink），以及代价。下面在数组 `[2, 9, 7, 6, 5, 8]`（n = 6）上演示这两种方式。

### 7.2 方法 A：朴素的自顶向下构建

堆**从左侧生长**。起初只有位置 1 构成一个堆；每一步让下一个键加入堆的末尾，并在它大于父节点时**上浮**。这相当于原地完成 n 次 `insert`（向空堆插入不移动任何东西，因此循环从 k = 2 开始）：

```cpp
template <typename T>
void buildTopDown(T* a, int n) {              // method A: n inserts, O(n log n)
    for (int k = 2; k <= n; k++)              // positions 1..k-1 are already a heap
        swim(a, k);                           // position k joins it
}
```

| 步骤 | 新键 | 上浮 | 之后的堆 |
| --- | --- | --- | --- |
| k = 1 | 2 | —（单独一个） | 2 |
| k = 2 | 9 | 9 > 2 → 交换 | 9 2 |
| k = 3 | 7 | 7 < 9 → 留在原处 | 9 2 7 |
| k = 4 | 6 | 6 > 2 → 交换；6 < 9 → 停止 | 9 6 7 2 |
| k = 5 | 5 | 5 < 6 → 留在原处 | 9 6 7 2 5 |
| k = 6 | 8 | 8 > 7 → 交换；8 < 9 → 停止 | 9 6 8 2 5 7 |

演示把每一步写作 `insert(x)`，它与"追加 + 上浮"是同一回事：

```viz binary-heap

```

**代价：**第 k 个键至多上浮 log k 层。在最坏情况下（升序输入：每个新键都是新的最大值，并一路上浮到根），代价为 log 1 + log 2 + … + log n = **O(n log n)**。

### 7.3 方法 B：自底向上构建

把整个数组**按原样**看作一棵完全二叉树。叶子（位置 n/2+1 … n）本身已经是只含一个键的堆，因此跳过它们。从右到左遍历内部节点，对每个节点执行 **sink（下沉）**：

```cpp
template <typename T>
void buildBottomUp(T* a, int n) {             // method B: O(n)
    for (int k = n / 2; k >= 1; k--)
        sink(a, k, n);
}
```

**关键洞见：**执行完 `sink(a, k, n)` 后，以 k 为根的子树就是一个堆。从右到左下沉，意味着处理 k 时它的两个子节点都已经是堆，因此一次 sink 就能修复整棵子树；在 `sink(a, 1, n)` 之后，整个数组就是一个堆。

**为什么第一个要处理的节点是 n/2？** 节点 k 有左子节点，当且仅当 2k ≤ n，即 k ≤ n/2。最后一个节点 n 的父节点是 ⌊n/2⌋，所以 ⌊n/2⌋ 是最后一个有子节点的节点，它上面的每个下标都是叶子。当 n = 11 时，循环从 k = 5 开始。

在 `[2, 9, 7, 6, 5, 8]` 上（n = 6，因此循环从 k = 6/2 = 3 开始）：

| --- | --- | --- | --- |
| 开始 | （任意顺序） | — | 2 9 7 6 5 8 |
| k = 3 | sink(3, 6) | 7 < 它唯一的子节点 8 → 交换 | 2 9 8 6 5 7 |
| k = 2 | sink(2, 6) | 9 ≥ 6 和 5 → 不移动 | 2 9 8 6 5 7 |
| k = 1 | sink(1, 6) | 2 与 9 交换，然后与 6 交换 | 9 6 8 2 5 7 |

### 7.4 两种方法并列对比

| | A：朴素（自顶向下） | B：自底向上 |
|---|---|---|
| 思路 | n 次插入：堆一次一个键地从左侧生长 | 从最后一个内部节点到根，原地修复整个数组 |
| 循环 | `for k = 2 … n: swim(a, k)` | `for k = n/2 … 1: sink(a, k, n)` |
| 键的移动方向 | **向上**（swim，朝根移动） | **向下**（sink，朝叶子移动） |
| 叶子 | 每个键都要上浮，包括叶子 | 叶子被跳过（它们已经是堆） |
| 最坏情况 | O(n log n) | **O(n)** |
| 在 `[2, 9, 7, 6, 5, 8]` 上 | 9 6 8 2 5 7（3 次交换） | 9 6 8 2 5 7（3 次交换） |
| 在 `[1, 2, 3, 4, 5, 6, 7]` 上 | 7 4 6 1 3 2 5（10 次交换） | 7 5 6 4 2 1 3（4 次交换） |
| 典型用途 | 键随时间到达的优先队列 | 堆排序的第一阶段（所有键一开始就都在） |

在第一个数组上，两种方法恰好得到相同的堆。一般情况下则不然（最后一行）：两个结果都是有效的堆，只是不同的堆。因此，询问"自底向上"结果的题目必须用方法 B 来作答。交换次数由[第 9 节](#9-完整实现)的程序测得。

> ⚠️ **易错点**：方法 B 的循环从**右到左**运行（从 n/2 减到 1）。从左到右会出错：当你对 k 执行 sink 时，它的子树必须已经是堆。

> ⚠️ **易错点**：不要把操作对调。方法 A **swim**（每个新键向上移动）；方法 B **sink**（每个内部节点向下移动）。把键从 n/2 到 1 依次上浮，既不是方法 A，也不是方法 B，而且无法构建出堆。

### 7.5 为什么自底向上构建是 O(n)

对一个节点执行 sink 的代价至多是它的**高度**（到叶子的距离），而大多数节点都靠近底部。按层计数（高度 0 为叶子）：

| 高度 h | 高度为 h 的节点数 | 最大下沉代价 | 每层的工作量 |
| --- | --- | --- | --- |
| 0（叶子） | 约 n/2 | 0 | 0 |
| 1 | 约 n/4 | 1 | (n/4) · 1 |
| 2 | 约 n/8 | 2 | (n/8) · 2 |
| … | … | … | … |
| h | 约 n / 2^(h+1)（根为 1） | h（根处为 log n） | (n / 2^(h+1)) · h |

总工作量 = n/2 · 0 + n/4 · 1 + n/8 · 2 + … + 1 · log n = n (0/2 + 1/4 + 2/8 + 3/16 + …) ≤ n · 1 = **O(n)**。

**错位相减法**说明这个级数至多为 1。令 S = 1/4 + 2/8 + 3/16 + 4/32 + …。则 S/2 = 1/8 + 2/16 + 3/32 + …。逐项相减：

S − S/2 = 1/4 + 1/8 + 1/16 + … = 1/2（一个等比级数），因此 S = 1。

作为对比：朴素构建一次插入一个键，后来的插入可能上浮 log n 层，因此为 **O(n log n)**。自底向上的方法之所以更快，是因为真正能移动很远的少数节点（靠近根的那些）恰好是被下沉的，而众多的叶子则不需要任何代价。

> 💡 **关键洞见**：朴素插入为*大量*底部节点付出 log n 的代价；自底向上的下沉则只为*一个*顶部节点付出 log n 的代价。

### 7.6 排空（sortdown）

第二阶段：逐个删除最大值，但把它**留在数组中**，而不是把它清空。交换位置 1 与位置 n，把最大值换到堆的最后一个位置；缩小 n 使该位置落在堆之外，于是它保存的就是最终值。

```cpp
template <typename T>
void sortdown(T* a, int n) {
    while (n > 1) {
        std::swap(a[0], a[n - 1]);            // exchange positions 1 and n
        n--;                                  // the heap shrinks
        sink(a, 1, n);                        // repair the new root
    }
}
```

**关键洞见：**每次迭代之后，数组是一个**堆序子数组，后面跟着一个已按最终顺序排好的子数组**。升序输出来自**最大**堆，因为每个最大值都被放到了末尾。

对由 `S O R T E X A M P L E` 构建的堆做排空，即 `X T S P L R A M O E E`：交换位置 1 与 11，然后 sink(1, 10)；交换位置 1 与 10，然后 sink(1, 9)；……一直到交换位置 1 与 2，之后执行 sink(1, 1)，最终得到 `A E E L M O P R S T X`。在下面逐步演示：

```viz binary-heap

```

**代价：**n − 1 次迭代，每次一次交换加上一次代价为 O(log n) 的 sink → 最坏情况为 **O(n log n)**。

> ⚠️ **易错点**：`sink(a, 1, n)` 必须使用**已经减 1 的** n。若用旧的 n 进行 sink，就会把刚放好的最大值拉回堆中。

### 7.7 完整的堆排序

堆排序 = 第一阶段（方法 B）+ 第二阶段（排空），两者作用于同一个数组：

```cpp
template <typename T>
void heapSort(T* a, int n) {
    buildBottomUp(a, n);                      // phase 1: bottom-up construction, O(n)
    sortdown(a, n);                           // phase 2: sortdown, O(n log n)
}
```

两个阶段都调用**同一个 `sink`**，只是参数不同。第一阶段以完整的 n 对**每一个**内部节点 k 执行 sink。第二阶段总是对根 1 执行 sink，并且 n 每轮减 1。在 `[2, 9, 7, 6, 5, 8]` 上的完整排序：


### 7.8 堆排序分析

堆排序 = 自底向上构建 + 排空。

| 阶段 | 交换与比较 |
| --- | --- |
| 堆构建 | O(n) 次交换和 O(n) 次比较 |
| 排空（以及总计） | O(n log n) 次交换和比较 |

因此堆排序是**原地**的，并且有**有保证的 O(n log n) 最坏情况**，无需额外的数组。归并排序需要 O(n) 的额外空间；快速排序是原地的，但最坏情况为 O(n²)。

**在大 O 意义上是最优的，但是……**

1. **内层循环更长：**与快速排序相比，每次键比较的工作量更大（常数因子更高）。
2. **缓存局部性差。** *为什么？* sink 从下标 k 跳到 2k，因此在大数组中，相邻的比较访问的内存相距很远。快速排序和归并排序扫描的是相邻元素，它们能留在缓存中。
3. **不稳定：**远距离交换不会保持相等键的原始次序。

VisuAlgo 在 https://visualgo.net/en/heap?slide=1 上为完整的堆排序制作了动画演示。

> 📘 **延伸阅读**：常数很小。algs4 表明，自底向上构建至多使用 2n 次比较和 n 次交换，而堆排序整体使用的比较和交换次数少于 2 n lg n（这也是它的平均情况）。（algs4 §2.4）

> ⚠️ **易错点**："堆排序是 O(n log n)"对**最好情况也成立**（键互不相同时）。与插入排序不同，它不能在已排序的数组上提前结束：升序数组并不是最大堆，而排空总会做 n − 1 次 sink。

## 8. 排序对比

### 8.1 汇总表

| 排序 | 原地 | 稳定 | 最好 | 平均 | 最坏 | 备注 |
|---|---|---|---|---|---|---|
| 选择 | ✓ | | O(n²) | O(n²) | O(n²) | n 次交换 |
| 插入 | ✓ | ✓ | O(n) | O(n²) | O(n²) | 适用于小数组或部分有序的数组 |
| 归并 | | ✓ | O(n log n) | O(n log n) | O(n log n) | 性能有保证；稳定 |
| 快速 | ✓ | | O(n log n) | O(n log n) | **O(n²)** | n log n 的概率保证；实践中最快 |
| 堆 | ✓ | | O(n log n) | O(n log n) | O(n log n) | 性能有保证；原地 |

没有哪一种排序能同时做到原地、稳定，并且最坏情况为 O(n log n)：归并排序放弃了原地性，快速排序和堆排序放弃了稳定性，快速排序还放弃了最坏情况的保证。

### 8.2 实测运行时间

在 64,000 个整数上测得（g++ -O2，单次运行，时间单位为毫秒），分别针对随机输入和已排序的输入：

| n = 64,000 | 选择 | 插入 | 归并 | 归并，截止值 32 | 快速，主元 `First` | 快速，`Median` | 快速，`Random` |
|---|---|---|---|---|---|---|---|
| 随机 | 836 | 7,766 | 6.5 | 8.6 | 5.2 | 6.2 | 5.5 |
| 已排序 | 871 | 0.04 | 0.34 | 0.08 | **983** | 0.72 | 1.95 |

该表是[第 6.6 节](#66-性质)的数字版本：快速排序在随机数据上最快，但主元选择不当时会退化为平方级；插入排序在已排序数据上是所有算法中最快的，在随机数据上却最慢，甚至比同为 O(n²) 的选择排序还慢，因为基于交换的版本每一步都是有依赖的交换，而不是廉价的比较。归并排序的调优（截止值、跳过检查）见[第 5.7 节](#57-改进)。

### 8.3 下界

**所有基于比较的排序算法，在最坏情况下的下界都是 n log n**（严格地说，这是一个下界，即 Ω）。

> 📘 **延伸阅读**：为什么 n log n 无法被突破？比较排序必须区分输入的全部 n! 种排列，而每次比较只有两种结果，因此某些输入至少需要 lg(n!) ≈ n lg n 次比较（algs4 §2.2）。归并排序达到了这一下界，因此在渐近意义上是最优的。

## 9. 完整实现

一个翻译单元包含了全部五种排序及其变体：`selectionSort`、`insertionSort`、`merge` / `mergeSort` / `mergeSortOptimized` / `mergeNoChecks`、`partition` / `quickSort`（打乱版，以及带 `Pivot` 规则和截止值的版本），以及堆辅助函数 `swim`、`sink`、`buildTopDown`、`buildBottomUp`、`sortdown` 和 `heapSort`。每个排序都具有签名 `void xSort(T* a, int n)`（递归辅助函数接收 `lo`、`hi`）。`main` 是一个测试驱动程序：它在 `3 44 38 5 47 1 36 26` 上运行全部五种排序，用 `Counted` 类型计数比较与交换（一次交换即一次移动构造），用只按点数比较的 `Card` 类型检查稳定性，重放本章的追踪与练习，并在随机输入上把每个变体与 `std::sort` 对比。

```cpp
#include <algorithm>
#include <cstdlib>
#include <iostream>
#include <random>
#include <string>
#include <utility>
#include <vector>

// ===========================================================================
// Elementary sorts
// ===========================================================================
template <typename T>
void selectionSort(T* a, int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;                          // index of the smallest remaining item
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[min]) {
                min = j;
            }
        }
        std::swap(a[i], a[min]);
    }
}

template <typename T>
void insertionSort(T* a, int n) {
    for (int i = 1; i < n; i++) {
        for (int j = i; j > 0; j--) {         // move a[i] left past larger items
            if (a[j] < a[j - 1]) {
                std::swap(a[j], a[j - 1]);
            }
            else break;                       // everything further left is smaller
        }
    }
}

// ===========================================================================
// Merge sort
// ===========================================================================
// Merge the sorted ranges a[lo..mid] and a[mid+1..hi] (stable).
template <typename T>
void merge(T* a, T* aux, int lo, int mid, int hi) {
    for (int k = lo; k <= hi; k++)            // copy a to aux
        aux[k] = a[k];

    int i = lo, j = mid + 1;
    for (int k = lo; k <= hi; k++) {          // merge back into a
        if (i > mid)                          // left half exhausted
            a[k] = aux[j++];
        else if (j > hi)                      // right half exhausted
            a[k] = aux[i++];
        else if (aux[j] < aux[i])             // right item is strictly smaller
            a[k] = aux[j++];
        else                                  // left item (ties go left)
            a[k] = aux[i++];
    }
}

template <typename T>
void mergeSort(T* a, T* aux, int lo, int hi) {
    if (hi <= lo) return;                     // 0 or 1 items: already sorted
    int mid = lo + (hi - lo) / 2;
    mergeSort(a, aux, lo, mid);
    mergeSort(a, aux, mid + 1, hi);
    merge(a, aux, lo, mid, hi);
}

template <typename T>
void mergeSort(T* a, int n) {
    T* aux = new T[n];                        // allocated once
    mergeSort(a, aux, 0, n - 1);
    delete[] aux;
}

// Improvements: insertion sort below a cutoff, skip merges of ordered halves.
template <typename T>
void mergeSortOptimized(T* a, T* aux, int lo, int hi, int cutoff) {
    if (hi <= lo) return;
    if (cutoff > 0 && hi - lo + 1 <= cutoff) {
        insertionSort(a + lo, hi - lo + 1);   // sorts exactly a[lo..hi]
        return;
    }
    int mid = lo + (hi - lo) / 2;
    mergeSortOptimized(a, aux, lo, mid, cutoff);
    mergeSortOptimized(a, aux, mid + 1, hi, cutoff);
    if (!(a[mid + 1] < a[mid])) return;       // halves already in order
    merge(a, aux, lo, mid, hi);
}

template <typename T>
void mergeSortOptimized(T* a, int n, int cutoff = -1) {   // cutoff <= 0: off
    T* aux = new T[n];
    mergeSortOptimized(a, aux, 0, n - 1, cutoff);
    delete[] aux;
}

// Faster but unstable merge: the right half is copied in reverse, so the
// largest item of each half is a sentinel and no exhaustion checks are needed.
template <typename T>
void mergeNoChecks(T* a, T* aux, int lo, int mid, int hi) {
    for (int k = lo; k <= mid; k++)
        aux[k] = a[k];
    for (int k = mid + 1; k <= hi; k++)
        aux[k] = a[hi + mid + 1 - k];

    int i = lo, j = hi;
    for (int k = lo; k <= hi; k++) {
        if (aux[j] < aux[i])
            a[k] = aux[j--];
        else
            a[k] = aux[i++];
    }
}

// ===========================================================================
// Quick sort
// ===========================================================================
// Partition a[lo..hi] around v = a[lo]; returns the pivot's final index j.
template <typename T>
int partition(T* a, int lo, int hi) {
    int i = lo;
    int j = hi + 1;
    T v = a[lo];
    while (true) {
        while (i < hi && a[++i] < v) {        // stop at a key >= v
            if (i == hi) break;
        }
        while (v < a[--j]) {                  // stop at a key <= v
            if (j == lo) break;
        }
        if (i >= j) break;                    // pointers crossed
        std::swap(a[i], a[j]);
    }
    std::swap(a[lo], a[j]);                   // pivot to its final place
    return j;
}

template <typename T>
void quickSort(T* a, int lo, int hi) {
    if (hi <= lo) return;
    int j = partition(a, lo, hi);
    quickSort(a, lo, j - 1);
    quickSort(a, j + 1, hi);
}

template <typename T>
void quickSort(T* a, int n) {
    std::random_device device;                // shuffle first: probabilistic guarantee
    std::default_random_engine engine{device()};
    std::shuffle(a, a + n, engine);
    quickSort(a, 0, n - 1);
}

// Improvements: choose the pivot without shuffling, insertion sort for small ranges.
enum class Pivot { First, Median, Random };

// Move the chosen pivot into a[lo], where partition expects it.
template <typename T>
void choosePivot(T* a, int lo, int hi, Pivot rule, std::mt19937& rng) {
    if (rule == Pivot::Median) {              // median of a[lo], a[mid], a[hi]
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < a[lo]) std::swap(a[lo], a[mid]);
        if (a[hi] < a[lo])  std::swap(a[lo], a[hi]);
        if (a[hi] < a[mid]) std::swap(a[mid], a[hi]);
        std::swap(a[lo], a[mid]);
    }
    else if (rule == Pivot::Random) {         // any index in [lo, hi]
        std::uniform_int_distribution<int> dist{lo, hi};
        std::swap(a[lo], a[dist(rng)]);
    }
}

template <typename T>
void quickSort(T* a, int lo, int hi, Pivot rule, std::mt19937& rng, int cutoff = 0) {
    if (hi <= lo) return;
    if (cutoff > 0 && hi - lo + 1 <= cutoff) {
        insertionSort(a + lo, hi - lo + 1);
        return;
    }
    choosePivot(a, lo, hi, rule, rng);
    int j = partition(a, lo, hi);
    quickSort(a, lo, j - 1, rule, rng, cutoff);
    quickSort(a, j + 1, hi, rule, rng, cutoff);
}

// ===========================================================================
// Heap sort (heap positions are 1..n; position k is stored in a[k - 1])
// ===========================================================================
template <typename T>
void swim(T* a, int k) {
    while (k > 1 && a[k / 2 - 1] < a[k - 1]) {
        std::swap(a[k / 2 - 1], a[k - 1]);
        k /= 2;
    }
}

template <typename T>
void sink(T* a, int k, int n) {
    while (2 * k <= n) {
        int j = 2 * k;
        if (j < n && a[j - 1] < a[j]) j++;    // the larger child
        if (!(a[k - 1] < a[j - 1])) break;    // heap order restored
        std::swap(a[k - 1], a[j - 1]);
        k = j;
    }
}

template <typename T>
void buildTopDown(T* a, int n) {              // method A: n inserts, O(n log n)
    for (int k = 2; k <= n; k++)              // positions 1..k-1 are already a heap
        swim(a, k);                           // position k joins it
}

template <typename T>
void buildBottomUp(T* a, int n) {             // method B: O(n)
    for (int k = n / 2; k >= 1; k--)
        sink(a, k, n);
}

template <typename T>
void sortdown(T* a, int n) {
    while (n > 1) {
        std::swap(a[0], a[n - 1]);            // exchange positions 1 and n
        n--;                                  // the heap shrinks
        sink(a, 1, n);                        // repair the new root
    }
}

template <typename T>
void heapSort(T* a, int n) {
    buildBottomUp(a, n);                      // phase 1: bottom-up construction, O(n)
    sortdown(a, n);                           // phase 2: sortdown, O(n log n)
}

// ===========================================================================
// Test helpers
// ===========================================================================
struct Counted {                              // counts < calls and swaps
    int v;
    static long cmps, swaps;
    Counted(int x = 0) : v(x) {}
    Counted(const Counted& o) : v(o.v) {}
    Counted(Counted&& o) noexcept : v(o.v) { ++swaps; }   // std::swap = one move-construct
    Counted& operator=(const Counted&) = default;
    Counted& operator=(Counted&&) = default;
    bool operator<(const Counted& o) const { ++cmps; return v < o.v; }
    static void reset() { cmps = swaps = 0; }
};
```

## 10. 速查与五个要点

| 排序 | 原地 | 稳定 | 最好 | 平均 | 最坏 | 额外内存 |
|---|---|---|---|---|---|---|
| 选择 | 是 | 否 | O(n²) | O(n²) | O(n²) | O(1) |
| 插入 | 是 | 是 | O(n) | O(n²) | O(n²) | O(1) |
| 归并 | 否 | 是 | O(n log n) | O(n log n) | O(n log n) | O(n)，`aux` |
| 快速 | 是 | 否 | O(n log n) | O(n log n) | O(n²) | O(log n)，栈 |
| 堆 | 是 | 否 | O(n log n) | O(n log n) | O(n log n) | O(1) |

| 组成部分 | 代价 |
|---|---|
| 两个各为 n/2 的半部分的 `merge` | 约 n/2 到 n − 1 次比较 |
| `partition(a, lo, hi)` | O(n) |
| 堆构建：朴素（n 次插入）/ 自底向上 | O(n log n) / **O(n)** |
| sortdown | O(n log n) |

**五个要点**

1. 选择排序在每种输入上都做 n(n−1)/2 次比较（n − 1 次交换，且不稳定）；插入排序提前的 `break` 使已排序的情况为 O(n)，并且它是稳定的。
2. 归并排序：划分是平凡的，所有工作都在 `merge` 中（平局时取左边的元素，因此稳定）；C(n) = 2C(n/2) + (n − 1) 在所有情况下都给出 Θ(n log n)，代价是 O(n) 的 `aux` 数组。
3. 快速排序：划分把主元放到最终位置（两个扫描都在遇到等于主元的键时停止，最后的交换与 `a[j]` 进行）；平均 O(n log n)，当主元总是最小或最大值时最坏为 O(n²)，通过打乱或随机主元 / 三数取中主元，使这种情况不太可能发生。
4. 堆排序 = 自底向上构建（对 k 从 n/2 到 1 执行 sink，O(n)）+ 排空（交换位置 1 与 n，缩小堆，`sink(1, n)`，O(n log n)）：原地，并有有保证的 O(n log n) 最坏情况，但不稳定，且对缓存不友好。
5. 没有比较排序能在最坏情况下突破 n log n；这里每一种 n log n 排序都付出了某种代价（归并：不原地；快速：稳定性与最坏情况；堆：稳定性与实践中的速度）。
