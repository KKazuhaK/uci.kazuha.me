## 1. 排序基础

### 1.1 为什么要学习排序

1. **实用价值。** 排序无处不在：按价格、姓氏、尺寸、日期、邮编排序。用户界面、数据库查询和数据展示都以它为基础。
2. **基准。** 它是在完全相同的问题上比较不同算法性能的好方法，而且某些排序策略与特定的数据结构紧密相连。
3. **解题工具。** 先对数据排序，通常是很好的起点（面试时请记住这一点）。它改变了接下来能做的事：例如，有序数组允许二分查找。

排序算法有很多种：adaptive heapsort、bitonic sorter（高度并行，在 GPU 上很流行）、block sort、bubble sort、bucket sort、cascade mergesort、cocktail sort、comb sort、flashsort、gnome sort、**heapsort**、**insertion sort**、library sort、**mergesort**、odd-even sort、pancake sort、**quicksort**、radixsort、**selection sort**、shell sort、spaghetti sort、treesort，等等。加粗的是本课程要学习的算法。

### 1.2 键、比较与交换

- **排序**是把集合中的 n 个元素按非递减顺序排列，可以是数值顺序，也可以是字母顺序。
- 当一个元素有多个分量时，**键**就是我们用来排序的那个分量，它决定元素之间的相对顺序。例：一本书可以按书名、按作者（都是字母序）或按 ISBN（数值）排序。

这里的每个算法都只通过两种操作接触数据：

- **比较**：`v` 是否小于 `w`？在 C++ 中，这就是 `operator<`（可为你的类型重载），或自定义的比较函数。
- **交换**：交换 `a[i]` 与 `a[j]`。

```cpp
T temp = a[i];      // manual swap
a[i] = a[j];
a[j] = temp;

std::swap(a[i], a[j]);   // standard library (#include <utility>)
```

### 1.3 代价模型、内存与稳定性

**代价模型。** 我们计算**比较和交换**的次数。对于不做交换的算法，改为计算数组访问次数。并非所有排序都基于比较：例如，基数排序从不比较两个键。

**内存。** 额外的内存与运行时间同样重要。

| 类别 | 额外内存 |
|---|---|
| **原地（in place）** | 相对于被排序的元素，只需常数或对数级的额外内存 |
| **非原地（not in place）** | 线性额外内存，与输入规模成正比 |

**稳定性。** 如果键相等的元素在输出中保持输入时的相对顺序，这个排序就是**稳定的（stable）**。以按点数排序的扑克牌为例：输入 7♠ 5♥ 2♥ 5♠。稳定排序得到 2♥ **5♥ 5♠** 7♠（5♥ 原本在前，所以仍然在前）。不稳定排序则可能得到 2♥ **5♠ 5♥** 7♠。

> 📘 **课外补充**（Thornton，*Comparison-Based Sorting*）：稳定性使你能够依次按多个键排序。先按名字排序，再对结果**稳定地**按姓排序。最终结果按姓排序，同姓的人仍保持按名字排序。若第二次排序不稳定，就可能打乱这些同姓者的顺序。

## 2. 选择排序

### 2.1 思路与代码

把数组分成**左侧的已排序子数组**和**右侧的未排序子数组**。重复以下步骤：

- 在未排序部分中找到**最小**元素，
- 将它与**最左边的未排序**元素交换，
- 把边界向右移动一个元素。

```cpp
#include <utility>// for std::swap
template <typename T>
void selectionSort(T* arr, int size) {
   for (int i = 0; i < size - 1; i++) {
      // Find index of smallest remaining element
      int min = i;
      for (int j = i + 1; j < size; j++) {
         if (arr[j] < arr[min]) {
            min = j;
         }
      }

      // efficient swap using move semantics
      std::swap(arr[i], arr[min]);
   }
}
```

**不变式。** 第 i 次迭代结束时：

- `arr[0…i]` 按升序排列，并且
- `arr[i+1…n−1]` 中没有任何元素小于 `arr[0…i]` 中的任何元素。

因此，第 i 次迭代之后，`arr[0…i]` 保存了这些位置的最终值，之后再也不会被改动。最后一个元素会自动就位，这就是外层循环在 `size − 1` 处停止的原因。

在数组 `3 44 38 5 47 1 36 26`（→ `1 3 5 26 36 38 44 47`）上逐步演示：

```viz selection-sort
{"title": "选择排序：对 3 44 38 5 47 1 36 26 排序", "array": [3, 44, 38, 5, 47, 1, 36, 26], "interactive": true}
```

### 2.2 分析

- **比较次数：** 第 i 次迭代扫描 n − 1 − i 个元素，总数为 (n−1) + (n−2) + … + 1 = n(n−1)/2 ≈ n²/2，即 **O(n²)**。对每种输入都一样，因为扫描无法提前停止。
- **交换次数：** 每次迭代一次，共 n − 1 次，即 **O(n)**（代码在 `min == i` 时也会“交换”）。
- **已经有序时？** 仍然是 n(n−1)/2 次比较，因此仍为 O(n²)。选择排序察觉不到数据已经有序。
- **原地：** 是，额外只使用 `i`、`j` 和 `min`。
- **稳定：** 否。远距离交换可能使某个元素越过与它相等的元素。例：`5♥ 5♠ 2♥`。第 0 趟将 2♥ 与 5♥ 交换，得到 `2♥ 5♠ 5♥`，两个 5 的顺序就颠倒了。

用计数器在 n = 1000 上测量（与上面的公式吻合：1000·999/2 = 499,500）：

```text
n=1000 sorted:   selection cmps=499500 swaps=999
n=1000 reversed: selection cmps=499500 swaps=999
```

> 📘 **课外补充**（algs4 §2.1）：由于选择排序最多只做 n − 1 次交换，当**移动**元素的代价远高于比较时，应当选用它。algs4 的例子是：一位仓库职员通过阅读标签来整理沉重的箱子。

## 3. 插入排序

### 3.1 思路与代码

保持左侧一个*部分*有序的子数组，右侧是未排序的子数组。重复以下步骤：

- 取未排序部分的下一个元素，
- 找到它在已排序部分中应当所在的位置，并把它插入那里，
- 把边界向右移动一个元素。

大多数人整理手中的扑克牌就是这样做的。与选择排序不同，左侧部分只是**相对于自身**有序：之后的元素仍可以插入其中。

```cpp
#include <utility>// for std::swap
template <typename T>
void insertionSort(T* arr, int size) {
   for (int i = 0; i < size ; i++) {
      for (int j = i; j > 0; j--) {      // slide: "j–" (see bug note)
         if (arr[j] < arr[j-1]) {
            std::swap(arr[j], arr[j-1]);
         }
         else break;
      }
   }
}
```

> ⚠️ **易错点**（幻灯片错误）：幻灯片的内层循环写的是 `j–`（一个 en dash），无法编译。应为 `j--`。（外层循环从 `i = 0` 开始是无害的：第 0 趟什么也不做。）

内层循环会把 `arr[j]` 向左交换，**越过每一个比它大的邻居**。遇到第一个不比它大的邻居时，它就**跳出（break）**：左边更远的部分都已有序，因此该元素已经就位。这个提前退出正是它与选择排序的全部区别。

在同一个数组上逐步演示：

```viz insertion-sort
{"title": "插入排序：对 3 44 38 5 47 1 36 26 排序", "array": [3, 44, 38, 5, 47, 1, 36, 26], "interactive": true}
```

### 3.2 分析

| 输入 | 比较次数 | 交换次数 | Big-O |
|---|---|---|---|
| **最好：已经有序** | n − 1（每趟：一次比较，然后 break） | 0 | **O(n)** |
| **最坏：逆序** | n(n−1)/2（每个元素都要一路移到最前面） | n(n−1)/2 | **O(n²)** |
| 平均（随机） | ≈ n²/4 | ≈ n²/4 | O(n²) |

```text
n=1000 sorted:   insertion cmps=999    swaps=0
n=1000 reversed: insertion cmps=499500 swaps=499500
```

- **原地：** 是。
- **稳定：** 是。只有在 `arr[j] < arr[j-1]`（严格小于）时才交换，因此元素永远不会越过与它相等的元素。把扑克牌 7♠ 5♥ 2♥ 5♠ 按点数排序，得到 `2H 5H 5S 7S`：5♥ 仍在 5♠ 之前。

> 📘 **课外补充**（algs4 §2.1）：插入排序进行的交换次数恰好等于**逆序对**（inversion，即顺序错误的元素对）的数量。因此，对于**部分有序**的数组（逆序对很少，例如一个已排序的列表后面追加了几个新元素），插入排序几乎以线性时间运行。这就是它常用于小规模或接近有序输入的原因。

## 4. 选择排序与插入排序

| | 选择排序 | 插入排序 |
|---|---|---|
| 比较次数，最坏 | n(n−1)/2 → O(n²) | n(n−1)/2 → O(n²)（逆序） |
| 比较次数，最好 | n(n−1)/2 → O(n²)（总是如此） | n − 1 → O(n)（已经有序） |
| 交换次数 | n − 1 → O(n)，总是如此 | 0（最好）到 n(n−1)/2（最坏） |
| 原地 | 是 | 是 |
| 稳定 | **否**（远距离交换） | **是**（只交换相邻且严格更小的元素） |
| 优势 | 交换次数最少 | 在已排序或接近有序的数据上很快 |

> 💡 **关键洞见**：两者在最坏情况下都是 O(n²)。选择排序**每次**都要付出 n²/2 次比较的代价。插入排序只为实际存在的无序付出代价。

计时比较（同时包括归并排序和快速排序）：在 64,000 个随机整数上，这个基于交换的插入排序比选择排序*慢*约 9 倍（每一步都是相互依赖的交换，而不是廉价的比较，因此看似相同的 O(n²) 其常数相差很大）；在已排序的输入上则快约 20,000 倍。表格见[第 6.8 节](#68-代码中的枢轴策略)。

## 5. 归并排序

### 5.1 基本思想

归并排序由 John von Neumann 于 1945 年发明，是“分治法的典型范例”。算法如下：

1. **划分**：把数组分成两半。
2. **递归排序**：分别排序每一半。
3. **归并**：把两个有序的半部分合并起来。

对 `M E R G E S O R T E X A M P L E` 的概览：

| 步骤 | 数组 |
| --- | --- |
| 输入 | M E R G E S O R T E X A M P L E |
| 排序左半部分 | E E G M O R R S \| T E X A M P L E |
| 排序右半部分 | E E G M O R R S \| A E E L M P T X |
| 归并结果 | A E E E E G L M M O P R R S T X |

> 💡 **关键洞见**：划分是平凡的（在中间下标处切开）。所有真正的工作，也就是每一次比较，都发生在 `merge()` 中。

### 5.2 归并两个有序半部分

`merge` 接受 `a[lo..mid]` 和 `a[mid+1..hi]`，这两段**各自已经有序**，并使 `a[lo..hi]` 有序。它先把该区间复制到辅助数组 `aux` 中，然后逐个位置 `k` 写回 `a`：

```cpp
template <typename T>
void merge(T* a, T* aux, int lo, int mid, int hi)
{
    for (int k = lo; k <= hi; k++)       // Copy from a to aux
        aux[k] = a[k];

    int i = lo, j = mid + 1;

    for (int k = lo; k <= hi; k++) {     // Merge back into a
        if (i > mid)                     // Left subarray is exhausted
            a[k] = aux[j++];
        else if (j > hi)                 // Right subarray is exhausted
            a[k] = aux[i++];
        else if (aux[j] < aux[i])        // Select from right subarray
            a[k] = aux[j++];
        else                             // Select from left subarray
            a[k] = aux[i++];
    }
}
```

各个下标的含义：

- `i` = `aux` 中左半部分下一个未使用的元素（在 `i <= mid` 时有效）
- `j` = `aux` 中右半部分下一个未使用的元素（在 `j <= hi` 时有效）
- `k` = `a` 中下一个要填充的位置

`i > mid` 表示左半部分已用完，`j > hi` 表示右半部分已用完；此时剩下的元素直接复制，不再比较。只有当两半都还有元素时，第三个分支才比较 `aux[j] < aux[i]`，较小者胜出。可以把它想象成“扑克牌游戏”：两叠已排序的牌正面朝上，每次总是取较小的顶牌。

归并 `aux = A G L O R | H I M S T`（lo = 0, mid = 4, hi = 9）：

| k | 情况 | 赋值 | a 之后 |
| --- | --- | --- | --- |
| 0 | aux[i] < aux[j]（A 对 H） | a[0] = aux[0] | **A** |
| 1 | G 对 H | a[1] = aux[1] | A **G** |
| 2 | aux[i] > aux[j]（L 对 H） | a[2] = aux[5] | A G **H** |
| 3 | L 对 I | a[3] = aux[6] | A G H **I** |
| 4 | L 对 M | a[4] = aux[2] | … **L** |
| 5 | O 对 M | a[5] = aux[7] | … **M** |
| 6 | O 对 S | a[6] = aux[3] | … **O** |
| 7 | R 对 S | a[7] = aux[4] | … **R** |
| 8 | i > mid | a[8] = aux[8] | … **S** |
| 9 | i > mid | a[9] = aux[9] | A G H I L M O R S T |

在下面逐步演示（聚焦演示区后，← / → 键有效）：

```viz merge-sort
{"title": "归并 A G L O R | H I M S T", "items": "A, G, L, O, R, H, I, M, S, T", "mode": "merge", "mid": 4}
```

> ⚠️ **易错点**：只有当两半都已有序时，`merge` 才是正确的。它从不回头检查，因此一个无序的半部分会按其原始顺序输出，与另一半混在一起。

### 5.3 递归排序与包装函数

```cpp
template <typename T>
void sort(T* a, T* aux, int lo, int hi)
{
    if (hi <= lo)                        // Base case for recursion
        return;

    int mid = lo + (hi - lo) / 2;        // calculate midpoint, split in half
    sort(a, aux, lo, mid);               // recursively sort left subarray
    sort(a, aux, mid+1, hi);             // recursively sort right subarray
    merge(a, aux, lo, mid, hi);          // merge left and right
}

template <typename T>
void sort(T* a, int length)
{
    T* aux = new T[length];              // Dynamically allocate aux array
    sort(a, aux, 0, length - 1);
    delete[] aux;
}
```

- `lo` 和 `hi` 都是**闭区间**，因此包装函数传入 `length - 1`。
- 基本情况 `hi <= lo`：只有 0 或 1 个元素的区间本身就是有序的。
- `mid = lo + (hi - lo) / 2` 与 `(lo + hi) / 2` 相等，但不会使 `int` 溢出。当长度为奇数时，左半部分 `lo..mid` 多出一个元素。
- 两个 `sort` 函数是**重载**。用户调用 `sort(a, length)`；包装函数只分配一次 `aux` 并向下传递，而不是在每次 `merge` 中都分配。
- `new T[length]` 与 `delete[]` 配对使用。

`std::sort` 和 `std::merge` 已经在 `<algorithm>` 中；我们自己实现它们是为了理解其原理。

### 5.4 归并排序的追踪

追踪 `sort([M,E,R,G,E,S,R,T])`。调用顺序是**深度优先**的：一直向左走到基本情况（想象一面砖墙），然后处理右侧，最后在回溯时进行归并。

| 调用 | 发生了什么 | 之后的 a |
| --- | --- | --- |
| sort(0,7) | mid = 3，先走左侧 | M E R G E S R T |
| sort(0,3) | mid = 1，先走左侧 | |

### 5.5 归并排序的分析

**为什么重要：** 设计算速度为 10¹⁰ 次比较/秒（笔记本）对比 10¹⁷（超级计算机）：

| 计算机 | 插入排序：千 | 百万 | 十亿 | 归并排序：千 | 百万 | 十亿 |
| --- | --- | --- | --- | --- | --- | --- |
| 笔记本 | 瞬间 | 2 小时 | 300 年 | 瞬间 | 1 秒 | 15 分钟 |
| 超级计算机 | 瞬间 | 1 秒 | 1 周 | 瞬间 | 瞬间 | 瞬间 |

运行归并排序的笔记本胜过运行插入排序的超级计算机：好的算法比超级计算机更重要。

**比较次数的计算。** 对 n 个元素的一次 `merge` 最多做 **n − 1** 次比较：每次比较会放置一个元素，而最后一个元素总是不需要比较就能放置（另一半已经空了）。因此最坏情况下的比较次数满足

$$C(n) = 2\,C(n/2) + (n - 1), \qquad C(1) = 0$$

（两次递归排序，加上最后的一次归并；计算 `mid` 不需要比较）。若只看增长阶，可写为 $T(n) = 2T(n/2) + n$。

- **递归树**：第 k 层有 2ᵏ 个子问题，每个规模为 n/2ᵏ，因此每一层共归并 n 个元素。将 n 不断减半直到 1 需要 log₂ n 层。总计约为 n · log₂ n。精确地说，当 n 为 2 的幂时 $C(n) = n\log_2 n - n + 1$（n = 8 时为 17）。
- **主定理**（$T(n) = aT(n/b) + n^d$）：a = 2，b = 2，d = 1，且 a = bᵈ，因此 $T(n) = \Theta(n^d \log n) = \Theta(n \log n)$。

如果计算的是全部工作（复制到 `aux`、更新下标），而不只是比较次数，那么只会改变常数：每次 `merge` 仍是 Θ(n)，因此在最好、平均和最坏情况下，结果同样是 **Θ(n log n)**。

合并两个各为 n/2 的有序半部分，需要的比较次数在约 n/2（某一半先用完，例如 `1 2 3 | 4 5 6` → 3 次）与 n − 1（两半交错，例如 `1 3 5 | 2 4 6` → 5 次）之间。

> 📘 **课外补充**：algs4 §2.2 给出了完整范围：对于任意规模为 n 的输入，归并排序使用的比较次数在 ½ n lg n 与 n lg n 之间。最好情况是最坏情况的一半，因为一次归并至少需要 n/2 次比较（某一半先用完）。

### 5.6 性质与改进

- **额外内存与 n 成正比**：最后一次归并时，`aux` 必须容纳 n 个元素。
- 在最简单的形式下**不是原地的**。虽然有一些变体可以把辅助数组减半，但真正的原地归并非常困难。
- **稳定**：相等的键保持原有顺序。在 `merge` 中，只有 `aux[j] < aux[i]` 时才取右侧元素；相等时 `else` 分支取的是**左侧**元素，即先出现的那个。

改进方法：

1. 对小的子数组使用**插入排序**。
2. 如果已经有序则**停止**。
3. **消除**复制到辅助数组的步骤，以节省时间。

> 📘 **课外补充**：这三项改进的具体含义（algs4 §2.2）：(1) 在约 10–15 个元素以下截断为插入排序，可使典型的归并排序提速 10–15%；(2) 当 `a[mid] <= a[mid+1]` 时跳过 `merge`，这使得已排序的输入变为线性；(3) 在每一层递归中交替使用 `a` 和 `aux` 的角色，从而节省复制的时间（而不是空间）。

> ⚠️ **易错点**：把相等时的判断改为 `aux[j] <= aux[i]`，归并排序就不再稳定（来自右侧的相等元素会跑到前面）。

### 5.7 代码中的改进：截断与跳过检查

TimingSort 项目中的 `MergeOptimized` 把改进 1 和 2 融入了递归辅助函数。它与[第 5.3 节](#53-递归排序与包装函数)是同一个算法，但作用于 `std::vector<T>&`，并且 `aux` 在 `sort()` 中只分配一次：

```cpp
template <typename T>
void MergeOptimized<T>::mergeSortHelper(std::vector<T>& data,
        std::vector<T>& aux, int lo, int hi)
{
    if (hi <= lo) return;

    // 1. small range: insertion sort on data[lo..hi]
    if (insertionSortThreshold > 0 &&
        hi - lo + 1 <= insertionSortThreshold) {
        for (int i = lo + 1; i <= hi; ++i)
            for (int j = i; j > lo && data[j] < data[j - 1]; --j)
                std::swap(data[j], data[j - 1]);
        return;
    }

    int mid = lo + (hi - lo) / 2;
    mergeSortHelper(data, aux, lo, mid);
    mergeSortHelper(data, aux, mid + 1, hi);

    // 2. halves already in order: nothing to merge
    if (data[mid] <= data[mid + 1]) return;
    merge(data, aux, lo, mid, hi);
}
```

- **阈值 ≤ 0 表示关闭截断。** 构造函数的默认阈值为 `-1`（不截断，即 `MergeOptimized<int>()`），只有在开启时 `name()` 才会输出 `MergeSort: 32`。
- **跳过检查**：对于已经有序的输入，每次 `merge` 都被跳过，因此整个排序的代价为 T(n) = 2T(n/2) + 1 = **Θ(n)**（n − 1 次比较）。这两项改动都不会让相等的键互相越过，因此排序**保持稳定**（项目的 `IsStable` 测试会检查这一点）。
- **实测**（g++ -O2，64,000 个整数）：随机数据上，不截断为 6.5 ms，截断为 32 时为 8.6 ms，截断为 64 时为 12.0 ms；已排序数据上为 0.34 ms 对 0.08 ms。另一项在 2²⁰ 个随机整数上的基准测试（取 5 次中的最佳值）：不截断 128 ms，截断为 8 → 130，16 → 140，32 → 169，64 → 221。因此对于这种基于交换的插入排序，截断只在（接近）有序的数据上有益，而且 32/64 远高于 algs4 建议的 10–15。表格见[第 6.8 节](#68-代码中的枢轴策略)。

> ⚠️ **易错点**：辅助函数中的插入排序必须在 `j > lo` 处停止，而不是 `j > 0`。若使用 `j > 0`，它会继续与相邻的、递归尚未完成的子数组交换。

### 5.8 不做耗尽检查的归并

更快的 `merge` 去掉了前两个判断 `i > mid` 和 `j > hi`（algs4 练习 2.2.10，“更快的归并”）。诀窍是：把右半部分**反向**复制到 `aux` 中。这样 `aux[lo..hi]` 先沿左半部分上升，再沿右半部分下降，并且两半各自的最大元素都紧挨着中间。当某一半用完时，它的指针会停在另一半的**最大**元素上，而这个元素不会小于仍在等待的任何元素，因此它充当哨兵，无需边界检查。从两端同时归并：`i` 从 `lo` 向右移动，`j` 从 `hi` 向左移动。

```cpp
template <typename T>
void merge(T* a, T* aux, int lo, int mid, int hi)
{
    for (int k = lo; k <= mid; ++k) {
        aux[k] = a[k];
    }

    for (int k = mid + 1; k <= hi; ++k) {
        aux[k] = a[hi + mid + 1 - k];
    }

    int i = lo;
    int j = hi;

    for (int k = lo; k <= hi; ++k) {
        if (aux[j] < aux[i]) {
            a[k] = aux[j--];
        }
        else {
            a[k] = aux[i++];
        }
    }
}
```

以[第 5.2 节](#52-归并两个有序半部分)的两半为例：`A G L O R | H I M S T` 被复制为 `aux = A G L O R T S M I H`。归并依次取出 A、G（左侧），H、I（从末端取的右侧）……在 R 之后，左指针移到 T 上，因此 S 和 T 无需任何 `i > mid` 判断就能按顺序输出。

- 下标检查：`k = mid + 1` 复制的是 `a[hi]`，`k = hi` 复制的是 `a[mid + 1]`，因此第二个循环恰好将右半部分反转。
- 代价：每一步一次比较，而不是最多三次。仍然是每次 merge Θ(n)，总体 **Θ(n log n)**。同一基准（2²⁰ 个随机整数）：118 ms 对 128 ms（快约 8%）。
- **不稳定。** 左半部分用完后，`i` 会走进反转后的右半部分，相等时 `else` 分支取的是 `aux[i]`，即*较晚*出现的元素。例：`(1a) | (2b 2c)` → `aux = 1a 2c 2b` → 结果 `1a 2c 2b`。因此，若归并必须保持稳定，就要使用[第 5.2 节](#52-归并两个有序半部分)中的四分支版本。

> ⚠️ **易错点**：这个版本有两处容易出错的地方。第一，首次复制循环必须从 `lo` 开始，而不是 `0`（从 0 开始复制会使每次 merge 的代价变为 O(hi)，整个排序变为 O(n²)）。第二，左指针向前移动（`aux[i++]`），只有 `j` 是向后递减的。

## 6. 快速排序

### 6.1 背景与思想

快速排序同样是分治法，由 Sir Tony Hoare 于 1959 年发明。他想在字典中查单词之前先把单词排好序，想出了快速排序，但当时不知道如何实现它；后来他学习了 Algol 60 和递归，才把它实现出来。他因此获得了 1980 年的图灵奖（他还发明了 null，并为此后悔）。

与归并排序不同，这里的工作发生在递归**之前**，而不是之后：

1. **打乱**数组（随机洗牌）。
2. **划分**，使得对于某个枢轴下标 `j`：
   - 元素 `a[j]` 位于其最终位置，
   - 其左侧没有更大的元素，
   - 其右侧没有更小的元素。
3. **递归排序**每个子数组。不需要归并步骤：两侧都排好序之后，整个数组就有序了。

| | 之前 | 划分之后 |
|---|---|---|
| 布局 | `v`（枢轴位于 `lo`），然后是直到 `hi` 的未知区域 | `≤ v` … `v`（位于 `j`）… `≥ v` |

递归驱动函数与公开入口：

```cpp
#include <random>
#include <utility>

// quicksort
template <typename T>
void sort(T* a, int lo, int hi)
{
    if (hi <= lo) return;
    int j = partition(a, lo, hi);
    sort(a, lo, j-1);
    sort(a, j+1, hi);
}

template <typename T>
void sort(T* a, int length) {
    std::random_device device;                          // Random shuffle
    std::default_random_engine engine{device()};
    std::shuffle(std::begin(a), std::end(a), engine);

    sort(a, 0, length-1);
}
```

例（来自 algs4）：输入 `Q U I C K S O R T E X A M P L E` → 打乱 → `K R A T E L E P U I M Q C X O S` → 以 `K` 划分 → `E C A I E K L P U T M Q R X O S` → 排序左侧 → 排序右侧 → `A C E E I K L M O P Q R S T U X`。

> ⚠️ **易错点**（幻灯片中的代码错误）：
> `std::shuffle(std::begin(a), std::end(a), engine)` 无法编译：`a` 是 `T*`，而 `std::begin`/`std::end` 需要数组或容器。修正：`std::shuffle(a, a + length, engine);`
> `std::shuffle` 声明在 `<algorithm>` 中，而幻灯片没有包含它。修正：加入 `#include <algorithm>`。

> 💡 **关键洞见**：归并排序 = 平凡的划分，困难的合并。快速排序 = 困难的划分（partition），平凡的合并。每次划分都会把**一个**元素（枢轴）放到最终位置，这就是递归总能终止的原因：每个子数组都严格更小。

### 6.2 划分

目标：重排 `a[lo..hi]`，使得 `a[lo..j-1] <= a[j] <= a[j+1..hi]`。

- 枢轴 `v` 取 `a[lo]`（“最简单的方法”）。指针 `i` 从 `lo` 开始，`j` 从 `hi + 1` 开始。
- 重复以下步骤，直到 `i` 与 `j` 交错：
  - 从左到右扫描 `i`，**只要 `a[i] < v`**（在遇到**大于等于**枢轴的键时停止）；
  - 从右到左扫描 `j`，**只要 `v < a[j]`**（在遇到**小于等于**枢轴的键时停止）；
  - 若 `i >= j`，跳出；
  - 交换 `a[i]` 与 `a[j]`。
- 最后，交换 `a[lo]` 与 `a[j]`，并返回 `j`。

为什么要与 `a[j]` 交换，而不是 `a[i]`？当两个扫描交错时，`j` 位于 `≤ v` 区域的最后一个元素上，因此把枢轴换到那里，可以保证它左边的所有元素都 `≤ v`。

```cpp
template <typename T>
int partition(T* a, int lo, int hi) {
    int i = lo;
    int j = hi + 1;
    T v = a[lo];
    while (true) {

        // Move i to the right for elements < v

        while (i < hi && a[++i] < v) {
            if (i == hi) break;
        }
        // Move j to the left for elements > v

        while (v < a[--j]) {
            if (j == lo) break;
        }
        if (i >= j) break;         // If pointers cross, stop

        std::swap(a[i], a[j]);     // Swap elements at i and j
    }
    // Place the partitioning item in its correct position
    std::swap(a[lo], a[j]);
    return j;
}
```

`i == hi` / `j == lo` 这两个保护条件，确保当枢轴是最大或最小的键时，扫描仍然留在子数组之内。（`j == lo` 这个保护实际上是多余的：`a[lo]` 就是 `v` 本身，而 `v < v` 为假，但它无害。）幻灯片标题把名字拼成了 “Sedgwick”；正确的拼写是 Robert **Sedgewick**。

> ⚠️ **易错点**：前置自增很关键。`a[++i]` 先移动再比较，因此 `i` 看的第一个元素是 `a[lo+1]`（枢轴被跳过）。同理，`a[--j]` 从 `a[hi]` 开始，因为 `j` 起始于 `hi + 1`。

> 📘 **课外补充**：两个扫描都在**等于枢轴的键**处停止（用 `<`，而不是 `<=`）。这看起来会导致多余的交换，但正是它使快速排序在含有大量重复元素的数组上依然快速：当所有键都相等时，停止使 `i` 与 `j` 在中间相遇（均匀划分 → n log n）；如果不停止，一个指针会一直走到末尾，得到 0 / n−1 的划分 → 平方级时间（algs4 §2.3）。

### 6.3 追踪一次划分

对打乱后的数组 `K R A T E L E P U I M Q C X O S`，以 `v = K` 进行第一次划分：

| 轮次 | `i` 停在 | `j` 停在 | 操作 | 之后的数组 |
|---|---|---|---|---|
| 1 | 1（`R` ≥ K） | 12（`C` ≤ K） | 交换 | `K C A T E L E P U I M Q R X O S` |
| 2 | 3（`T`） | 9（`I`） | 交换 | `K C A I E L E P U T M Q R X O S` |
| 3 | 5（`L`） | 6（`E`） | 交换 | `K C A I E E L P U T M Q R X O S` |
| 4 | 6（`L`） | 5（`E`） | `i >= j` → 跳出 | — |
| 结束 | | | `swap(a[0], a[5])`，返回 5 | `E C A I E K L P U T M Q R X O S` |

划分之后：`K` 永久位于下标 5，它左边的所有元素都 `≤ K`，右边的都 `≥ K`。然后 `sort` 对 `lo = 0, hi = 4` 递归（从 `E C A I E` 开始，`i = 0`，`j = 5`）。

algs4 的追踪列出了每一次 `partition` 调用。每一行是对 `a[lo..hi]` 围绕最终落在 `j` 处的枢轴划分后的数组；`lo == hi`（或 `hi < lo`）的行表示大小为 1 或 0 的子数组，**不进行划分**，`sort` 直接返回。

### 6.5 分析：最坏、最好、平均

对 `n` 个元素进行一次 `partition` 的代价是 **O(n)**：`i` 与 `j` 合起来只扫过子数组一次（约 n + 1 次比较）。因此一切取决于**枢轴落在哪里**。

| 情况 | 场景 | 递推式 | 解 |
|---|---|---|---|
| 最坏 | 枢轴总是最小或最大的键 → 划分为 0 和 n−1（例如未打乱的已排序或逆序输入） | T(n) = T(n−1) + n | n + (n−1) + … + 2 ≈ n²/2 → **O(n²)** |
| 最好 | 枢轴总是中位数 → 两个相等的半部分 | T(n) = 2T(n/2) + n | lg n 层，每层 n 的工作量 → **O(n log n)** |
| 平均 | 随机打乱 → 枢轴的秩均匀随机 | — | **O(n log n)** |

用上面的代码实测（不打乱，规模为 n 的已排序输入）：n = 100 → 5,148 次比较，n = 200 → 20,298 次，n = 400 → 80,598 次，大约是 n²/2，每当 n 翻倍时比较次数翻四倍。同样规模为 1,000 的已排序输入，**加上**打乱之后只需 12,083 次比较。

什么能降低最坏情况发生的可能性？开始时的**随机打乱**：任何固定的输入（已排序、逆序……）都不再是坏情况；只有不走运的随机选择才会导致坏情况，而对于大规模输入，这种情况几乎不会发生。这就是“概率性保证”。

> 📘 **课外补充**：平均情况约为 **2n ln n ≈ 1.39 n lg n** 次比较（algs4 §2.3），而归并排序至多约为 n lg n 次。“比归并排序多 39% 的比较”正是由此而来。

### 6.6 性质

- **比归并排序多 39% 的比较，但实践中更快。** 原因：
  - 数据移动更少（归并排序在每一层都要把每个元素复制到 `aux` 再复制回来）；
  - 缓存性能好：划分按顺序扫描内存，与预取配合得很好；
  - 没有额外的内存分配。
- **随机打乱**提供了针对最坏情况的概率性保证。
- 平均 O(n log n)，最坏 O(n²)。
- **原地**：只在数组内部交换（外加递归栈）。
- **不稳定**：远距离交换会重新排列相等的键。下面练习中的例子：对 `5 8 7 9 5 4` 围绕第一个 `5` 划分，最后的 `swap(a[lo], a[j])` 交换了两个 `5`。

快速排序的性能表明，Big-O 是对现实性能的一个**不完整的模型**：它的最坏 Big-O 在 n log n 类排序中是最差的，但它仍然是最快的。

### 6.7 改进

1. **对小的子数组使用插入排序**：在极小的子数组上，递归开销占主导，而插入排序在那里很快（与归并排序相同的技巧，见[第 5.6 节](#56-性质与改进)）。
2. **改进枢轴选择**（并去掉开始时的随机打乱）：
   - 使用一个**随机元素**作为枢轴（先把它换到 `a[lo]`，然后照常划分）；
   - 使用**一个小样本的中位数**作为枢轴，平均而言划分得更好。

> 📘 **课外补充**：algs4 建议切换为插入排序的阈值在约 5 到 15 个元素之间，并指出取 **3** 个样本（三数取中）就能获得样本中位数方法的大部分好处。

存在 [归并排序](https://www.youtube.com/watch?v=XaqR3G_NVoo) 和 [快速排序](https://www.youtube.com/watch?v=3San3uKKHgg) 的动画“舞蹈”视频——快速排序的舞蹈使用的是与这里**不同的划分变体**，因此不要用它来核对追踪过程。

### 6.8 代码中的枢轴策略

TimingSort 项目中的 `QuickOptimized` 实现了改进 2，并且**不做开始时的打乱**。构造函数接受 `"LO"`（默认）、`"MEDIAN"` 或 `"RANDOM"`，`choosePivot` 在每次 `partition` 之前运行。它选出的枢轴会被**交换到 `data[lo]`**，因此 `partition` 保持与[第 6.2 节](#62-划分)完全相同的代码（枢轴 `v = a[lo]`）。

```cpp
// MEDIAN: order a[lo], a[mid], a[hi],
// then move the median into a[lo]
int mid = lo + (hi - lo) / 2;
if (a[mid] < a[lo]) std::swap(a[lo], a[mid]);
if (a[hi] < a[lo])  std::swap(a[lo], a[hi]);
if (a[hi] < a[mid]) std::swap(a[mid], a[hi]);
std::swap(a[lo], a[mid]);

// RANDOM: any index in [lo, hi] (inclusive)
std::uniform_int_distribution<int> dist{lo, hi};
std::swap(a[lo], a[dist(rng)]);
```

- 经过三次比较-交换后，`a[lo] <= a[mid] <= a[hi]`，因此 `a[mid]` 是三者的中位数；最后一次交换把它移到 `lo`。其他任何不是 `"MEDIAN"`/`"RANDOM"` 的值都回退为 `"LO"`（枢轴 = 第一个元素）。
- `rng` 是一个成员变量（`std::mt19937 rng{std::random_device{}()};`），只初始化一次。每次调用都创建 `random_device` 会很慢。
- **为什么它重要——已排序的输入。** 使用 `"LO"` 时，枢轴每次都是最小的键，因此每次划分都是 0 / n−1：约 n²/2 次比较，递归深度为 n（足够深的输入会使栈溢出）。三数取中在已排序的区间中选出真正的中间值，因此顶层划分是完美的，以下各层也接近完美；随机枢轴则给出了概率性的 n log n 保证，这原本是由打乱提供的。

实测（g++ -O2，单次运行，毫秒）：

| n = 64,000 | 选择 | 插入 | 归并 | 归并，截断 32 | 快速 LO | 快速 MEDIAN | 快速 RANDOM |
|---|---|---|---|---|---|---|---|
| 随机 | 836 | 7,766 | 6.5 | 8.6 | 5.2 | 6.2 | 5.5 |
| 已排序 | 871 | 0.04 | 0.34 | 0.08 | **983** | 0.72 | 1.95 |

这张表正是[第 6.6 节](#66-性质)的数据体现：快速排序在随机数据上最快，但枢轴选得不好时是平方级的；插入排序在已排序数据上是所有算法中最快的，在随机数据上却是最慢的，甚至比同为 O(n²) 的选择排序还慢，因为基于交换的版本每一步都是相互依赖的交换，而不是廉价的比较。归并排序的调优（截断、跳过检查）见[第 5.7 节](#57-代码中的改进截断与跳过检查)。

> ⚠️ **易错点**：`medianOfThree` / `randomPivot` 必须把枢轴留在 **`a[lo]`** 中，因为 `partition` 假定如此。如果只返回枢轴的值，却让它留在 `mid`（或随机下标）处，划分就会围绕错误的元素进行。

## 7. 堆排序

### 7.1 计划

利用堆（[堆](topic-heaps.zh-CN.md)）分两步进行排序：

1. **堆构建**：把全部 n 个待排序的键建成一个二叉堆；
2. **排空（sortdown）**：反复删除并返回最大键。

例：由 9 个键 1, 2, 3, 7, 17, 19, 25, 36, 100 建成的最大堆，经过九次 delete-max 调用依次返回 `100 36 25 19 17 7 3 2 1`，即按降序排列。由于 `exch(1, n--)` 把每次取出的最大值放到逐渐缩小的堆之后，数组本身最终按升序排列：`– 1 2 3 7 17 19 25 36 100`。这种原地技巧就是排空（[第 7.6 节](#76-排空sortdown)）。

第二阶段总是相同的。第一阶段有**两种方法**，二者很容易混淆，因为两者最终都得到一个堆。它们的区别在于方向、所用的操作（上浮 swim 还是下沉 sink），以及代价。下面两种方法都在数组 `[2, 9, 7, 6, 5, 8]`（n = 6）上演示。

### 7.2 方法 A：朴素的自顶向下构建

堆从**左侧**开始生长。起初只有 `a[1]` 是一个堆；每一步，下一个键加入堆的末尾，并在大于其父节点时**上浮（swim）**。这相当于就地做 n 次 `insert`（向空堆插入不移动任何元素，因此循环从 k = 2 开始）：

```cpp
for (int k = 2; k <= n; k++)   // a[1..k-1] is already a heap
    swim(a, k);                // a[k] joins it: swim up past smaller parents
```

| 步骤 | 新键 | 上浮 | 之后的堆 |
|---|---|---|---|
| k = 1 | 2 | —（单独一个） | 2 |
| k = 2 | 9 | 9 > 2 → 交换 | 9 2 |
| k = 3 | 7 | 7 < 9 → 留在原处 | 9 2 7 |
| k = 4 | 6 | 6 > 2 → 交换；6 < 9 → 停止 | 9 6 7 2 |
| k = 5 | 5 | 5 < 6 → 留在原处 | 9 6 7 2 5 |
| k = 6 | 8 | 8 > 7 → 交换；8 < 9 → 停止 | 9 6 8 2 5 7 |

演示把每一步写成 `insert(x)`，它与“追加并上浮”是同一回事：

```viz binary-heap
{"title": "方法 A：依次插入 2, 9, 7, 6, 5, 8", "ops": "insert(2); insert(9); insert(7); insert(6); insert(5); insert(8)"}
```

**代价：** 第 k 个键最多上浮 log k 层。在最坏情况下（升序输入：每个新键都是新的最大值，并一路上浮到根），总代价为 log 1 + log 2 + … + log n = **O(n log n)**。

### 7.3 方法 B：自底向上构建

把整个数组**原样**看作一棵完全二叉树。叶子（`a[n/2+1..n]`）本身已经是只有一个键的堆，因此跳过它们。从右到左遍历内部节点，并对每个节点**下沉（sink）**：

```cpp
for (int k = n/2; k >= 1; k--)
    sink(a, k, n);
```

**关键洞见：** `sink(a, k, n)` 完成之后，以 k 为根的子树就是一个堆。从右到左下沉，意味着处理 k 时它的两个子节点都已经是堆，因此一次下沉就能修复整棵子树；`sink(a, 1, n)` 之后，整个数组就是一个堆。

**为什么第一个要处理的节点是 n/2？** 节点 k 有左子节点，当且仅当 2k ≤ n，即 k ≤ n/2。最后一个节点 n 的父节点是 ⌊n/2⌋，因此 ⌊n/2⌋ 是最后一个有子节点的节点；比它更大的下标都是叶子。当 n = 11 时，循环从 k = 5 开始。

`sink(a, k, n)` 是堆的 `sink` 接受数组和大小作为参数的版本（因此堆排序可以作用于任意数组）；其函数体与 [堆](topic-heaps.zh-CN.md) 中的 `sink(k)` 相同。

对 `[2, 9, 7, 6, 5, 8]`（n = 6，循环从 k = 6/2 = 3 开始）：

| 步骤 | 调用 | 移动了什么 | 之后的数组 |
|---|---|---|---|
| 开始 | （任意顺序） | — | 2 9 7 6 5 8 |
| k = 3 | sink(3, 6) | 7 < 它唯一的子节点 8 → 交换 | 2 9 8 6 5 7 |
| k = 2 | sink(2, 6) | 9 ≥ 6 和 5 → 不移动 | 2 9 8 6 5 7 |
| k = 1 | sink(1, 6) | 2 与 9 交换，再与 6 交换 | 9 6 8 2 5 7 |

### 7.4 两种方法并列对比

| | A：朴素（自顶向下） | B：自底向上 |
|---|---|---|
| 思路 | n 次插入：堆一次一个键地从左侧生长 | 从最后一个内部节点回溯到根，原地修复整个数组 |
| 循环 | `for k = 2 … n: swim(a, k)` | `for k = n/2 … 1: sink(a, k, n)` |
| 键的移动方向 | **向上**（swim，朝根） | **向下**（sink，朝叶子） |
| 叶子 | 每个键都要上浮，包括叶子 | 叶子被跳过（本身已经是堆） |
| 最坏情况 | O(n log n) | **O(n)** |
| 对 `[2, 9, 7, 6, 5, 8]` | 9 6 8 2 5 7（3 次交换） | 9 6 8 2 5 7（3 次交换） |
| 对 `[1, 2, 3, 4, 5, 6, 7]` | 7 4 6 1 3 2 5（10 次交换） | 7 5 6 4 2 1 3（4 次交换） |
| 典型用途 | 键随时间到达的优先队列 | 堆排序的第一阶段（所有键一开始就已存在） |

对于上面的数组，两种方法恰好得到相同的堆。但一般来说它们并不相同（最后一行）：两个结果都是合法的堆，只是不同的堆。因此，如果问题要求“自底向上”的结果，必须用方法 B 作答。

> ⚠️ **易错点**：方法 B 的循环是**从右到左**运行的（从 n/2 减到 1）。从左到右会使它失效：下沉 k 时，它的子节点所在的子树必须已经是堆。

> ⚠️ **易错点**：不要混淆两种操作。构建方法 A **上浮**（每个新键向上移动）；构建方法 B **下沉**（每个内部节点向下移动）。从 n/2 到 1 对键做上浮既不是方法 A，也不是方法 B，而且无法构成堆。

### 7.5 为什么自底向上构建是 O(n)

下沉一个节点的代价至多是它的**高度**（到叶子的距离），而大多数节点都在底部附近。按层计数（高度 0 = 叶子）：

| 高度 h | 高度为 h 的节点数 | 最大下沉代价 | 每层工作量 |
|---|---|---|---|
| 0（叶子） | ~ n/2 | 0 | 0 |
| 1 | ~ n/4 | 1 | (n/4) · 1 |
| 2 | ~ n/8 | 2 | (n/8) · 2 |
| … | … | … | … |
| h | ~ n / 2^(h+1)（根为 1 个） | h（根处为 log n） | (n / 2^(h+1)) · h |

总工作量 = n/2 · 0 + n/4 · 1 + n/8 · 2 + … + 1 · log n = n (0/2 + 1/4 + 2/8 + 3/16 + …) ≤ n · 1 = **O(n)**。

**位移法**可以说明该级数至多为 1。令 S = 1/4 + 2/8 + 3/16 + 4/32 + …，则 S/2 = 1/8 + 2/16 + 3/32 + …。逐项相减：

S − S/2 = 1/4 + 1/8 + 1/16 + … = 1/2（等比级数），因此 S = 1。

相比之下，朴素构建一次插入一个键，后期插入的键可能上浮 log n 层，因此是 **O(n log n)**。自底向上的方法更快，因为真正能移动很远的少数节点（靠近根的那些）才是被下沉的，而众多的叶子不花任何代价。

> 💡 **关键洞见**：朴素插入要为底部的*大量*节点付出 log n 的代价；自底向上的下沉只为顶部的*一个*节点付出 log n 的代价。

### 7.6 排空（sortdown）

第二阶段：每次删除最大值，但把它**留在数组中**，而不是把它清空。`exch(a, 1, n--)` 把最大值交换到堆的最后一个位置并缩小堆，因此该位置已经不属于堆，并保存着它的最终值。

```cpp
while (n > 1) {
    exch(a, 1, n--);
    sink(a, 1, n);
}
```

**关键洞见：** 每次迭代之后，数组是一个**堆序的子数组，后面跟着一个按最终有序顺序排列的子数组**。升序输出来自*最大*堆，因为每个最大值都被放到后面。

对 algs4 的例子进行排空（由 `S O R T E X A M P L E` 构建的堆，即 `X T S P L R A M O E E`）：`exch(1, 11), sink(1, 10)`，`exch(1, 10), sink(1, 9)`，……一直到 `exch(1, 2), sink(1, 1)`，最终得到 `A E E L M O P R S T X`。在下面逐步演示：

```viz binary-heap
{"title": "对 X T S P L R A M O E E 排空", "heap": "X, T, S, P, L, R, A, M, O, E, E", "ops": "sortdown()", "interactive": true}
```

**代价：** n − 1 次迭代，每次一次交换加上一次 O(log n) 的下沉 → 最坏情况 **O(n log n)**。

> ⚠️ **易错点**：`sink(a, 1, n)` 必须使用**已经减小的** n。若用旧的 n 下沉，会把刚放好的最大值重新拉回堆中。

### 7.7 完整的堆排序

堆排序 = 第一阶段（方法 B）+ 第二阶段（排空），两者作用于同一个数组：

```cpp
void heapSort(std::vector<int>& a) {     // keys in a[1..n]; a[0] unused
    int n = a.size() - 1;
    for (int k = n/2; k >= 1; k--)       // phase 1: bottom-up construction, O(n)
        sink(a, k, n);
    while (n > 1) {                      // phase 2: sortdown, O(n log n)
        exch(a, 1, n--);                 //   max to the back; the heap shrinks
        sink(a, 1, n);                   //   repair the new root
    }
}
```

两个阶段都调用**同一个 `sink`**，但参数不同。第一阶段以**完整的 n** 下沉**每一个内部节点 k**。第二阶段总是下沉**根 1**，并且 n 每轮减一。（`less`、`exch` 和 `sink` 见[第 9 节](#9-完整实现)。）对 `[2, 9, 7, 6, 5, 8]` 的完整排序：


### 7.8 堆排序分析

堆排序 = 自底向上构建 + 排空。

| 阶段 | 交换与比较 |
|---|---|
| 堆构建 | O(n) 次交换和 O(n) 次比较 |
| 排空（及总计） | O(n log n) 次交换和比较 |

因此，堆排序是**原地**的，并且具有**有保证的 O(n log n) 最坏情况**——不需要额外的数组。归并排序需要 O(n) 的额外空间；快速排序是原地的，但最坏情况为 O(n²)。

**在 Big-O 上是最优的，但是……**

1. **内层循环较长：** 每次键比较所做的工作比快速排序多（常数因子更大）。
2. **缓存局部性差。** *为什么？* 下沉从下标 k 跳到 2k，因此在大数组中，相邻的比较会访问相距很远的内存。快速排序和归并排序扫描的是相邻元素，它们留在缓存中。
3. **不稳定：** 远距离交换不能保持相等键的原始顺序。

完整的堆排序动画见 https://visualgo.net/en/heap?slide=1。

> 📘 **课外补充**：这些常数很小。algs4 表明，自底向上构建最多使用 2n 次比较和 n 次交换，而整个堆排序使用的比较和交换次数少于 2 n lg n（这也是它的平均情况）。（algs4 §2.4）

> ⚠️ **易错点**：“堆排序是 O(n log n)”对**最好情况**同样成立（键互不相同时）。与插入排序不同，它无法在已排序的数组上提前结束：已排序的升序数组不是最大堆，而排空总要进行 n − 1 次下沉。

## 8. 排序对比

### 8.1 汇总表

| 排序 | 原地 | 稳定 | 最好 | 平均 | 最坏 | 备注 |
|---|---|---|---|---|---|---|
| 选择 | ✓ | | O(n²) | O(n²) | O(n²) | n 次交换 |
| 插入 | ✓ | ✓ | O(n) | O(n²) | O(n²) | 用于小数组或部分有序的数组 |
| 归并 | | ✓ | O(n log n) | O(n log n) | O(n log n) | 性能有保证；稳定 |
| 快速 | ✓ | | O(n log n) | O(n log n) | **O(n²)** | n log n 的概率性保证；实践中最快 |
| 堆 | ✓ | | O(n log n) | O(n log n) | O(n log n) | 性能有保证；原地 |

这里没有任何一种排序能同时做到原地、稳定，并且最坏情况为 O(n log n)：归并排序放弃了原地性，快速排序和堆排序放弃了稳定性，快速排序还放弃了最坏情况的保证。

### 8.2 下界

**所有基于比较的排序算法，在最坏情况下的下界都是 n log n**（严格地说，这是一个下界，即 Ω）。

> 📘 **课外补充**：为什么 n log n 无法被超越：比较排序必须区分输入的全部 n! 种排列，而每次比较只有两种结果，因此某些输入至少需要 lg(n!) ≈ n lg n 次比较（algs4 §2.2）。归并排序达到了这个下界，因此在渐近意义上是最优的。

## 9. 完整实现

归并排序：

```cpp
#include <utility>

namespace mergesort {
template <typename T>
void merge(T* a, T* aux, int lo, int mid, int hi) {
    for (int k = lo; k <= hi; k++) aux[k] = a[k];
    int i = lo, j = mid + 1;
    for (int k = lo; k <= hi; k++) {
        if (i > mid)              a[k] = aux[j++];
        else if (j > hi)          a[k] = aux[i++];
        else if (aux[j] < aux[i]) a[k] = aux[j++];
        else                      a[k] = aux[i++];
    }
}
template <typename T>
void sort(T* a, T* aux, int lo, int hi) {
    if (hi <= lo) return;
    int mid = lo + (hi - lo) / 2;
    sort(a, aux, lo, mid);
    sort(a, aux, mid+1, hi);
    merge(a, aux, lo, mid, hi);
}
template <typename T>
void sort(T* a, int length) {
    T* aux = new T[length];
    sort(a, aux, 0, length - 1);
    delete[] aux;
}
}
```

快速排序（已修正打乱的问题）：

```cpp
#include <algorithm>
#include <random>
#include <utility>

template <typename T>
int partition(T* a, int lo, int hi) {
    int i = lo;
    int j = hi + 1;
    T v = a[lo];
    while (true) {
        while (i < hi && a[++i] < v) {
            if (i == hi) break;
        }
        while (v < a[--j]) {
            if (j == lo) break;
        }
        if (i >= j) break;
        std::swap(a[i], a[j]);
    }
    std::swap(a[lo], a[j]);
    return j;
}

template <typename T>
void sort(T* a, int lo, int hi) {
    if (hi <= lo) return;
    int j = partition(a, lo, hi);
    sort(a, lo, j - 1);
    sort(a, j + 1, hi);
}

template <typename T>
void sort(T* a, int length) {
    std::random_device device;
    std::default_random_engine engine{device()};
    std::shuffle(a, a + length, engine);  // fixed
    sort(a, 0, length - 1);
}
```

堆排序（1 起始：`a[0]` 不使用），附带一个驱动程序，它为 `[2, 9, 7, 6, 5, 8]` 构建堆并进行排序：

```cpp
#include <iostream>
#include <utility>
#include <vector>

// ---------- Heap sort (1-based: a[0] unused) ----------
template <typename T>
bool less(const std::vector<T>& a, int i, int j) { return a[i] < a[j]; }

template <typename T>
void exch(std::vector<T>& a, int i, int j) { std::swap(a[i], a[j]); }

template <typename T>
void sink(std::vector<T>& a, int k, int n) {
    while (2 * k <= n) {
        int j = 2 * k;
        if (j < n && less(a, j, j + 1)) j++;
        if (!less(a, k, j)) break;
        exch(a, k, j);
        k = j;
    }
}

template <typename T>
void heapSort(std::vector<T>& a) {       // a[1..n] holds the keys
    int n = static_cast<int>(a.size()) - 1;
    for (int k = n / 2; k >= 1; k--)     // 1) heap construction
        sink(a, k, n);
    while (n > 1) {                       // 2) sortdown
        exch(a, 1, n--);
        sink(a, 1, n);
    }
}

int main() {
    std::vector<int> a{0, 2, 9, 7, 6, 5, 8};         // a[0] unused
    int n = 6;
    for (int k = n / 2; k >= 1; k--) sink(a, k, n);
    std::cout << "heap: ";
    for (int i = 1; i <= n; i++) std::cout << a[i] << " ";
    std::cout << "\n";
    heapSort(a);
    std::cout << "sorted: ";
    for (int i = 1; i <= n; i++) std::cout << a[i] << " ";
    std::cout << "\n";

    std::vector<char> s{' ', 'S','O','R','T','E','X','A','M','P','L','E'};
    heapSort(s);
    for (std::size_t i = 1; i < s.size(); i++) std::cout << s[i];
    std::cout << "\n";
}
```

## 10. 速查与五个要点

| 排序 | 原地 | 稳定 | 最好 | 平均 | 最坏 | 额外内存 |
|---|---|---|---|---|---|---|
| 选择 | 是 | 否 | O(n²) | O(n²) | O(n²) | O(1) |
| 插入 | 是 | 是 | O(n) | O(n²) | O(n²) | O(1) |
| 归并 | 否 | 是 | O(n log n) | O(n log n) | O(n log n) | O(n) 的 `aux` |
| 快速 | 是 | 否 | O(n log n) | O(n log n) | O(n²) | O(log n) 的栈 |
| 堆 | 是 | 否 | O(n log n) | O(n log n) | O(n log n) | O(1) |

| 部分 | 代价 |
|---|---|
| 两半各为 n/2 的 `merge` | 约 ~n/2 到 n − 1 次比较 |
| `partition(a, lo, hi)` | O(n) |
| 堆构建：朴素（n 次插入）/ 自底向上 | O(n log n) / **O(n)** |
| 排空 | O(n log n) |

**必须记住的 5 个要点**

1. 选择排序对每种输入都要做 n(n−1)/2 次比较（n − 1 次交换，不稳定）；插入排序在排好序的情况下通过提前的 `break` 变为 O(n)，并且它是稳定的。
2. 归并排序：平凡的划分，所有工作都在 `merge` 中（相等时取左侧元素，因此稳定）；C(n) = 2C(n/2) + (n − 1) 在所有情况下给出 Θ(n log n)，代价是一个 O(n) 的 `aux` 数组。
3. 快速排序：划分把枢轴放到最终位置（两个扫描都在等于枢轴的键处停止，最后的交换与 `a[j]` 进行）；平均 O(n log n)，当枢轴总是最小或最大值时最坏为 O(n²)，通过打乱或随机 / 三数取中的枢轴可使其极不可能发生。
4. 堆排序 = 自底向上构建（从 n/2 到 1 下沉 k，O(n)）+ 排空（`exch(1, n--)`、`sink(1, n)`，O(n log n)）：原地，最坏情况有保证为 O(n log n)，但不稳定，且对缓存不友好。
5. 没有任何基于比较的排序在最坏情况下能突破 n log n；这里每一种 n log n 排序都付出了某些代价（归并：不是原地的；快速：稳定性与最坏情况；堆：稳定性以及实践中的速度）。
