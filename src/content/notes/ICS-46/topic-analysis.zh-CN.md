## 1. 为什么要分析算法？

你常常同时扮演三种角色：**程序员**（需要一个能用的解）、**客户**（希望它高效）和**理论家**（想要理解它）。分析效率的理由：**预测**性能、**比较**算法、**提供**保证、**理解**理论，以及**避免**性能缺陷。

**计算复杂度** = **时间复杂度**（运行时间如何随输入规模增长）+ **空间复杂度**（内存如何增长）。时间可以用两种方式来研究：测量它（[§2](#2-运行时间的实测分析)）和建模它（[§3](#3-运行时间的数学模型)）；模型随后用渐近记号概括（[§4](#4-渐近分析big-obig-ωbig-θ)）。空间在 [§6](#6-空间复杂度) 中讨论，递归算法则在 [§7](#7-递归分析递推式与递归树)–[§8](#8-主定理) 中讨论。

## 2. 运行时间的实测分析

### 2.1 贯穿全讲的例子：3-SUM

给定 n 个互不相同的数，有多少个**无序三元组**之和为 0？输入 `30 -40 -20 -10 40 0 10 5` → **4**（`30 -40 10`、`30 -20 -10`、`-40 40 0`、`-10 0 10`）。

```cpp
int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = i+1; j < n; j++) {
        for (int k = j+1; k < n; k++) {
            if (a[i] + a[j] + a[k] == 0) {
                count++;
            }
        }
    }
}
```

用随机整数文件计时：

| 文件 | n | 三元组数 | 用时（秒） |
|---|---|---|---|
| 8ints.txt | 8 | 4 | 0 |
| 1Kints.txt | 1000 | 70 | 0.081 |
| 2Kints.txt | 2000 | 528 | 0.38（重跑：0.371） |
| 4Kints.txt | 4000 | 4039 | 2.792 |
| 8Kints.txt | 8000 | 32074 | 21.623 |
| 16Kints.txt | 16000 | 255181 | 177.344 |

同样的输入，时间却不同（0.38 与 0.371）：测量本身带有噪声。

> 📘 **课外补充**：algs4 把这一过程看作科学方法——观察、提出模型假设、预测一个未测量的情形、验证、重复。下面的倍增测试正是这个循环。

### 2.2 对数-对数图与幂律

画出 T(n) 关于 n 的图，再重画到**对数-对数**图上。如果它是一条直线，则运行时间是**幂律**：

$$T(n) = a\,n^b \quad\Longrightarrow\quad \log T(n) = b \log n + \log a$$

斜率就是 **b**。把 3-SUM 的测量值逐个加到对数-对数图上，并标出倍增比（在下面逐步演示，演示获得焦点时 ← / → 键可用）：

```viz doubling-test
{"title": "3-SUM 倍增测试", "n": [1000, 2000, 4000, 8000, 16000], "times": [0.081, 0.38, 2.792, 21.623, 177.344]}
```

从 lg n = 11.97 到 13.97，直线上升 7.47 − 1.48 ≈ 6.0，跨度为 2.0：斜率 **b = 3**。拟合结果：**T(n) ≈ 0.42 × 10⁻¹⁰ n³** 秒。

### 2.3 倍增假设

让 n 翻倍并取比值，a 被约掉：

$$\frac{T(n)}{T(n/2)} = \frac{a\,n^b}{a\,(n/2)^b} = 2^b$$

- **b**：从 8000 到 16000，比值为 177.344 / 21.623 ≈ **8.2**，所以 b ≈ lg 8.2 ≈ **3**。
- **a**：T(16000) = 177.34 = a × 16000³ → a = 0.42 × 10⁻¹⁰。

> ⚠️ **易错点**：177.34 / 16000³ 实际算出来是 **0.43 × 10⁻¹⁰**；0.42 来自拟合直线。

测量表中的全部比值：

| n | T(n)（秒） | T(n)/T(n/2) | lg 比值 |
|---|---|---|---|
| 8 | 0 | — | — |
| 1000 | 0.081 | — | — |
| 2000 | 0.38 | 4.7 | 2.2 |
| 4000 | 2.792 | 7.3 | 2.9 |
| 8000 | 21.623 | 7.7 | 2.95 |
| 16000 | 177.344 | 8.2 | 3.04 |

**为什么选取较大的两个输入规模？** n 较小时运行时间极短，计时器精度和噪声占比很大（n = 8 甚至读数为 0），而且低阶项和固定开销在 n³ 旁边还不可忽略。比值只有在 n 较大时才会稳定在 8 附近。

在我的机器上复现（`-O2`，取 3 次运行的最小值，随机整数）：从 n = 500 到 8000 的比值为 7.97、7.60、8.25、7.81——**b ≈ 3** 依然成立，但 a ≈ 1.7 × 10⁻¹⁰（n = 8000 时为 86.949 秒），在不同硬件上常数不同。

### 2.4 什么决定了 a 和 b

对于 T(n) = a·n^b：

| | 与系统无关的因素 | 与系统相关的因素 |
|---|---|---|
| 决定 | 指数 **b**（并影响 a） | 只决定常数 **a** |
| 例子 | 操作所用的数据结构与算法；算法本身；输入数据 | 硬件（CPU、内存、缓存）；软件（编译器、垃圾回收器）；系统（操作系统、网络等） |

所以 b 是算法及其输入的性质；更快的机器改变的是 a，永远不会改变 b。

## 3. 运行时间的数学模型

### 3.1 总时间 = Σ 代价 × 频率

（Donald Knuth，1960 年代）：**总运行时间 = 对所有操作求 代价 × 频率 之和。**

| 代价 | 频率 |
|---|---|
| 与系统和机器有关 | 与算法和数据有关 |
| 精确代价取决于机器与编译器；分析程序以找出其基本操作 | 取决于数据结构、算法设计和输入；原则上可以得到精确的数学模型 |

C++ 基本操作的相对代价：`int add < int multiply < int divide < float add < float multiply < float divide`；内存访问的代价各不相同，但基本模型假设它的代价与一次加法相当。

| 操作 | 例子 | 代价 |
|---|---|---|
| 变量声明 | `int a;` | c1 |
| 赋值 | `a = b;` | c2 |
| 整数比较 | `a < b;` | c3 |
| 数组/向量访问 | `a[i]`、`v[i]` | c4 |
| 容器大小 | `v.size()` | c5 |
| 动态分配 | `new int[n]`、`std::vector<int> v(n)` | c6·n |

分配是个特例：它与 n 成正比，而不是常数。（原表的列标题显示的是未渲染的 `$c_i$`——一处 LaTeX 渲染失误。）

### 3.2 数操作次数：1-Sum

给定 n 个互不相同的数，有多少个数等于 0？

```cpp
int count = 0;
for (int i = 0; i < n; i++) {
    if (a[i] == 0) {
        count++;
    }
}
```

| 操作 | 频率 | 原因 |
|---|---|---|
| 变量声明 | 2 | `count`、`i` |
| 赋值 | 2 | `count = 0`、`i = 0` |
| 小于 | **n + 1** | `i < n` 为真 n 次，然后为假一次以退出 |
| 相等 | n | `a[i] == 0` |
| 数组访问 | n | `a[i]` |
| 自增 | **n 到 2n** | `i++` 执行 n 次，另加 0 到 n 次 `count++`（取决于数据） |

在 n = 10 时实测：`less=11 equal=10 access=10`；无零时 `incr=10`，有一个零时 `incr=11`。

> ⚠️ **易错点**：数互不相同时，至多有一个为 0，所以自增次数实际为 **n 到 n + 1**（若不假设“互不相同”，界为 n 到 2n）。

### 3.3 数操作次数：2-Sum

**问题：** 给定 n 个互不相同的数，有多少个*无序*数对（“二元组”）之和为 0？暴力法对每个数对 `i < j` 试一次：

```cpp
int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = i+1; j < n; j++) {
        if (a[i] + a[j] == 0) {
            count++;
        }
    }
}
```

对于固定的 `i`，内层循环体执行 `n - i - 1` 次，因此总计 $(n-1) + \dots + 1 + 0 = n(n-1)/2$ 次（每个数对一次）。每个循环的*判断条件*比其循环体多执行一次。计数如下：

| 操作 | 频率 | 来源 |
|---|---|---|
| 变量声明 | $n + 2$ | `count`、`i`，以及每次外层迭代声明一次的 `j` |
| 赋值 | $n + 2$ | `count = 0`、`i = 0`、`j = i+1` ×n |
| 小于 | $(n+1)(n+2)/2$ | 外层：$n+1$；内层：$n + (n-1) + \dots + 1 = n(n+1)/2$ |
| 相等 | $n(n-1)/2$ | 每个内层循环体一次 |
| 数组访问 | $n(n-1)$ | `a[i]`、`a[j]`：每个内层循环体 2 次 |
| 自增 | $n(n+1)/2$ 到 $n^2$ | `i++` ×n + `j++` ×n(n−1)/2，另加 0 次或多次 `count++` |

结论：**“计算起来已经太繁琐了！”**——所以只选一种代价模型（数组访问），并只保留首项（[§3.4](#34-波浪号记法)、[§3.5](#35-简化代价模型--波浪号)）：暴力法 2-Sum 做 **$\sim n^2$** 次数组访问。

实测运行（每一行都与公式一致）：

```text
n=10 (no pairs)  pairs=0 decl=12 assign=12 less=66 eq=45 access=90 incr=55
   formulas: n+2=12 (n+1)(n+2)/2=66 n(n-1)/2=45 n(n-1)=90 n(n+1)/2=55 n^2=100
```

> ⚠️ **易错点**：循环判断条件比循环体多执行 **一次**（最后那次判断失败）——外层 `<` 是 $n+1$ 次，而不是 $n$ 次。

### 3.4 波浪号记法

只保留**首项**来估计运行时间（或内存），因为当 n 很大时低阶项可以忽略。

| 表达式 | 波浪号 |
|---|---|
| (1/6)n³ + 10n + 100 | ~ n³ |
| (1/6)n³ + 100n² + 47 | ~ n³ |
| (1/6)n³ + 100n^(2/3) + (1/2)/n | ~ n³ |

> 📘 **课外补充**：algs4 把 g(n) ~ f(n) 定义为 g(n)/f(n) → 1，这样会保留系数：第一行严格来说是 ~ (1/6)n³。“~ n³”的形式只是增长阶的简写。Big-O（[§4](#4-渐近分析big-obig-ωbig-θ)）连常数也会去掉。

### 3.5 简化：代价模型 + 波浪号

(1) **代价模型**——用某一种基本操作作为运行时间的代理，例如**数组访问**；(2) 用波浪号记法描述它的频率。应用到 2-Sum 上：

| 操作 | 频率 | 波浪号 |
|---|---|---|
| 变量声明 | n + 2 | ~ n |
| 赋值 | n + 2 | ~ n |
| 小于 | (n + 1)(n + 2)/2 | ~ n² |
| 相等 | n(n − 1)/2 | ~ n² |
| 数组访问 | n(n − 1) | ~ n² |
| 自增 | n(n + 1)/2 到 n² | ~ n² |

结果：**2-SUM 问题约需 ~n² 次数组访问。**同样的推理用于 3-SUM：C(n, 3) ~ n³/6 个三元组 × 3 次访问 = **约 n³/2 次数组访问**，与实验得到的 b = 3 相吻合。

<summary>解答</summary>

## 4. 渐近分析：Big-O、Big-Ω、Big-Θ

### 4.1 为什么要“往大处想”

比较 $f(n) = n$、$g(n) = 4n$、$h(n) = n^2$。当 n 很小时，$f$ 和 $g$ 看起来差别很大，$h$ 甚至比它们*更低*（$n < 4$ 时 $n^2 < 4n$）。当 n 很大时，$f$ 和 $g$ 与 $h$ 相比看起来很相似，两者的增长速度明显不同。

**渐近分析**用输入规模 n 的函数来描述运行时间，只看 n 变大时的增长情况：**忽略小的 n（“THINK BIG”）**；**增长率越慢 = 算法越好**。

| n | $f = n$ | $g = 4n$ | $h = n^2$ |
|---|---|---|---|
| 2 | 2 | 8 | 4 |
| 4 | 4 | 16 | 16 |
| 100 | 100 | 400 | 10,000 |

### 4.2 Big-O：上界

$f(n)$ 为 $O(g(n))$，当存在正常数 $c$ 与 $n_0$，使得

$$f(n) \le c \cdot g(n) \quad \text{for all } n \ge n_0.$$

$f$ 是实际的运行时间，$g$ 是形状相同但更简单的函数；$c$ 吸收常数因子，$n_0$ 忽略小的 n。通俗地说：“我的代码**至多**花这么长时间。”例子：$3n^3 + 2n + 7 = O(n^3)$；$2^n + n^2 = O(2^n)$；$1000 = O(1)$；而 $3n^3 + 2n + 7 = O(n^6)$ 虽然成立，却是**没用的界**——应给出最紧的界。Big-O 让我们能在 n 变大时做高层次的比较，并忽略底层细节：它**不是**精确的运行时间。

**求 $c$、$n_0$ 的例子：** 当 $n \ge 1$ 时，$2n \le 2n^3$ 且 $7 \le 7n^3$，所以 $3n^3 + 2n + 7 \le 12n^3$。因此 $c = 12$、$n_0 = 1$ 即可，$3n^3 + 2n + 7 = O(n^3)$。捷径：**保留增长最快的项，去掉它的系数。**

### 4.3 Big-Ω：下界

若存在正的 $c$、$n_0$，使得对所有 $n \ge n_0$ 有 $f(n) \ge c \cdot g(n)$，则 $f(n)$ 是 $\Omega(g(n))$——“**至少**花这么长时间”。Ω 可以描述整类算法：每一种基于比较的排序都是 $\Omega(n \log n)$。

两个示例图：$f_1(n)$ 大多数时候取较小的值，偶尔会冲高到接近 n → $\Omega(1)$；$f_2(n)$ 是一条近似 n 的直线 → $\Omega(n)$。

> 📘 **课外补充**：$f_1$ 的尖峰落在素数上，它的低值则像是每个 n 的最小因子——这正是试除法素性检验的步数：对大多数 n 很便宜，对素数则是线性的。

### 4.4 Big-Θ：紧界

若 $f(n)$ 既是 $O(g(n))$ 又是 $\Omega(g(n))$，则它是 $\Theta(g(n))$——“恰好花这么长时间，忽略常数和低阶项。”**若 Big-O 与 Big-Ω 不一致，Big-Θ 无定义。**所以 $f_2(n) = \Theta(n)$，而 $f_1$（$O(n)$、$\Omega(1)$）没有 Θ。

| 记号 | 界 | 定义（∃ $c, n_0 > 0$，∀ $n \ge n_0$） | 通俗说法 |
|---|---|---|---|
| $O(g)$ | 上界 | $f(n) \le c \cdot g(n)$ | 至多 |
| $\Omega(g)$ | 下界 | $f(n) \ge c \cdot g(n)$ | 至少 |
| $\Theta(g)$ | 紧界 | 两者同时成立 | “恰好”，忽略常数 |

这些记号既可以描述时间，也可以描述空间。

### 4.5 情形与增长率

这是两个独立的问题：**哪种情形？**（最好、平均、最坏输入）以及**增长得多快？**（O(1)、O(log n)、O(n)、O(n²)，……）。在长度为 n 的数组中做线性查找：

| 情形 | 何时发生 | 比较次数 | 增长率 |
|---|---|---|---|
| 最好 | 目标在第一个位置 | 1 | O(1) |
| 平均 | 目标在中间 | n/2 | O(n) |
| 最坏 | 目标在最后或不存在 | n | O(n) |

> ⚠️ **易错点**：“Big-O = 最坏情形，Big-Ω = 最好情形”是**错的**。先确定情形，再给它求界：线性查找的最坏情形是 Θ(n)，最好情形是 Θ(1)。若未指明情形，它是 O(n) 且 Ω(1)，但没有 Θ。

#### 简单任务的 Big-O、Big-Ω、Big-Θ

给定一个由 n 个三位整数组成、顺序随机的数组，用 Big-O、Big-Ω、Big-Θ 描述下列任务的时间复杂度：(a) 1. 把所有元素打印到 std::out；2. 在（未排序的）数组中查找某个数。(b) 求下列各式的 Big-O：1. T(n) = 7n − 2000；2. T(n) = n³ + 46n² + 10000；3. T(n) = 3 log n + 5n。

## 6. 空间复杂度

**位**（bit）是 0/1，**字节**（byte）是 8 位。传统的 KB/MB/GB/TB 分别是 $2^{10}/2^{20}/2^{30}/2^{40}$ 字节（是 1,024，而不是 1,000）；这些二的幂对应的 IEC 名称是 KiB/MiB/GiB/TiB。

典型 C++ 类型大小，`sizeof` 在 x86-64 Linux（g++ 13）上测得：

| 类型 | 典型值 | 实测 |
|---|---|---|
| `bool`、`char` | 1 字节 | 1 |
| `short` | 2 | 2 |
| `int`、`float` | 4 | 4 |
| `long` | 4 或 8 | 8 |
| `long long`、`double` | 8 | 8 |
| 指针（`int*`） | 64 位上为 8，32 位上为 4 | 8 |

- **静态数组**：只有元素存储，没有额外开销。**动态数组**与**对象**：存储加上变量开销。

## 7. 递归分析：递推式与递归树

### 7.1 为什么要分析递归

有些算法和数据结构用递归来写最为合适，因此我们需要像分析循环那样求出它们的运行时间。标准例子：

```cpp
int factorial(int n)
{
    if (n == 0)
        return 1;
    else
        return n * factorial(n - 1);
}
```

**最坏情形时间复杂度是多少？** O(n)。`factorial(n)` 总共做 n 次乘法和 n + 1 次调用（`factorial(n)`、`factorial(n-1)`，……，`factorial(0)`），每次调用做常数工作。

> ⚠️ **易错点**：“没有循环，所以是 O(1)”是错的。工作隐藏在递归调用里：`factorial(10)` 显然比 `factorial(5)` 做得更多。应始终问：会发生多少次调用，每次调用的代价是多少。

### 7.2 两步法

求递归算法的时间复杂度：

1. **建立递推式**：一个方程，用于表示运行时间 T(n)
   - 用规模小于 n 的一个或多个子问题来表示，
   - 再加上递归调用之外所做的任何额外工作。
2. **求解递推式**（近似地），使用以下两种方法之一：
   - **方法 A——递归树法**（[§7.4](#74-方法-a阶乘的递归树)–[§7.5](#75-分治递推式的递归树)）
   - **方法 B——主定理**（[§8](#8-主定理)）

每个递推式还需要一个**基底情况**（例如 T(0) 或 T(1)），它是一个常数。

### 7.3 建立递推式：阶乘

对于上面的 `factorial` 函数：

```text
T(0) = a
T(n) = b + T(n - 1)      for n > 0
```

- **T(0)** 是 `n == 0` 时的时间。**a** 是检查 `n == 0` 并返回 1 的常数时间。
- 对于 **n > 0**，**b** 是除递归调用之外所有工作的常数时间（判断、`n - 1`、乘法、返回）。
- **T(n − 1)** 是递归调用的时间，它由同一个递推式描述。

从代码读出递推式：数出递归调用的次数（这里是一次），写出每次调用得到的规模（这里是 n − 1），再加上函数体其余部分的代价（这里是常数 b）。

> 📘 **课外补充**（Thornton，*Asymptotic Analysis of Recursion*）：另一种求解方法是**逐次代入**。不断代入，直到看出规律：
> T(n) = b + T(n−1) = 2b + T(n−2) = 3b + T(n−3) = … = jb + T(n−j).
> （这一规律可以用归纳法对所有 j 证明。）取 j = n 到达基底情况：T(n) = nb + T(0) = **nb + a**，它线性增长，因此 T(n) 是 Θ(n)。下一节的递归树通过画图得到同样的求和。

### 7.4 方法 A：阶乘的递归树

每次调用画一个节点，把该调用在递归调用*之外*所做的工作写在旁边，然后把所有值加起来。对于 `factorial(5)`，这棵“树”是一条链：

| 调用 | 层 | 递推式项 | 该节点的工作量 |
|---|---|---|---|
| `factorial(5) = 5 * factorial(4)` | 0 | T(n) | b |
| `factorial(4) = 4 * factorial(3)` | 1 | T(n−1) | b |
| `factorial(3) = 3 * factorial(2)` | 2 | T(n−2) | b |
| `factorial(2) = 2 * factorial(1)` | 3 | T(n−3) | b |
| `factorial(1) = 1 * factorial(0)` | 4 | T(n−4) | b |
| `factorial(0) = 1` | 基底 | T(0) = 常数 | a |

- 共有 **n 层**（另加基底情况）。
- 每层花费常数时间 b。
- T(n) = 层数 × 每层时间 = n·b（+ a） ⇒ **O(n)**。

下面逐步演示（演示获得焦点时，← / → 键可用）：

```viz recursion-tree

```

在真实代码中计数调用，结果一致：加了 `++calls` 的 `factorial`（位于函数开头）输出

```text
factorial(5) = 120, calls = 6
```

即 n + 1 = 6 次调用：五次代价为 b，一次基底情况代价为 a。

### 7.5 分治递推式的递归树

某个“未知算法”把输入对半分两次，并在每次调用中做线性工作：

```text
T(n) = 2T(n/2) + n
T(1) = c,  where c is a constant
```

**该方法的规则：** 把每个操作记到执行它的那个函数调用（树节点）上。在后续递归调用中完成的工作，要在*它们*的节点上单独计算。因此，输入长度为 m 的节点记 m（即在其自身规模上求值的 “+ n” 项），且绝不多记。

| 层 | 调用数 | 每次调用的输入规模 | 每次调用的工作量 | 该层合计 |
|---|---|---|---|---|
| 0 | 1 | n | n | n |
| 1 | 2 | n/2 | n/2 | n |
| 2 | 4 | n/4 | n/4 | n |
| 3 | 8 | n/8 | n/8 | n |
| … | … | … | … | n |
| log₂ n（叶子） | 2^(log₂ n) = n | 1 | c | c·n |

- 规模每层减半，因此经过 **log₂ n** 次减半后到达 1。树高为 log₂ n，计入叶子层共有 log₂ n + 1 层。
- 有 **n 个叶子**，每个都是基底情况 T(1) = c。
- 每个非叶层的总代价为 **n**：2^i 次调用，每次 n/2^i。
- 总计：n·log₂ n + c·n ⇒ **O(n log n)**。

下面逐步演示。输入框允许你输入任意形如 aT(n/b) + f(n) 的递推式（例如练习中的那些）：

```viz recursion-tree
{"title": "T(n) = 2T(n/2) + n，n = 8 时的图", "recurrence": "T(n) = 2T(n/2) + n", "n": 8, "interactive": true}
```

这是一个具有完全相同形状的真实函数，每个 “+ n” 步计 1 个单位，每个基底情况也计 1 个单位（c = 1）：

```cpp
long work = 0;

void unknown(int n)                      // T(n) = 2T(n/2) + n
{
    if (n == 1) { ++work; return; }      // base case: c
    for (int i = 0; i < n; ++i) ++work;  // the "+ n"
    unknown(n / 2);
    unknown(n / 2);
}
```

```text
unknown(8): work = 32
unknown(16): work = 80
unknown(1024): work = 11264
```

每个结果都与 n·log₂ n + n 一致：8·3 + 8 = 32，16·4 + 16 = 80，1024·10 + 1024 = 11264。

> 💡 **关键洞见**：画递归树需要三个数：有多少层、每层有多少节点，以及每个节点做多少工作。总量等于各层合计之和。

## 8. 主定理

### 8.1 公式

主定理是一个公式，用于求解**所有子问题规模都相同**的递推式。它把递归树方法打包成即插即用的结果，因此比画树更快。

设 $T(n) = a \cdot T(n/b) + O(n^d)$，则

$$
T(n) = \begin{cases}
O(n^d \log n) & \text{if } a = b^d \\
O(n^d) & \text{if } a < b^d \\
O(n^{\log_b a}) & \text{if } a > b^d
\end{cases}
$$

三个参数：

- **a**：子问题数（每次调用的递归调用数）
- **b**：输入规模缩小的因子（每个子问题的规模为 n/b）
- **d**：非递归工作为 n^d，即创建所有子问题并合并其解的工作

使用时，读出 a、b、d，计算 b^d，并将其与 a 比较。

> ⚠️ **易错点**：常数额外工作，即 O(1) 或 “+ c”，意味着 **d = 0**（n⁰ = 1），因此 b^d = 1。在 T(n) = 2T(n/2) + c 中，比较的是 2 与 1，而不是 2 与 2。

### 8.2 为什么是三种情形：工作量在哪里

递归树展示了这个公式的来源。第 0 层有 1 个节点，执行 f(n)。第 1 层有 a 个节点，各执行 f(n/b)。第 i 层有 **a^i** 个节点，输入规模为 **n/b^i**。最底层有 a^(log_b n) = n^(log_b a) 个叶子，各执行 f(1)。

若 f(n) = n^d，则第 i 层的代价为 a^i · (n/b^i)^d = n^d · (a/b^d)^i。因此每往下一层，该层的合计就乘以 **a / b^d**：

| 情形 | 逐层向下的合计 | 直观理解 | 结果 |
|---|---|---|---|
| a = b^d | 保持不变（每层 n^d，共 log_b n + 1 层） | 工作量在树中**均衡**分布 | O(n^d log n) |
| a < b^d | 几何级数递减 | 根节点的工作量**占主导** | O(n^d) |
| a > b^d | 几何级数递增 | 叶子的工作量**占主导** | O(n^(log_b a))，即叶子数 |

下面演示一个叶子占主导的例子；在输入框中输入其他递推式，可以看到另外两种情形：


### 8.3 典型例题

| 递推式 | a | b | d | a 与 b^d | T(n) |
|---|---|---|---|---|---|
| T(n) = 4T(n/2) + O(n) | 4 | 2 | 1 | 4 > 2 | O(n^(log₂ 4)) = **O(n²)** |
| T(n) = 3T(n/2) + O(n) | 3 | 2 | 1 | 3 > 2 | O(n^(log₂ 3)) ≈ **O(n^1.6)**（log₂ 3 ≈ 1.585） |

作为对比，[§7.5](#75-分治递推式的递归树) 中的递推式 T(n) = 2T(n/2) + n 满足 a = 2、b = 2、d = 1，所以 2 = 2¹，属于平衡情形：O(n log n)，与递归树结果相同。

### 8.4 不适用的情况

**主定理能否求解 T(n) = T(n/3) + T(2n/3) + n？** **不能。** 两个子问题的规模不同（n/3 和 2n/3），因此不存在单一的 b。改用递归树：每个完整层的代价至多为 n（同一层的规模之和至多为 n）。最长路径每步缩小为 2/3，因此约有 log_{3/2} n 层。总计 O(n log n)。

> ⚠️ **易错点**：主定理要求形如 a·T(n/b) + n^d、子问题规模相等的递推式。T(n−1) 型递推式（如阶乘）以及不均匀划分都不适用。这些情况请使用递归树（或代入法）。

## 9. 速查与五个要点

| 工具 | 给出什么 | 关键事实 |
|---|---|---|
| 倍增测试 | 指数 b（T(n) = a·n^b） | T(n)/T(n/2) → 2^b；a 取决于机器，b 不取决于机器 |
| 代价模型 + 波浪号 | 操作计数的首项 | 2-Sum ~ n² 次数组访问；3-Sum ~ n³/2 |
| Big-O / Ω / Θ | 上界 / 下界 / 紧界 | 仅当 O 与 Ω 一致时才有 Θ；情形（最好/最坏）是另一个独立的选择 |
| 增长阶 | 1 < log n < n < n log n < n² < n³ < 2ⁿ < n! | 增长越慢 = 算法越好 |
| 递推式（阶乘） | T(n) = b + T(n−1) | O(n) |
| 递推式（对半） | T(n) = T(n/2) + c；2T(n/2) + c；2T(n/2) + n | O(log n)；O(n)；O(n log n) |
| 主定理 | T(n) = aT(n/b) + O(n^d) | a = b^d：O(n^d log n)；a < b^d：O(n^d)；a > b^d：O(n^(log_b a)) |

**必记的 5 个要点**

1. 运行时间服从幂律 T(n) = a·n^b；倍增比 2^b 揭示 b，只有常数 a 取决于硬件。
2. 总时间 = Σ 代价 × 频率；选定一种代价模型（例如数组访问），并保留波浪号的首项：2-Sum ~ n²，3-Sum ~ n³。
3. Big-O 是上界，Big-Ω 是下界，Big-Θ 是紧界（只有两者一致时才存在）；最好/平均/最坏情形与界是两个独立的问题。
4. 递归算法需要一个递推式（基底情况 + 子问题 + 外部工作）；用递归树求解：层数 × 每层节点数 × 每个节点的工作量。
5. 主定理适用于 T(n) = aT(n/b) + O(n^d)：比较 a 与 b^d（相等：n^d log n；较小：n^d；较大：n^(log_b a)）；常数额外工作意味着 d = 0，而子问题规模不均或 T(n−1) 型递推式需要改用递归树。
